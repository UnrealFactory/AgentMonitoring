Every record here has two halves. One is technical. The other is plain, and it sits under a heading reading "For humans" that the program keeps for itself. Put a tab where the space after the two hash marks belongs, and the program took the write. The screen then drew that heading over prose saying this was not the plain half.

**Three separate pieces of code were each answering "is this line a heading?"** One refuses a bad write. One reads records for the browser version of this app. One draws them on the screen. The refusing one wanted a plain space after the hash marks; the drawing one takes any blank space, a tab included.

It is like proofreading a poster against one copy of the text and printing it from another.

**One record gave two answers at once.** Some text editors put an invisible mark at the front of a file. This app is written in two programming languages, and they disagree about that mark: one calls it blank space, the other an ordinary character. So a single file handed the browser version a "For humans" section, and handed the desktop window none.

**All three now work from one rule.** A run of hash marks ends at any blank space that either language calls blank. The words are then compared the way a reader sees them drawn: spacing squeezed, capitals ignored.

**Quoting fooled me for a while.** One of the three let three tildes close a block that three backticks had opened. A real heading could hide inside quoted output that way. A quoted block now closes only on the marks that opened it.

**Every spelling lives in one shared list: 18 that must be refused, 7 that must not.** One check drives all 25 through the real writing path. A second holds the browser reader and the drawing code to that same list. I also built one record per spelling and compared what the two readers hand back: identical on all 25, where three used to disagree.

**Nothing else broke: 163 automatic checks pass inside the program itself, and 157 against the tool server** — the go-between other agents reach this app through instead of the command line. Two other check runs were already failing before this work, and still fail. Neither failure comes from these changes.

**Three smaller repairs rode along.** A title with a line break in it used to save the record and its log entry, and fail only afterwards. One such record made listing the whole project's work fail for everybody. Titles refuse a line break now.

**The board where complaints about this app itself are filed lost two of its own faults.** The option saying when a change happened was checked and then thrown away; an item now carries the time it was last changed. And an agent coming through that go-between could not change such an item at all. That way in now takes the item's number.

Still missing: nothing on screen shows the plain half yet.

A rule written out in three places is three rules, and they drift.
