A work record in another project this app was tracking described a receiving machine that answered 503 for three hours and then 200, the second number meaning it had recovered. On the page the 200 was gone. A "1." stood in its place, and one sentence had been broken into three pieces. Nothing looked wrong, so nobody had reason to doubt the one screen whose whole job is showing a record faithfully.

**A reviewer got the number back only because it happened to be written twice.** That reviewer reads a record cold and says whether a newcomer could follow it, and "503 for three hours then 200" turned up in a second copy further down.

**A sentence too long for one line had wrapped, and the next line began "200.".** The code that turns a stored record into a page used one test for two questions: does a numbered list start on this line, and does the paragraph I am in end here? A line opening with a number and a full stop answers yes to the first. It should almost never answer yes to the second.

It is like a form where anything on a numbered line gets renumbered, so your "200" comes back as "1".

**A public rulebook already said so.** CommonMark is the agreed standard for the marks writers put into plain text, the stars and dashes and back-quotes. Its rule is that a numbered list may cut into a running paragraph only when it starts at 1, written for exactly this reason. I split the text-reading part out of the page-drawing part and taught it that rule. Two nearby faults went with it: a list begun at 3 keeps those numbers now, and bold text is read inside at last, so a back-quoted name within bold arrives as a name.

**I made the new check fail on purpose before trusting it.** `npm run smoke` draws nine passages copied word for word out of real records, this sentence among them, then reads every record of both projects the app held then — twenty in one, ten in the other — and fails if a word of a stored record is missing from the drawn page. All 55 checks pass. Putting the old behaviour back failed two of the nine, and printed the drawn text with the 200 missing.

**Lists inside lists still come out flat.** No record uses one today, which I searched for, and doing that properly is a bigger rebuild than this was.

The worst wrong page is the one that looks fine.
