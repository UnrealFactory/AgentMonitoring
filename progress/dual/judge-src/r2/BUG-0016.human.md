`cargo test`, the command that runs this program's own automatic checks, reported 20 of 21 passed and one failed. Which one, nobody could say: the output had been trimmed to its last twelve lines, so the tally survived and the list of failures was thrown away.

**A suite that fails one run in sixteen teaches everybody to run it again.** Then the run that means something gets run again too, and its answer is waved away.

**It would not come back that day.** Four more full runs, green. Six runs of that one file, green. Four of them at once, to make them fight over the disk, green. The failure had come straight after a browser check that loaded 413 pages, so the machine was busy, and that run finished in 0.40 seconds where an idle one takes 0.57.

**The suspect was written down as a suspect.** One test in that file starts several writers at once and checks that none takes another's number or drops an entry. It was the obvious candidate, and it went into the report as a guess rather than a finding.

**Two days later the agent who took it over caught it with the whole output kept.** Three of that test's writers had died on one file, `.agentmon.lock` — the marker a writer makes so the others wait their turn. It is like a key that has to be hung back on its hook before the next person can take it, and for a moment it is neither on the hook nor in a hand.

**Windows gives an answer nobody was waiting for.** Ask for that marker while the previous holder is halfway through handing it back, and the reply is "permission denied", not "someone already has it". The waiting code only knew to wait on the second, and treated the first as fatal, so the writer gave up on the spot. Load makes the hand-back and the next grab overlap more often, which is why a disk-hammering browser check shook it out.

**The fix is one more answer to wait on.** "Permission denied" on that marker now waits and tries again, on the same clock as before, so nothing waits forever. That change is filed as `BUG-0024`.

**It holds under the load that broke it.** Three full runs of the suite, green, and five runs of the crowded test alone. By then it was no longer rare: once note-writing added more traffic to that same marker, the suite was failing about one run in five on this machine.

The lesson that cost the most: never trim the output of a failing test.
