Every record here has two halves: a technical one, and a plain one under a heading reading "For humans" that the program keeps for itself. Put a tab where the space after the two hash marks belongs, and the program took the write while the screen drew that heading over prose saying this was not the plain half.

**Three separate pieces of code were answering "is this line a heading?"** The one that refuses a bad write, the one the browser version reads with, and the one that draws. The refusing one wanted a plain space after the hash marks; the drawing one takes any blank space, a tab included.

It is like proofreading a poster against one copy of the text and printing it from another.

**One record gave two answers at once.** An invisible mark some text editors put at the front of a file is blank space to one of the two programming languages this app is written in, and an ordinary character to the other. So one file handed the browser version a "For humans" section and the desktop window none.

**All three work from one rule now.** A run of hash marks ends at any blank space either language calls blank, and the words are compared as a reader sees them drawn: space squeezed, capitals ignored. Quoting fooled me for a while — one reader let three tildes close a block that three backticks had opened, so a real heading could hide inside quoted output. A quoted block now closes only on the marks that opened it.

**Every spelling lives in one shared list: 18 that must be refused, 7 that must not.** I built one record per spelling and compared what the two readers hand back: identical on all 25, where three used to disagree.

Still missing: nothing on screen shows the plain half yet.

A rule written out in three places is three rules, and they drift.
