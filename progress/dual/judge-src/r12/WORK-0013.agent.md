## What

Make the whole app live, finish Projects + vault portability, and put a Linear-grade shell
around them: a vault-change nonce that drives every page loader (Tauri watcher event on the
desktop, a change-cursor the client polls in browser mode), an in-app project create and
archive that writes through the same core code the CLI uses, a vault bar with "Open vault
folder…", a Cmd/Ctrl+K command palette, and the carry-over sweep the P4 critics left behind.

## Why

The P4 design critic's biggest gap: every page fetched once, at navigation. The desktop
watcher only reloaded the sidebar context, so an open dashboard showed stale numbers while
the sidebar two hundred pixels to its left already knew better — the screen contradicted
itself, under a green LIVE flag and a 30s clock tick. Browser mode was worse: the Vite
plugin answered a vault write with a full page reload, which throws away scroll position
and repaints the world.

Projects was the one screen nobody had rebuilt since P0: five read-only rows, no way to make
a project, no way to archive one, no way to point the app at a vault somewhere else — which
is the portability claim P5 exists to prove.

## How

One nonce in AppContext, bumped by the desktop watcher event or by a browser-mode poll of a
new cheap /vault-api/cursor endpoint; useAsync gains a refresh key that re-runs a loader
without clearing data or raising the loading flag, so a refresh never flashes a skeleton or
loses scroll. Writes go through agentmon-core: new Tauri commands for create/archive, and in
browser mode the dev middleware shells out to the agentmon binary itself, so there is exactly
one implementation of a write. A new gate, check:live, proves it headlessly against a
throwaway copy of the vault.

## Outcome

**Shipped, in four parts.**

**1. Liveness, app-wide.** `AppContext` now owns a vault nonce and is the app's only
subscriber to vault changes: on the desktop the Tauri watcher's `vault-changed` event bumps
it; in browser mode `subscribeVaultChanges` polls a new `/vault-api/cursor` — one hashed stat
walk over every record file, around forty stats — every two seconds, skipping the poll while
the tab is hidden and asking once when it comes back. `useAsync` gained a third argument, a
refresh key: when only that changes it re-runs the loader **without** clearing data, without
raising the loading flag, and without replacing a readable screen with an error if the vault
is momentarily unreadable. All eight loaders in the app take it (dashboard, work list, work
detail, bug board, bug detail, the related-records index, and the context's own vault info and
project list), so the sidebar can no longer know something the page beside it does not — the
self-contradiction the P4 critic caught. The Vite plugin stopped answering a vault write with
a full-reload down the HMR socket, which was throwing away the reader's scroll position and
every open day-group in the feed, and `vault/**` is out of Vite's watcher.

**2. Projects and vault portability.** Projects is rebuilt: a vault bar (name, absolute path,
schema, created, transport), cards carrying description, tags, work done/total, in-flight,
open bugs, events, last activity and start date, an in-app create form with a slug derived
from the name and duplicate detection, and archive/unarchive with an Archived section.
Writes go through `agentmon-core` on both transports — new `create_project` and
`set_project_status` Tauri commands in-process, and in browser mode the dev middleware runs
the `agentmon` binary itself (`handleVaultWrite`), so there is exactly one implementation of a
write and the JS reader stays a reader. Portability: desktop `choose_vault_folder` opens the
native picker, refuses a directory with no `vault.json` (naming the `agentmon init` that would
make one), persists the choice in the app config dir, re-arms the watcher, retitles the window
and emits `vault-changed`; browser mode takes `?vault=<dir>`, carried in sessionStorage so it
survives navigation, alongside `AGENTMON_VAULT`. An empty vault gets designed onboarding with
the real commands and a copy button; an unreadable one gets the same, led by `agentmon init`.

**3. Shell.** Sidebar sections, a search row, a vault footer that says which vault is open and
links to the screen that can change it, a Ctrl/Cmd+K command palette (records by id or title,
projects, screens — everything from memory, one fetch per project) and a window title that
follows the location on both shells.

**4. The P4 carry-over sweep.** In-flight rows carry a "waiting on <agent>" chip and highlight
the sentence that asks — both read from the quote already on screen, with the sentence in the
chip's tooltip, and the chip only ever names an agent this project's own records carry. Open
bug titles wrap to two lines. Open bugs are orange, not green. The last-24-hours sentence now
accounts for every event in the window and says "quiet for 12h 10m". Sidebar counts say what
they count ("13" work logs against "2 open" bugs). The Agents table counts `project_*` events,
so its rows reconcile with the Activity card and "Last seen" matches the feed. The feed has
Expand all. The idle dot has a label. `noteOutline` keeps decision-bearing lines, so nova's
"Deliberately not doing the production swap this week" survives the trim. The agent bar
tooltip pluralises. The Open Bugs card's footnote sits on the floor of the card. The range
sentence lives under its control at every width, so switching ranges no longer jumps the page.

**Deviation from SPEC, recorded.** `agentmon project update` gained `--status
active|archived` (the SPEC CLI list has `--name`, `--description`, `--tags`, `--at`). The
schema already carries `status: active|archived`; without a CLI verb it could only be set by
hand-editing `project.json`, which skips the event log the app's feed is built from. The app's
Archive button and the flag are the same code path.

because Vite discovers `import()`-ed dependencies on first request and reloads mid-navigation

sections — the CLI's own write making the vault fail `agentmon doctor`. Fixed in
`validate.rs`, which now refuses one on outcomes, resolutions and notes and names the style to
use instead; the manual says it too. The record that hit it (BUG-0014) was repaired by hand —
heading syntax only, `## Root cause` to `**Root cause.**`, no word of content changed — because
a resolved bug cannot be re-resolved; `agentmon doctor` is clean over all 47 records.
