The heading a record's plain half sits under, `## For humans`, belongs to the program. An agent could still write one that draws exactly those ten letters and have it accepted. Put a character that paints nothing after the words — a zero-width space, say — and the screen drew the same ten letters. The check, meanwhile, was comparing two different texts. Seven spellings did that, and an eighth swapped the English o for the Cyrillic one, a letter you can see and cannot tell apart.

It is like a name with a silent extra letter: it reads aloud the same, and no list you search will find it.

**A heading is compared now the way a reader sees it.** `normalize_title` is the step that builds that reader's version first. Characters leaving no ink are dropped, and blank ones that still take a full space count as the space they replaced. A letter drawn exactly like one of the nine in "for humans" becomes that letter. Only those nine are in the table, because no other swap can turn a different title into this one.

**The same rule had a second end.** The two programming languages this app is written in each trim blank space off the ends of the plain half. They disagree about one mark, `U+FEFF`, the one some text editors put at a file's front. A plain half read out of such a file looked different in the desktop window than in the browser. Both ends trim the same set now, and one with nothing visible in it is refused rather than stored.

**The shared list of spellings grew from 25 to 44 — 34 that must be refused, 10 that must not.** It lives in `crates/agentmon-core/tests/reserved-heading-shapes.json`, written so a reviewer can see what each character is. Each shape is driven through the real writing path. `markdown-smoke` holds `scripts/project-fs.mjs`, the reader behind the browser version, and the drawing code to that same list. All eight spellings the reviewer found are refused where they used to be accepted.

**Every one of those checks passes today.** The Rust side runs 166 of them; `markdown-smoke` runs 700, up from 643 before this round. Of the 101 records already stored, 97 hand their text back through the browser reader byte for byte. The four that do not are the four carrying a plain half, which is what the rule asks for.

**A file name on screen was being cut off at one line.** Every record lists the files it touched. The list of spellings above has the longest such name any record here has carried, 28 characters, and the chip drawing it kept every name on one line and ended it in three dots. So the check that opens each screen at eight window widths and reports text its own box cuts off had gone red — on this very piece's record. Names wrap onto a second line now, the way this app already draws a file path inside an error message, and that check is green again in both languages.

**A title broken across two lines could put the reserved heading on the board by accident.** Feedback about this app is a fourth kind of record, kept on its own board, and it can be filed from the command line with a title. That title was not going through the guard the other three kinds use, so a second line reading `## For humans` would have been stored as part of it. It goes through that guard now: a title with a line break stops the command with an error, before anything is written.

**A refusal was being cut off in the middle of a rule.** Other agents reach this app through a go-between program instead of the command line. Hand that program a plain half that breaks the style contract and it refuses, quoting the contract back. That quote was capped at 2,500 characters, a guess at how long the contract is, and the first rewrite of the contract pushed its last line past the cap — the line naming the command that prints the whole thing. The cap is gone, and the go-between's own 160 checks now assert that last line arrives and nothing is trimmed.

Still missing: nothing on screen shows the plain half yet.
