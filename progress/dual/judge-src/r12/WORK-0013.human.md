The app shows a page of live numbers with a column of counts down its left edge. Leave that page open and its numbers stopped moving. The column two hundred pixels away already showed newer ones. One window, two answers, under a green flag reading LIVE.

**One count of changes now feeds every screen.** Something writes a record into the project folder. On the desktop that arrives as an event; in a browser the page asks a small address, `/vault-api/cursor`, every two seconds whether anything on disk has moved. Either way it nudges a single number, and all eight of the app's screen loaders watch that number. They reload underneath you, with no blank flash and no jump back to the top.

It is like wiring every clock in a house to one movement instead of winding each by hand.

**The Projects screen could only be read.** Five rows, nothing to press. You can now make a project, archive one, and point the app at a folder elsewhere on the disk. Each of those writes runs through `agentmon`, the small command-line program that owns this file format, so one piece of code writes and the rest only read. Archiving needed a switch that program did not have; adding it departs from the written plan, and I recorded that, because editing the folder's own file by hand would skip the event log the whole app is built on.

**One key now jumps you anywhere in the app.** Ctrl+K, or Cmd+K on a Mac, drops a search box over whatever you are reading. Type a record's number, a few words of its title, a project's name or the name of a screen, and it takes you there. It answers out of what the app already holds in memory, having read each project once, so nothing waits on the disk while you type. The left column gained headings of its own, a search row, and a line at the foot naming the open folder with a link to the screen that changes it. The window's title now follows wherever you stand.

**Earlier reviewers had left a list of small things nobody had done.** I worked through it. An open bug was drawn in green — a colour nobody reads as a warning — and is orange now. A row for work in progress carries a chip saying which worker it is waiting on, taken from the quote already on the screen, with the sentence doing the asking lit up in the text. The last-24-hours line accounts for every event in that window and says "quiet for 12h 10m" when there is nothing to report. The counts down the left edge now say what they count: 13 work logs against 2 open bugs.

**The program's own writing failed the program's own checker.** A bug resolution typed with `##`, the markdown way to mark a heading, was accepted and then stored with its main section empty. Found and fixed on the way: the checker now refuses those headings and names the style to use instead.

**A cold server handed the page two copies of the same toolkit.** The server I run the app from while working discovers some of the app's parts only when the first page asks for them, then reloads in the middle of that page. For a moment the screen was running on two copies of React, the toolkit that draws every screen here, and any check driving a browser could land on a blank page and a complaint about reading a property of nothing. Every tool now starts that server through one script that warms it first, so those parts are found before anybody asks.

**A new check watches the whole thing happen.** `npm run check:live` copies the project folder to a scratch directory and never touches the real one. It starts the app against the copy, opens two screens, scrolls both, then writes with the real command-line program. Fifteen checks pass: the change arrives with no page load, no blank skeleton and no lost scroll position. The summary page caught up in 1.3 seconds, the record page in 0.27.

**The desktop-only parts are untested.** The folder picker, remembering which folder you chose, re-aiming the file watcher: all are written and wired, but this machine could not run the desktop app, so nobody has watched them work. The quick-search box searches only the project you are standing in.

A screen that keeps its own count will eventually disagree with the one beside it.
