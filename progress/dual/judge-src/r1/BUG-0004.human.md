A work record in another project this app tracks described a receiving machine that answered 503 for three hours and then 200, the second meaning it had recovered. On the page the 200 was gone. In its place stood a "1.", and the sentence had been split into three pieces. A reviewer whose job is checking whether a record can be understood by someone new recovered that number only because the record happened to state it again further down.

**The page printed a number nobody wrote and dropped one somebody did.** Nothing looked broken, so the reader had no reason to doubt the one screen whose whole job is to show a record faithfully.

**A sentence too long for one line had wrapped, and the next line began "200.".** `src/lib/markdown.tsx`, the code that turns a stored record into the page you read, used one test to answer two questions: does a numbered list start on this line, and does the paragraph I am in end here? A line beginning with a number and a full stop answers yes to the first. It should almost never answer yes to the second.

It is like a form that treats any line starting with a number as a new entry. Write your house number at the start of a line and your address becomes entry one.

**A public rulebook already says so.** CommonMark is the agreed standard for these formatting marks, the stars and dashes and back-quotes writers put into plain text, and its rule is that a numbered list may cut into a running paragraph only when it starts at 1, written for exactly this reason. So I split the text-reading part out of the page-drawing part and taught it that rule. Two nearby faults went with it: a list the author began at 3 keeps the author's numbers now, and bold text is read inside at last, so a back-quoted name within bold arrives as a name.

**I made the new check fail on purpose before trusting it.** `npm run smoke` draws nine passages copied word for word out of real records, this sentence among them, then sweeps every record in the project and fails if any word of the stored text is missing from the drawn page. All 55 checks pass. Then I put the old behaviour back: two of the nine failed, and the failure printed the drawn text with the 200 missing. Restoring the fix passed them again.

**Lists inside lists still come out flat.** No record uses one today, which I searched for, and doing that properly is a bigger rebuild than this was.

A page that looks right and is wrong is worse than a page that looks broken.
