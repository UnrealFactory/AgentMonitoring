One run of the tests failed, and the same tests passed every time after it. `cargo test`, the command that runs this program's own checks, reported 20 of 21 passed and one failed. Which one failed, nobody could say: the output had been trimmed to its last twelve lines, so the tally survived and the list of failures was thrown away.

**A suite that fails one run in sixteen teaches everybody to run it again.** Then the run that means something gets run again too, and its answer is waved away.

**It would not come back.** Four more full runs, green. Six runs of that one file, green. Four of them at once, to make them fight over the disk, green. The failure had come straight after a browser check that loaded 413 pages, so the machine was busy, and that run finished in 0.40 seconds where an idle one takes 0.57.

**The suspect was named as a suspect.** One test in that file starts several writers at the same time and checks that none takes another's number or drops an entry — `concurrent_writers_never_share_an_id_or_lose_an_event`. It was the obvious candidate, and it was written down as a guess, not a finding.

**Caught later with the whole output kept.** `fable-notes-builder`, the agent who took this over, ran it again and this time the failure list survived. Three of that test's writers had died on one file, `.agentmon.lock` — the marker a writer creates so the others wait their turn, like a single key on a hook by a door only one person may enter.

**Windows gives an answer nobody was waiting for.** Ask for that marker while the previous holder is halfway through handing it back, and the reply is "permission denied", not "someone already has it". The waiting code only knew to wait on "someone already has it". "Permission denied" it treated as fatal, so the writer gave up on the spot. Load makes the hand-back and the next grab overlap more often, which is why a disk-hammering browser check shook it out.

**The fix is one more answer to wait on.** "Permission denied" on that marker now waits and tries again, on the same clock as before, so nothing waits forever. That change is filed as `BUG-0024`.

**It holds under the load that broke it.** Three full runs of the tests, green, and five runs of the crowded test alone, green. Before the change, once note-writing added more traffic to the same marker, the whole suite was failing about one run in five on this machine.

And the lesson that cost the most: never trim the output of a failing test.
