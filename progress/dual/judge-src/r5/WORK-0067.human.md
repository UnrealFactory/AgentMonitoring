Every record here has two halves. One is technical. The other is plain, and it sits under `## For humans`, a heading the program keeps for itself. Put a tab where the space after those two hash marks belongs, and the program accepted the write. The screen then drew that heading over prose saying this was not the plain half.

**Three separate pieces of code were each answering "is this line a heading?"** `body::heading` is the guard that refuses a bad write. `scripts/project-fs.mjs` is the file the browser version of this app reads records with. `src/lib/markdown-parse.ts` is the code that draws a record on the screen.

The guard wanted a plain space after the hash marks. The drawing code takes any blank space, a tab included.

It is like proofreading a poster against one copy of the text and printing it from another.

**One record gave two answers at once.** Some editors put an invisible mark, `U+FEFF`, at the front of a file. JavaScript, the language behind the browser version, counts that mark as blank space and drops it. Rust, the language behind the desktop window, keeps it as an ordinary character. So one file handed the browser version a "For humans" section, and handed the desktop window none.

**All three now work from one rule.** A run of hash marks ends at any blank space that either language calls blank. `human::is_heading_title` matches a heading's words against the ones the program keeps for itself. It now reads both the way a reader sees them drawn: spacing squeezed, capitals ignored.

**Quoting fooled me for a while.** `body::Fences`, the part of the guard that tracks where quoted blocks open and close, let three tildes close a block three backticks had opened. A real heading could hide inside quoted output that way. A quoted block now closes only on the marks that opened it.

**Every spelling lives in one shared list.** `reserved-heading-shapes.json` names 18 that must be refused and 7 that must not. A test in `human_area.rs` drives all 25 through the real writing path. `scripts/markdown-smoke.mjs` holds the browser reader and the drawing code to that same list.

I also built one record per spelling and compared what the two readers hand back. They matched on all 25. Three of them used to disagree.

**Nothing else broke.** `cargo test --workspace` passes 163 checks inside the program itself. `npm --prefix mcp test` passes 157 against the MCP server — the go-between other agents reach this app through instead of the command line. `npm run smoke` and `check:i18n --locale ko` were already failing before this work, and still fail. Neither failure comes from these changes.

**Three smaller repairs rode along.** A `--title` with a line break in it used to save the record and its log entry. It failed only afterwards. One record left that way made `work list`, which prints a project's work, fail for everybody. A line break in a title is refused now.

**The board where complaints about this app itself are filed lost two of its own faults.** `--at`, the option saying when a change happened, was checked and then thrown away. An item now carries `updated:`, the time it was last changed. And an agent coming through that go-between could not change such an item at all. That way in now takes the item's number.

Still missing: nothing on screen shows the plain half yet.

A rule written out in three places is three rules, and they drift.
