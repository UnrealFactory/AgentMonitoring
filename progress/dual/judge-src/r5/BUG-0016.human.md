`cargo test`, the command that runs this program's own automatic checks, reported 20 of 21 passed and one failed. Which one, nobody could say. The run had been piped through `tail -12`, which keeps only a command's last twelve lines. So the tally survived and the list of failures was thrown away. A suite that fails one run in sixteen teaches everybody to run it again, the run that means something included.

**It would not come back that day.** Four more full runs of everything: green. Then six runs of one test file, one after another. Then four more runs of that file at once, to make them fight over the disk. Green every time.

**The file was `crates/agentmon-core/tests/write_roundtrip.rs`**, which writes records and reads them back. Its failure had come straight after `npm run check:clipping`. That check opens the app's own pages in a browser and looks for text cut off at an edge. It had just loaded 413 of them. The suite finished in 0.40 seconds where an idle run takes 0.57.

**One test in that file was the obvious suspect.** It is `concurrent_writers_never_share_an_id_or_lose_an_event`, and it starts several writers at once. It checks that no two of them hand out the same id, and that nothing they write is lost. It went in as a suspect, not a finding.

**Two days later `fable-notes-builder` caught it with the whole output kept.** That agent found three of the test's writers dead on one file, `.agentmon.lock` — the marker a writer makes so the others wait their turn.

It is like a key that must be hung back on its hook before the next person can take it. For a moment it is neither on the hook nor in a hand.

**Windows gives an answer nobody was waiting for.** The way to take the marker is `create_new`, which makes a file only if it is not there yet. Ask for it while the previous holder is halfway through handing it back. The answer is `PermissionDenied`, the refusal a program gets when it may not touch a file. What it should mean here is `AlreadyExists`: someone has it, wait.

**The waiting code only knew the second answer.** `ProjectLock::acquire`, the step that takes that marker before any write, waited on `AlreadyExists` and gave up on the spot for anything else. A busy disk makes the hand-back and the next grab overlap more often.

**`PermissionDenied` now waits and tries again**, on the same clock as before. Three full runs of the suite are green, and five of the crowded test alone. By then it was no longer rare: once note-writing added traffic to that marker, the suite was failing about one run in five.

Never trim the output of a failing test.
