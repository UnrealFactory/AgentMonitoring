`WORK-0005`, a work record in the relay project this app also tracked, described a receiving machine. It answered 503 for three hours, then 200, meaning it had recovered. On the page the 200 was gone, a "1." stood in its place, and one sentence had been broken into three.

**The P2 comprehension critic got the number back only by luck.** That reviewer reads a record cold and says whether a newcomer could follow it. The critic ran into this while reading `WORK-0010`, another work record of that project. The phrase was written a second time, further down. That second copy is where it came back from.

**A sentence too long for one line had wrapped, and the next line began "200.".** Inside `src/lib/markdown.tsx`, the file that turns a stored record into a page, the step that cuts text into paragraphs and lists asked one test two questions: does a numbered list start here, and does the paragraph I am in end here? That test accepted any line opening with a dash, a star, a plus, or a number and a dot. "200." is one.

It is like a form where anything on a numbered line gets renumbered, so your "200" comes back as "1".

**CommonMark, the agreed standard for the marks writers put into plain text, has a rule against this**: a numbered list may cut into a running paragraph only when it starts at 1.

**I moved the reading apart from the drawing.** It now sits in its own file that runs without the page around it, and a new test there lets a dash cut in and a number only at 1. A list the writer began at 3 keeps those numbers, taken from the writer's own first marker. Bold is now read all the way through too, so a name marked as code inside bold arrives as a name, not as quote marks.

**`npm run smoke` is the check that would have caught this.** It draws nine passages copied word for word out of real records, this sentence among them, then reads every record of both projects the app held then, twenty in one and ten in the other, failing if a word of a stored record is missing from the drawn page. All 55 checks pass.

**I made it fail on purpose before trusting it.** Putting the old behaviour back failed two of the nine passages and printed the drawn text with the 200 missing.

**Lists inside lists still come out flat.** No record uses one today; I checked every record the app then held; doing it properly is a bigger rebuild than this fix was.

The worst wrong page is the one that looks fine.
