## What

Archive is out of the product, and deleting a project is in.

Removed: the archive/unarchive items from the project menu (src/lib/menus.ts), the ARCHIVED
section and its show/hide disclosure and the undo bar on /projects, the archived pill and
tooltip on the dashboard, the "archived" flag and hollow bullet in the sidebar, the
`setProjectStatus` call in src/lib/api.ts, the `set_project_status` Tauri command, the
`POST /vault-api/projects/:slug/status` route, and every archive string from both
dictionaries. The Projects screen is now one list headed 이 볼트의 프로젝트, the vault bar's
fact is 프로젝트 rather than 활성 프로젝트 with a "· N 보관" aside, and the sidebar's count is
the same number as that one.

Added: 삭제 on every project surface — red, under a divider, hinted "영구 삭제 — 되돌릴 수
없습니다" — plus a visible 삭제 on each row of the Projects screen, both opening one
app-styled dialog (src/components/DeleteProject.tsx, mounted above the router in App.tsx
because the menu that opens it is on six surfaces). The dialog names the project, counts
what goes with it (작업 로그 N개 · 버그 N개 · 이벤트 N건), says in plain words that the folder
leaves the disk, and arms its button only when the slug has been typed exactly.

The backend: `Vault::delete_project` in agentmon-core, a new `delete_project(slug, agent?)`
Tauri command over it, and `DELETE /vault-api/projects/:slug` in the dev server for browser
mode. No CLI subcommand and no MCP tool — the five tools there are unchanged.

## Why

The user asked for it, in two sentences: they will not use archive, so take it out; and a
project they have stopped using should be removable from the app they read it in. Agents
stay unable to delete — no CLI verb, no MCP tool — so the vault an agent writes into is
still append-only from the agent's side, and the one destructive act in the product belongs
to the human, in the window, behind a confirmation.

Archive was also a second state with no reader: it hid a project from the switcher and the
default list while leaving it readable by its address, which meant every surface in the app
had to carry an exception for "the archived project you happen to be standing in". Removing
it deletes that exception from the sidebar, the switcher, the dashboard's live flag and the
Projects screen at once.

## How

`project.json` keeps its `status` field: v1 files in the wild carry it and
`agentmon project update --status` still writes it — the app simply never reads it now, and
SPEC.md, the manual and `Project.status`'s doc comment all say so in one line each.

Path safety is the part that got the tests. `Vault::delete_project` validates the slug with
the same `validate_slug` every other path-forming argument uses, canonicalises the directory
and then requires it to still be a direct child of *this* vault's `projects/` — the rule is
`inside_projects`, split out so the failing half can be unit-tested against fabricated paths
rather than only against directories somebody dared delete. The browser twin in
scripts/vault-fs.mjs keeps both rules with `realpathSync` and a one-component `relative()`
check; it is the one write in that file that does not shell out to `agentmon`, because there
is no verb to shell out to.

The dialog is the palette's own surface (scrim, raised panel, border, radius, shadow) with a
red hairline along its top edge, so it reads as something this app drew. Esc and the scrim
cancel; Tab is trapped; ↵ in the empty field is guarded in the submit handler rather than
only by `disabled`, because implicit submission does not care what the attribute says.
