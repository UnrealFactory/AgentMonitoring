The other bug
Two robots, two rulebooks.
The same check runs in two languages — Rust and JavaScript.
Each has its own idea of which blank characters to strip off the edges of text.
One strips a certain invisible mark; the other keeps it.
Same file, two different answers.

The fix: both now strip everything in either circle.
Same file → same answer, every time. And “blank” now means “no visible ink at all.”
A note made of nothing but invisible marks used to count as writing.
Now it's refused: “no human text was supplied.”
While we were here
Three small fixes rode along.
📛
File names wrap now
A long file name was chopped to “reserved-heading-sh…” on screen.
Now it wraps onto the next line instead.
↩️
No sneaky line breaks
A title hiding a line break could smuggle a fake heading onto its second line.
It's now rejected before anything is saved.
✂️
No more cut-off message
A help message had a size cap that trimmed off its last, most useful line.
The cap is gone; the whole message prints.
