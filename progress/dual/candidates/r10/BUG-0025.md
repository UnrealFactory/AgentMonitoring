You edit a file in the app while it is running, and nothing on screen changes. Not as you type, not after a full page reload. You get the code as it stood when the development server started. That server is vite, the program that serves the app while you work on it, and it kept handing out whatever it prepared on the first request.

**The leftover server.** Two sessions blamed an old server still sitting on 5173, the number it answers on, and restarted it. Restarting never helped. A server seconds old is already stale for anything edited after it started.

**A name that matched everything.** `vite.config.ts`, vite's own settings file, told chokidar — the part that watches files for changes — to ignore `**/AgentMonitoring/**`: any folder named AgentMonitoring, at any depth, and everything inside it. The point was sound. The project's data is written into a folder of that name, and those writes should not shake the running app. But this repository sits at `C:/Code/AgentMonitoring`. Its own top folder carries the name.

**The settings file itself.** So the rule matched every file in the project, and the watcher watched nothing. It matched `vite.config.ts` too, so vite could not see edits to the file holding the rule, and never restarted itself over it.

It is like a sign at your gate reading: deliver nothing to any house called Ash Lodge. You live in Ash Lodge.

**The one folder.** The ignore rule now points at the AgentMonitoring folder at the top of this repository, and only that one.

**The probe.** It surfaced when a file the app had just gained, `src/lib/useScrollRestoration.ts`, sat completely inert against a server started minutes earlier; asking that server for one source file showed the day's edits missing from what it handed back. The fix was then checked against a running desktop server. One marker line added to that same file appeared in what the server served within two seconds, and disappeared when the line was removed. No restart either way. Code cached once and never refreshed cannot do that.

**The data folder.** Edits reach the running app again. The original point survives: writes into the repo's own AgentMonitoring data folder still do not reload the dev server, and the app keeps noticing those writes by asking for them on a repeat. What was watched was one file, on one running server.

A rule that skips every folder with a given name will skip your own, if that is what you named it.
