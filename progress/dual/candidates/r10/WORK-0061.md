ElmwoodOnline's UnrealNetCore project keeps one note as a map of what that project remembers. Its index rows name the other notes: `[[unrealnetcore-mission-decisions]]`, `[[unrealnetcore-queue]]` — a note's name inside double square brackets. On screen those rows came out as plain characters. Nothing to click. Agents, the ones writing these notes, reach for that spelling on their own.

**The two brackets.** Record ids written in prose, like `WORK-0004`, already came out as chips — the small clickable label that stands in for a record. Note names did not. In `src/lib/markdown-parse.ts`, the file that turns written text into what you see, I added a rule for `[[...]]`. What sits between the brackets must look like a note name: 2 to 64 letters, digits and hyphens, no hyphen at either end — the shape the program already demands of a note name.

**The link it already had.** A match now produces exactly the link a record id produces. So the chips, the hover labels, the right-click menus and the "no note by that name" state needed no further work. `[[WORK-0004]]` resolves too.

It is like underlining a word by hand: the mark is the instruction, so nothing gets underlined by accident.

**The Korean particles.** One step flattens formatted text back to plain characters, and early on it dropped the brackets. A sweep of the live Elmwood folder showed the cost: people weld Korean particles straight onto the closing brackets — `unrealnetcore-queue]]의`. Swallow those and you have lost what someone wrote. Flattening now puts `[[name]]` back.

**The 443 checks.** `node scripts/markdown-smoke.mjs` — the script that pushes prepared snippets through the renderer and compares each result against what we wrote down — passes all 443. Its new seventeenth fixture covers wiki-links in prose and in table cells, bare kebab words staying plain text, and flattening restoring the brackets. Pointed at the Elmwood folder it passes 106, including the three that failed mid-work over the dropped brackets.

**What still will not link.** Every `[[...]]` row of that Elmwood map is a chip now. A kebab word left bare stays plain text, on purpose: catching words nobody meant as links is the risk that kept it that way. The double brackets are how you say you meant it, and that rule is now written down where agents read it.

If you want a word to be a link, type the mark; guessing is how the wrong words become links.
