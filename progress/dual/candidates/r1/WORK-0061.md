Agents were already writing `[[note-name]]` links into their notes, and the app printed them as dead text nobody could click.

Here is the shape of it. Records in this project refer to each other by id — WORK-0061, BUG-0031 — and the reader turns those into a small clickable chip. Notes have names instead of ids, like `unrealnetcore-queue`, and there was no way to link one. So agents invented it themselves, borrowing the double-bracket spelling from Obsidian: over in the ElmwoodOnline project, the UnrealNetCore memory map is a note whose index rows are nothing but `[[unrealnetcore-mission-decisions]]`, `[[unrealnetcore-queue]]` and the like. Every one of those rows showed up as literal brackets.

The change is in the rules that turn record text into what you see on screen, `src/lib/markdown-parse.ts`. The parser now recognises `[[...]]` when what sits inside looks like a note name — 2 to 64 letters, digits and hyphens, no hyphen at either end — and hands back the same "reference" the ids already produce. Everything after that point already knew how to deal with a note name, so chips, tooltips, right-click menus and the greyed-out state for a name matching no note all worked untouched. `[[WORK-0004]]` resolves as well.

Two things bit. First, `[[label](url)` is an ordinary link whose label happens to start with a bracket, so a quick "does it begin with `[[`" test would have eaten real links; the match has to be the whole pattern. Second, and worse: the app also flattens formatted text back to plain text, and the first version silently dropped the brackets while doing it. Some of these notes are Korean, and a Korean particle can be welded onto the closing brackets — `unrealnetcore-queue]]의`. Dropping brackets there loses actual text. Flatten now puts `[[name]]` back exactly.

Checking it: the markdown smoke test ran 443 checks, including a new group of 17 for this — links in prose and inside table cells, bare words staying plain, brackets with spaces or code inside staying literal, `[[label](url)` still a link, flatten restoring the brackets. Then the same test ran against the real ElmwoodOnline folder, 106 checks, three of which had genuinely failed mid-work while flatten was eating brackets. The type checker came back clean, and a screenshot of that live memory-map note (`progress/shots-wikilink/note-detail-full.png`) shows every row as a chip.

What is different now: an agent can point at another note in plain prose and the reader will follow it. SPEC.md and the agent manual now spell out the rule. The deliberate limit: a bare note name with no brackets still stays plain text, because guessing would turn ordinary hyphenated words into broken links — the brackets are the opt-in, and an agent who forgets them gets nothing.
