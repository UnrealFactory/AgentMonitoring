In another project of ours, ElmwoodOnline, there is a page called `unrealnetcore-index`. It is a map of what the assistants working there have written down. Every row of it points at another such page: `[[unrealnetcore-queue]]`, `[[unrealnetcore-mission-decisions]]`. On screen those rows arrived as flat text, brackets and all. Nothing to click. A work number typed into the same paragraph — `WORK-0004`, one of these numbered records of a piece of work — had been turning into a clickable label for a long time.

**The double brackets.** I added that spelling to the list of shapes the app hunts for while turning written text into a screen, in `src/lib/markdown-parse.ts`. The new shape accepts only a name of the form the rest of the app accepts: 2 to 64 letters, digits and hyphens, and no hyphen at either end. Out comes the same small clickable label the work numbers already produce, carrying the page's title. A hyphenated word sitting bare in a sentence still links to nothing. That was decided long before this: ordinary writing is full of words that merely look like names. The brackets are how a writer says they meant it.

It is like a phone book that dials a name you put in brackets, and never a word that only looks like one.

**The label that begins with a bracket.** The cheap way is to ask whether a line of text starts with two brackets. That is wrong. `[[label](url)` is an ordinary link whose visible words happen to open with a bracket. So the app tests the whole shape instead of the first two characters.

**The Korean particle.** One part of the app turns a formatted line back into plain text. My first version put the name back without its brackets. In the Elmwood pages, Korean is typed hard against the closing brackets — `unrealnetcore-queue]]의`. Swallow the brackets and that word is glued to the name; the writing has quietly lost something. Three checks over those pages failed mid-work, exactly there. Now the brackets come home with the name.

**443 checks.** `node scripts/markdown-smoke.mjs` feeds sample writing through the app and compares the result against what it should be. All 443 pass. A new seventeenth group of cases covers the bracketed name in a sentence and inside a table cell; a bare hyphenated word staying text; a name with a space in it, an array written out, text marked as code — all staying literal; `[[label](url)` staying a link; and the round trip back to plain text keeping its brackets. The same tool run over the real Elmwood pages: 106 checks, the three failures included. `npx tsc --noEmit` is clean. And `progress/shots-wikilink/note-detail-full.png` shows that index page in a browser — every row of the map is a label now, in prose and table cells alike, with the older work-number labels untouched.

**What is written down.** `SPEC.md` and `docs/AGENT_MANUAL.md` now state the rule plainly: numbered ids link on sight, pages link when written as `[[note-name]]`, bare hyphenated words never link. That last one is a limit, not an oversight, and it stays. Nothing changed in how anything is stored, and the command-line tool is the same; this is only what the screen does with text people were already typing.

A spelling everyone already writes by hand is a decision already made — the tool just has to answer.
