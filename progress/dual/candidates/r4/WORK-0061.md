Agents write notes and link between them by name, as `[[note-name]]`: a note's short name in
doubled square brackets. The app printed that as plain characters. In our UnrealNetCore project,
one note indexes the others; every row of it was unclickable.

**What we changed.** The app already turned a record's id into a tag. We added the bracket spelling
beside it, matching a note name only: two to sixty-four letters, digits or hyphens, no hyphen at
either end. Past the match, nothing else needed work.

Think of it as a sorter that knows every address, and needs telling only which marks are one.

**The lookalike.** An ordinary link can open with two brackets too: `[[label](url)` is a link whose
visible words begin with one. Testing for a leading pair of brackets would take those, so we match
the full shape.

**Writing it back out.** The app must also turn a link back into plain text. Our first version left
the brackets off. Real notes broke: Korean attaches a grammar particle onto the closing brackets,
as in `unrealnetcore-queue]]의`. Dropping them loses what the writer typed.

**How we know.** A test is a small program that checks one thing. The text tests now run 443
checks, all passing. New ones cover brackets in sentences and tables, the lookalike staying a link,
and the brackets returning when text is written out.

The same checks ran on the other project's real notes: 106, three of which failed while the
brackets were being lost. A check that the program's pieces fit was clean. A screenshot shows every
row of that note as a tag.

**What is different.** Notes link from ordinary text now, and the rule is written down: ids link
alone, notes link inside brackets, a bare hyphenated word never links. That last one is deliberate:
everyday words would link by accident. The record names nothing else as unchecked.

If people already write something by hand, honour their spelling instead of inventing one.
