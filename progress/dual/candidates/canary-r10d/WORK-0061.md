In another project's notebook one note works as a map to all the others. Its rows read `[[unrealnetcore-queue]]` — the name of another note, wrapped in two square brackets. On screen they came out exactly as typed, brackets and all — plain text, nothing to click. Agents write notes that way by habit.

**Two brackets now make a link.** The change went into `src/lib/markdown-parse.ts`, the file that reads a record's text and decides which pieces become links. It now catches a name in double brackets, so long as that name looks like a note name — 2 to 64 letters, digits and hyphens, no hyphen at either end — and gives it the same small clickable label work and bug ids already get.

It is like a highlighter: writing a note's name changes nothing, drawing brackets round it says you meant a link.

**A bracket at the front does not mean a wiki link.** An ordinary link can begin `[[label](url)`, its visible words opening with a bracket. Checking only the two front brackets would have swallowed those, so the file weighs the whole shape.

**Throwing the brackets away throws away someone's words.** The same file also turns that text back into plain words, and my first version dropped the brackets doing it. `node scripts/markdown-smoke.mjs`, the script that feeds prepared scraps of record text through that file and compares each answer with what we wrote down as correct, caught it: over the live project's folder, three of its checks failed. Rows there have a Korean ending welded straight onto the closing brackets, `unrealnetcore-queue]]의`, so dropping them loses letters somebody typed. The file now hands those words back with the brackets still on.

**Every check passes now, and 17 are new.** That script passes all 443, the new ones covering brackets in prose and in table cells, hyphenated words and bracketed code left as text, and the brackets coming back when text goes plain. Over the live folder it passes 106, the three earlier failures among them. I opened that map note in the app myself and looked: every bracketed row is a chip now, prose and table cells both, and the old work and bug chips look as they did.

**A hyphenated word on its own still stays plain text.** That is on purpose: without the brackets, ordinary words would turn into links by accident. Double brackets round a work or bug id resolve too. The rule is written down now where agents read it: ids link, notes link in double brackets, bare words never do. Only what you see on the page changed.

If people already write it that way, the app should read it that way.
