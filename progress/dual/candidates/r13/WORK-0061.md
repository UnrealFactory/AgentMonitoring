ElmwoodOnline, another project running this app, keeps one note that maps all its other notes. Every row of that map names another note inside double square brackets, like `[[unrealnetcore-queue]]`. Agents write names that way out of habit. The app printed each row exactly as typed, so nothing on the map could be clicked.

**Now each row is a chip: a small label you click to open the note it names.** I taught the part of the app that turns written notes into what you see on screen to recognise that bracketed shape. Only a real note name counts between the brackets — two to sixty-four letters, digits or hyphens, and no hyphen at either end.

**The brackets are the writer's permission.** A note's name is lowercase words joined by hyphens. Ordinary sentences are full of words like that. Linking every one would turn plain phrases into links by accident, so a bare name still stays plain text. Record numbers already linked on their own, and inside brackets they link too.

It is like underlining a name yourself instead of letting a machine underline every word that might be one.

**An ordinary link can begin with a bracket as well.** Its visible label may itself open with one. Testing only for the opening bracket would have grabbed those links too. Matching the whole shape leaves them alone.

**The second trap would have eaten someone's words.** The app must also turn formatted text back into plain writing. My first attempt dropped the brackets on that return trip. In the live Elmwood notes a Korean grammar particle sits welded to the closing brackets, with no space between. Losing the brackets would have taken those letters out of the sentence with them.

**Three checks failed on exactly that.** They failed in a run over Elmwood's own folder, and all 106 checks there pass now. That run uses `node scripts/markdown-smoke.mjs`, the script that feeds prepared writing through the same part of the app and compares each result with the answer written down for it, so a change to the rules cannot quietly garble what somebody wrote. The main run holds 443 checks, with a new group for this case: brackets in table cells, names with spaces, names written inside code. I opened the live Elmwood map in the browser and looked — every row shows as a chip, in prose and in table cells alike.

**The hover label and the right-click menu came free.** That path already existed for record numbers, including what shows when a name matches no note at all. Forget the brackets, though, and the name stays plain words; the app will not guess.

Left out: the type check, and the two documents that now state the rule. Neither changes what you click.

Mark the link yourself, and nothing has to guess what you meant.
