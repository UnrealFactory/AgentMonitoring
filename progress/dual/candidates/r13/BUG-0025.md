Change a file in this app while it is running, save, and the screen still shows the old thing. Reload the whole page and it is still the old thing.

**Two sessions blamed a forgotten server.** Both decided an old server from an earlier run was still up, serving yesterday's code. It was not that: a server started seconds ago was just as blind to anything edited after it started.

**One line of settings had switched off watching for the whole project.** `vite` is the program that serves the app while we work on it. One line in its settings told it to ignore any folder named AgentMonitoring: the app writes its own records into a folder by that name, and those writes should not reload the screen. We wrote that line as `**/AgentMonitoring/**` — any folder called AgentMonitoring, at any depth, and everything inside it.

**This whole repository is itself a folder called AgentMonitoring.** So the line matched every file we have — our source code, and the settings file holding it. The part of `vite` that watches files for changes ignored all of them. Nothing ever told the program a file had changed, so it kept serving the first copy it made of each one. It could not see edits to its own settings either, so it never restarted itself.

It is like a "do not disturb" sign meant for one room, hung on the front door of the building.

**A new file that did nothing gave it away.** `src/lib/useScrollRestoration.ts`, written that day to remember where you had scrolled to, did nothing on a server started minutes earlier. So I used `curl`, a command that asks a server for one file and prints exactly what comes back, on the app's main screen file. The day's edits were missing from it. The new file came back correct, because it had never been asked for before.

**The line now names one exact folder.** It spells out that data folder's full path, not any folder sharing the name. I checked that against a running desktop app. I added one throwaway line to that same scroll file, and it showed up in what the server handed out within two seconds. I deleted it, and it went away again, with no restart. Code still being ignored would have shown neither.

**Edits reach the screen again, and the original point still holds.** Writes into that data folder still do not reload the app; it notices new records by asking for them. What was checked is one file, added and removed by hand while a server ran.

A rule about "any folder with this name" will eventually match the one you are standing in.
