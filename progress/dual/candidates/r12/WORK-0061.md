Agents leave notes for each other inside this app. In one project's index note, every row pointed at another note the way agents naturally write it — the note's name inside double brackets, `[[note-name]]`. The app showed those rows as plain words with nothing to click. It already turned the ids of work records and bugs into small clickable tags; a note's name it left alone.

**Double brackets now make a link.** I taught `src/lib/markdown-parse.ts` — the file that reads a line of a record and works out which parts of it are links — to accept that spelling. It takes only what a note name is allowed to be: two to sixty-four letters, digits or hyphens, and no hyphen at either end. A name written bare in a sentence still never links, because too many ordinary words look like note names. The brackets are the agent saying which one was meant.

It is like underlining a word by hand: the app links what you marked and leaves the rest of the page alone.

**A real link can open with a bracket too.** `[[label](url)` is an ordinary link whose visible label happens to start with a bracket. Had I checked only whether a run of text began with two brackets, those would have been swallowed. Matching the whole shape instead leaves them alone.

**Turning a tag back into plain words lost the brackets.** The app can also go the other way and rebuild the original writing from what it read. My first version put the bare name back without its brackets. In the other project's notes, Korean particles sit welded to the closing brackets — `unrealnetcore-queue]]의` — so dropping them deletes part of the sentence. Three checks failed on exactly that, mid-work; the rebuilt writing now carries the brackets.

**Those three checks pass now.** `node scripts/markdown-smoke.mjs` is the script that feeds prepared record text through that reader and compares every piece it finds against what we wrote down it should find; when it says no, readers are seeing the wrong thing on the page, or losing words out of their own sentences. It reports 443 checks passing. A new seventeenth batch of prepared examples covers brackets in prose and in table cells, bare names staying text, brackets inside code staying literal, that bracket-opening link staying a link, and the rebuilt writing keeping its brackets.

I ran the same script over the live notes of ElmwoodOnline, another project whose agents keep their records in this app. All 106 checks pass, the three broken ones included. Then I opened that project's index note in the app and looked at it myself: every bracketed row of the map now shows as a clickable tag, in prose and inside table cells, and the record tags look exactly as they did.

**An agent can now link a note by writing its name in brackets.** The same brackets around a work record's id work too. A name left bare still does nothing, on purpose — so an agent who forgets the brackets gets no link and no warning. I wrote the rule into `SPEC.md`, the document that says how this app must behave, and into the manual agents read: ids link, notes link in double brackets, bare names never.

Better to link what someone marked than to guess at what they meant.
