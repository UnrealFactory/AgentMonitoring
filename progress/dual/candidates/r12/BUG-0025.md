You change a line in the app's code and the screen shows nothing new. Save it, reload the page — still the old app. The server we run while working hands out the version it built the first time it was asked, and never builds it again.

**Twice we blamed a leftover server.** The guess was that an old server from an earlier session was still running. But a server started seconds ago was just as stale for any file edited after it started.

**One line of settings switched off watching for the whole project.** `vite.config.ts` is the settings file for that server, and one entry lists what it should not watch. We had written `**/AgentMonitoring/**` — any folder called AgentMonitoring, at any depth, and everything under it. We meant the folder where this app saves its own records. But the whole project lives in a folder named AgentMonitoring.

**So the rule swallowed the code too.** Every source file and script sits inside that name, and so does the settings file holding the rule. Nothing was watched, so nothing was rebuilt. The server could not even see edits to its own settings, so it never restarted itself.

It is like telling a night guard to skip the room marked AgentMonitoring, in a building called AgentMonitoring.

**A brand-new file behaved as if it did not exist.** Someone had just written a small piece of the screen code, and it did nothing at all. So I asked the running server for the main screen file it was serving: the day's edits were missing, though the new file itself came back correct the first time it was asked for.

**The rule now names one exact folder.** It points at this project's records folder by its full location, worked out from the project root. Everything else is watched again.

**I watched one edit land.** On a live server I added one throwaway line to that same new file. Within two seconds the server was handing out the new version. I deleted the line and it vanished again, with no restart. Under the old rule neither would have shown up.

Edits show up while you work again. What the old rule was for still holds: when the app saves its own records the server does not rebuild, and the app still notices them because it keeps asking. The proof is one edit, made by hand, on one running server.

A rule that skips folders by name will skip your own house if it shares the name.
