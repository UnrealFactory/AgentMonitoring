Change a file in the app's code while the app is running, and nothing changes on screen. Reload the whole page and the old code comes back. The program that feeds the app its code prepared a version of every file when it started, and it never makes another.

**Twice we blamed the wrong thing.** Both times we decided an old copy of that program was still sitting on port 5173. It was not that: a copy seconds old was just as stale, for any file edited after it started. What settled it was a piece of the app I had just written, which did nothing in the running app. I asked the server for the app's main file, and it handed back a version missing that day's edits.

**One line of settings hid the whole project.** The server reads its settings from `vite.config.ts`. That file told the watcher — the part that notices when you save a file — to skip `**/AgentMonitoring/**`, meaning any path with a folder called `AgentMonitoring` in it. It was put there for a reason: this project writes its own records into a folder of that name, and those writes should not make the app reload.

**But the repository is itself named AgentMonitoring.** That is the project's own folder on disk, and every file we work on sits inside it. So the watcher skipped all of them: the app's code, the scripts, and the settings file carrying the rule. It could not see its own settings change either, so it never restarted itself.

It is like telling a helper to skip any box labelled Archive, then handing them everything you own in one box labelled Archive.

**The rule now names one folder, not any folder.** It points at the data folder at the top of this repository, written out in full. Writes into it still cause no reload, which is all the old rule wanted.

**I watched a line appear and vanish.** With the app running, I added one harmless line to that new piece of code, put there only so I could spot it. Within two seconds the server was serving it. I deleted the line, and the server stopped serving it. A sleeping watcher would have shown me the old file both times; nothing restarted.

**Saving a file changes the app again.** The records this project keeps about itself still set off no reloads — the app learns about those by asking its own server, over and over, for anything new. I checked all of this by hand, against one running server.

Before you tell a machine to skip everything called X, check what you are standing in.
