Another project keeps a memory map: one note whose rows point at its other notes. The rows are written `[[unrealnetcore-queue]]` — a note's short name inside two square brackets. Our app printed them exactly as typed, brackets and all, with nothing to click.

**Agents write those brackets on their own.** A record id in a sentence already became a tag you can click. A note's name never did. Note names are lowercase words joined by hyphens, and such words turn up in ordinary sentences; linking all of them would catch words nobody meant as links. Two brackets are how a writer says out loud that this one is meant as a link.

It is like quotation marks: the word inside does not change, and the marks are the whole signal.

**I taught the part that reads our text one new shape.** `src/lib/markdown-parse.ts` is the file that turns a record's written text into what you see on screen. I added a pattern there for two brackets around a note name — letters, digits and hyphens, no hyphen at either end, the shape the app already accepts as a name. It builds the same link a record id builds.

**Two things nearly went wrong.** An ordinary link whose visible words open with a bracket also starts with two brackets, so I match the whole shape. The app can also turn a link back into plain text; mine dropped the brackets doing it. A run over that project's real notes caught it: in Korean the next word is welded to the closing brackets — `unrealnetcore-queue]]의` — so eating them eats part of a word. It now puts the brackets back.

**443 checks pass.** `node scripts/markdown-smoke.mjs` is the script that feeds prepared scraps of text through that reader and compares every result with the answer written down for it. New cases cover brackets in sentences and table cells, plain hyphenated words staying text, and the brackets surviving the trip back to text. Pointed at that project's live notes it passes 106 checks, the three that had failed among them. I opened the memory map in a browser and looked: every row is a tag.

**Write `[[note-name]]` now and it lands as a working link.** Hover text, right-click menus and the "no such note" state work as they do for ids. A hyphenated word standing alone in a sentence still stays plain text, on purpose. That rule is now written down in `SPEC.md`, which says how this app should behave, and in the manual agents read. Nothing changed about how records are stored or run from the command line.

Two brackets cost the writer nothing; guessing which words are links costs everyone else.
