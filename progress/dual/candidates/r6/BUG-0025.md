You edit a file in the app. Nothing on screen changes. Reloading the page does not help. While we build this app, a second program runs beside it. It hands the browser the newest version of every file. It had stopped noticing our edits entirely.

**The ignore rule.** That program watches our files and rebuilds what changes. We had told it to skip one folder. This app writes its own records into a folder named AgentMonitoring, and those writes are not code. The skip was written as a wildcard: any folder called AgentMonitoring, at any depth. But the whole project lives in a folder called AgentMonitoring too. So the rule matched every file we own. The watcher skipped the entire codebase.

It is like being told to ignore anything in the room marked Archive, inside a building named Archive.

Two work sessions blamed the wrong thing. Both guessed an old copy of the program was still running. It was not. A freshly started one goes stale for every file you touch afterwards.

A new feature written that day exposed it. It sat in the app doing nothing at all.

The fix names one exact folder path instead of a wildcard. Only the data folder at the top of the project is skipped now.

**The probe.** With the app running, we added a marked line to a real source file. It reached the served code in under two seconds. We deleted it; it left again, no restart needed. That rules out stale code in either direction.

Editing works again. Record writes still restart nothing, and the app still sees new records by asking for them repeatedly.

Nothing would announce this failure if it came back. It hid for two work sessions, and the proof was one check run by hand. Left out: our settings file, and the served copy we checked. Neither changes what you see.

A rule that says "anywhere" also means the place you are standing.
