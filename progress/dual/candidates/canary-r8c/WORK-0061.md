ElmwoodOnline, another project keeping its records in this app, has one note that is a map of its other notes. Its rows are written in double brackets — `[[unrealnetcore-queue]]` and the like. On screen those rows came out as plain text, brackets and all, with nothing to click. Ids of past work already turned into little clickable chips there.

**Now the brackets make a link.** I added a rule to `src/lib/markdown-parse.ts`, the file that reads the text of a record and decides which pieces of it are links. A name inside double brackets now points at that note. It counts only if the name is shaped the way the app already accepts note names: 2 to 64 letters, digits and hyphens, no hyphen at either end.

**A bare hyphenated word still stays plain text.** That is deliberate: too many ordinary words look like a note name. It is like underlining a word by hand — the underline is you saying you meant this one.

**Matching only the opening bracket would have broken real links.** Written text already has a link whose label starts with a bracket, `[[label](url)`. So the rule has to match the whole shape, not just the start.

**Turning a link back into plain text ate Korean.** The app also runs backwards, putting the pieces back as ordinary characters. My first version dropped the brackets on the way back. In the Elmwood note a Korean particle sits welded onto the closing brackets — `unrealnetcore-queue]]의` — so dropping them threw away real writing. Putting the brackets back fixed it.

**443 checks pass.** `node scripts/markdown-smoke.mjs` feeds prepared snippets of record text through that reader and compares each result against what we wrote down it should give. Its new seventeenth batch covers brackets in prose and inside table cells, bare hyphenated words staying text, code snippets staying literal, that bracketed-label link staying a link, and the brackets surviving the trip back.

**Then I ran it over the real records and looked.** The same script across ElmwoodOnline's folder passed 106 checks, the three that broke mid-work among them. I opened that map note in the browser: every bracketed row is a chip now, and the older work chips are unchanged.

**The rule is written where agents will read it**, in `docs/AGENT_MANUAL.md`: ids link on their own, a note links inside double brackets, a plain hyphenated word never links. Nothing changed in how records are stored — only in what is drawn.

The app links what you marked, not what it guessed.
