In another project of ours, one note is the map to all the others. Its rows are written `[[unrealnetcore-queue]]` — the name of another note wrapped in two square brackets. On our screens those rows came out as exactly that: brackets, a hyphenated word, plain text nobody could click. Agents write links that way out of habit, and the app ignored them.

**The brackets now make a tag you can press.** I added a rule to `src/lib/markdown-parse.ts`, the file that turns a record's written text into what the screen draws. When it meets a name inside double brackets, it hands back the same small clickable tag that a work or bug number already gets, and pressing it opens that note. The name has to look like a note name: letters, digits and hyphens, no hyphen at either end. A hyphenated word with no brackets round it stays plain text on purpose — start guessing there and you link words that were never notes.

It is like quotation marks. The marks are how you say you meant the word as a name.

**An ordinary link can begin with a bracket too.** Spelled out, `[[label](url)` is a normal link whose visible words happen to open with one. Had I decided by the first two characters, I would have swallowed links like that. So the whole shape has to match, or the text is left alone.

**Someone's Korean was welded to the closing brackets.** The app also turns this text back into plain writing again, and my first attempt dropped the brackets on the way back. Those live notes contain `unrealnetcore-queue]]의` — a Korean particle stuck straight onto the two closing brackets. Eating the brackets throws away what a person typed. They now come back exactly as written.

**443 checks pass.** `node scripts/markdown-smoke.mjs` is the script that feeds prepared scraps of record text through this same reader and compares every result against what we wrote down as right. The new ones cover brackets in prose and in table cells, hyphenated words left as text, brackets inside code left untouched, and the brackets surviving that round trip. Run over the other project's real notes it passes 106, the three that had caught me among them. A row still coming out as dead text would have failed here.

**I opened the live map note in the app and looked.** Every bracketed row on it is a tag now, in the prose and in the table cells alike, and the work and bug tags look as they always did.

**No stored record changed; only the drawing did.** The rule is written down in `SPEC.md`, the file that says what this app must do, and in the manual agents read: numbers link on their own, notes link inside brackets, a bare hyphenated word never does. That last part is a choice, not a gap — you have to type the brackets.

A link is what the writer marked, not what the app guessed.
