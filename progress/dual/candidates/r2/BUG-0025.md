Editing any frontend file while the development server ran changed nothing in the app. No live update, and even a full reload served the old code. Two sessions blamed a stale leftover server before the real cause surfaced.

**One folder name, two meanings.** The server's settings file told its file watcher — the part that notices saved files — to ignore anything under a folder called AgentMonitoring, so data writes there would not bounce the app. But this repository's own directory is named AgentMonitoring. The rule was written `**/AgentMonitoring/**`, which matches a folder of that name at any depth, so it matched every file in the repo.

So nothing was watched. The server compiles each file the first time the browser asks for it and keeps that result until told the file changed; nothing ever did. It could not even see edits to its own settings file, so it never restarted itself either.

**What fooled two sessions.** A restart looked like a cure, because a fresh server compiles whatever you ask for next. It went stale only for files edited after it started, so a server seconds old was already broken and blaming a leftover one kept seeming almost right. The giveaway: a helper file added that day was dead in the app yet compiled fine on first request, while the served main app file lacked the day's edits.

**The fix.** The ignore rule now names one exact folder — the data folder at the repo root — not any folder with that name anywhere.

**How we know.** Checked live against a running desktop dev server: a one-line marker added to that helper file appeared in the served code within two seconds, and vanished on removal. No restart in between, so changes register both ways.

Frontend edits show up again, and `npm run dev`, the command that starts the server, no longer needs restarting. Data writes still cause no reloads; the app notices those by asking its own project interface on a timer. The record lists only this one live check; no automated test guards the pattern, so a future edit could bring the problem back unnoticed.
