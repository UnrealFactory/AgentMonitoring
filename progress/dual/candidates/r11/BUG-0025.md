While the app ran for development, editing any of its screen files changed nothing on screen. The page did not update on its own, and reloading it by hand gave the old code back too. Two commands start it that way, `npm run dev` and `npm run tauri:dev`.

**Two sessions blamed an old server left running.** Port 5173 is the numbered door the development server answers on. It was the wrong guess. A server seconds old had the same fault: it was already stale for any file edited after it started.

**One line in a settings file told the watcher to skip the whole repository.** `vite` is the program that converts our source files and serves the app to the browser while we work. It has a watcher, `chokidar`, whose job is to tell it when a file on disk has changed. In `vite.config.ts`, the settings file vite reads when it starts, we had told chokidar to ignore `**/AgentMonitoring/**` — any folder named AgentMonitoring, at any depth, and everything inside it.

**This repository is itself named AgentMonitoring, at `C:/Code/AgentMonitoring`.** So the pattern matched every path in it — `src/`, `scripts/`, `vite.config.ts` itself — and the watcher ignored the whole codebase. Vite converts each file once, on first request, and hands out that copy until something tells it the file changed. Nothing ever told it.

It is like a note for the cleaner saying "skip any room called Office", in a building that is itself called Office.

**A brand-new file proved it.** `WORK-0039` had just added `src/lib/useScrollRestoration.ts`, a piece of code whose name says it puts you back where you had scrolled to. In the app it did nothing at all. So I asked the server for `src/App.tsx` using `curl`, the command that fetches one file from a server and prints exactly what comes back. The day's edits were missing from it, while that new file came back correct the first time it was asked for.

**The rule now points at one folder by its full path.** It ignores the AgentMonitoring data folder inside this repo, instead of any folder anywhere with that name. I checked against a live server: I appended one throwaway line, `export const __watchProbe = 1`, to that file. It appeared in what the server handed out within two seconds, and vanished again when I deleted it, with no restart.

**What the old rule was for still holds.** Writes into this repo's own AgentMonitoring folder, where the app keeps its records, still do not reload the running server. Nothing automatic guards this; the only check was the one I ran by hand.

A rule that skips everything named X will skip you too, if you are standing in X.
