In another project's folder — `ElmwoodOnline` — one note indexes all the others. Its rows name them in double square brackets, rows like `[[unrealnetcore-queue]]`. On screen those rows sat as plain text, brackets and all. Nothing to click.

**Double brackets now make a link.** I taught `src/lib/markdown-parse.ts` — the file that reads a record's text and decides which words become links — to recognise that spelling. It accepts only what a note name may be: 2 to 64 letters, digits and hyphens, no hyphen at either end. Those get the same small clickable tag a work or bug number already gets.

A hyphenated word without the brackets still stays plain. It might just be a word; the brackets are how you say you meant a note. It is like a word highlighted by hand in a book: marked, so it stands apart.

**Checking for two brackets at the front would have caught the wrong thing.** An ordinary link can start with a bracket too, when the words it shows do. So the code looks for the whole shape of a name, not just the opening.

**Korean particles were welded to the closing brackets.** The app also has to turn its reading back into plain text, brackets restored. Sweeping the real notes, I found rows like `unrealnetcore-queue]]의` — the name, its closing brackets, and a Korean particle pressed straight against them. Dropping the brackets ate the particle. Three checks against those real notes failed on that mid-work, then passed once the brackets came back.

**I checked against real notes, not only made-up ones.** `node scripts/markdown-smoke.mjs` feeds prepared scraps of record text through that reader and compares each result with what was written down. When a check of that kind says no, somebody's note reaches the screen as something other than what they typed. All 443 pass. The new group among them covers the brackets in prose and inside table cells, and brackets with spaces or code inside staying literal.

Pointed at that other project's real folder, the same script passes 106. I also opened that index note in the app and looked. Every bracketed row is a tag now, in prose and in table cells. The work and bug tags look as before.

**Agents can write the link the way they already write it.** The rule now sits in `docs/AGENT_MANUAL.md`, the handbook agents read before working here: work and bug numbers link on sight, a note links when its name sits in double brackets. Nothing changed in how notes are stored or what the command-line tool does — only what the screen shows.

A computer can link what you marked. It can only guess at what you merely typed.
