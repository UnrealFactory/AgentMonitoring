You edit a file in the app and nothing on the screen changes. Not on save, not after a full page reload. That screen comes from `npm run dev`, the command that builds the app and serves it to your browser as you work. It kept serving the code exactly as it stood the moment it started.

**Twice we blamed an old server left running.** A server started seconds ago is just as blind to anything you edit after it starts.

**One line of settings was skipping the whole project.** `vite.config.ts`, the settings file for that server, lists places its file-watcher — the part that notices when a file changes — should leave alone. This project keeps its own records in a folder named AgentMonitoring, and every write into them would otherwise reload the app in your face. So the list held `**/AgentMonitoring/**`: any folder called AgentMonitoring, wherever it sits, and everything in it.

**The folder holding this whole project is named AgentMonitoring as well.** So it covered every file we have: the source code, the scripts, even the settings file holding it. Nothing ever told the server that a file had changed. Each file was built once, the first time it was asked for, and stayed that way — the settings file included, so the server never restarted itself either.

It is like telling a helper to ignore every box marked Spare, in a room that is also marked Spare.

**A brand-new file looked perfectly healthy.** I found this when a piece of code written that day did nothing at all in a server started minutes earlier. I asked that server for its own copy of the app's main file: the day's edits were nowhere in it. The new file, never asked for before, came back correct the first time.

**The ignore now names one exact folder.** It points at the records folder inside this project, not at any folder anywhere carrying that name.

**I watched one line arrive and leave.** Against a live server I added one throwaway line to that same new file. It showed up in what the server served within two seconds, and vanished when I deleted it — both directions, no restart. A server still frozen would have shown me neither.

**Your edits show up again, and the records folder still stays quiet.** Writes into those records still do not reload the server, and the app still spots them, because it keeps asking the server for them. For proof I have one check by hand: one file, one running server.

A rule that says "ignore anything called X" will one day catch the thing you are standing in.
