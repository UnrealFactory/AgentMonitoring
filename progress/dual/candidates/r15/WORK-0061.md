Another project that uses this app, ElmwoodOnline, keeps one note that maps all its other notes. Rows of that map name a note inside double square brackets — `[[unrealnetcore-queue]]` is one row. Agents write names that way by habit. Our app printed those rows as flat text, with nothing to click.

**Now each of those rows opens the note it names.** I added one pattern to `src/lib/markdown-parse.ts`, the file that turns a record's writing into what you see on screen. When it meets a name inside double brackets, it hands back the same link the app already builds for record numbers. The row becomes a chip: a small label you click.

**The brackets are the permission.** A note's name is lowercase words joined by hyphens. Ordinary sentences carry words like that too. Linking every one of them would turn plain phrases into links nobody asked for. So a bare name still stays plain text.

It is like putting your hand up. The app links the names that ask, and leaves the rest alone.

**An ordinary link can show words that themselves begin with a bracket.** Testing only the first two characters would have grabbed those links as well. The app matches the whole shape instead.

**The second trap would have eaten someone's words.** The app also has to turn its formatted text back into plain writing. My first attempt dropped the brackets on that return trip. In Elmwood's notes, Korean sentence endings are written stuck against the closing brackets, with no space. Dropping the brackets there takes letters out of a person's sentence.

**Three checks caught that.** `node scripts/markdown-smoke.mjs` runs prepared scraps of writing through that same file. It compares each result with what was written down. A no from it means the app is showing a record differently from how somebody typed it. Three of its checks failed mid-work, on the dropped brackets.

**They pass now.** Over Elmwood's own folder all 106 pass; over our records, 443. A new group covers brackets inside table cells, names with spaces, names inside code, and the brackets coming back whole.

**I opened Elmwood's map note in the browser version of the app and looked.** Every bracketed row shows as a chip. The record-number chips look as they did before. The hover label and the right-click menu came free, on the path record numbers already used. Write a note's name without the brackets, though, and it stays plain words.

Left out: a check that the code's own types still line up, and two guides that now write the rule down. Neither changes what you click.

Better a link somebody asked for than a link the app guessed.
