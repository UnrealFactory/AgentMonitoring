In `ElmwoodOnline`, another project whose records this app shows, one note indexes the project's other notes. Its rows are written `[[unrealnetcore-queue]]` — a note's name wrapped in double square brackets, the way agents point from one note to another. On our screen those rows were not links, just letters and brackets.

**A record's id already became a chip; a note's name never did.** Write a work item's id in a sentence and the app makes it a clickable badge. A note's name got nothing, on purpose: a hyphenated word is usually just a word, and a wrong guess makes a link to nothing. The brackets settle it.

It is like raising your hand before you speak. Any hyphenated word could be a note's name; only the brackets say you meant one.

**Now the brackets make a chip.** I taught `src/lib/markdown-parse.ts`, the file that turns a record's written text into what you see on the page, to recognise the bracketed form. It accepts only the names the app already allows, and hands back the same link the ids use. So the badge, its hover text, its right-click menu, and what it shows when the name matches no note all work untouched.

**Reading only the first two characters would have broken ordinary links.** An everyday web link puts its clickable words in square brackets, so a link whose words start with one begins the way a note link does. The code matches the whole shape instead.

**Going the other way ate people's words.** The app also turns a line back into plain text. My first version returned the bare name and dropped the brackets. In Korean the grammar particle is written stuck onto the closing brackets — `unrealnetcore-queue]]의` — so losing them rewrites the sentence somebody wrote. They come back with the name now.

**443 checks agree with what we wrote down by hand.** `node scripts/markdown-smoke.mjs` feeds prepared snippets of record text through this renderer and compares each result with the answer written beside it; when one disagrees, the app is drawing somebody's words wrong. All 443 pass, including new cases for brackets inside table cells and for the brackets coming back. Over ElmwoodOnline's real records the same script passes its 106, including three that failed mid-work while the brackets were still being dropped.

**I opened that index note and looked.** Every bracketed row is a chip now, and the record badges look as they always did.

**Bare hyphenated words still refuse to link, on purpose.** That rule is written down now in the manual agents read: only bracketed names and record ids link. Only what the page draws changed.

A link is something the writer asks for, not something the screen guesses.
