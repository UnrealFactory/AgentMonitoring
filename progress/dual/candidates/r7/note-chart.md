Our activity charts show several kinds of record at once. Each kind gets its own colour — one for work, one for done, one for bug, one for notes. Someone had to be sure the note colour does not blur into the ones drawn beside it.

The note colour is `#c9629b`. That string is how a program spells one exact shade of pink. The chart code reaches for it under the name `--series-note`. We put it through the dataviz palette validator. That is a program that holds chart colours up against each other in pairs. It reports back the pairs a person could not tell apart.

We ran it on the pairs that actually get drawn on screen: the note pink against the work colour, against the done colour, against the bug colour. Those passed.

That is all the checking there is. The purple used for fixes never went through it. Neither did the greys. Neither of those is drawn beside the note pink today. A pass beside one neighbour says nothing about a neighbour you never tried.

It is like holding a paint chip against the two walls of one room, then calling the colour settled for the whole house.

The charts people see now are fine as drawn. The risk sits in the next chart someone builds. Anyone who puts note pink beside fix-purple, or beside a grey, has to run the validator again before that chart ships.

A colour is only cleared against the company you checked it in.
