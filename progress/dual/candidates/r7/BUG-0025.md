You change a line of the app's code while the app is running on your own machine. Nothing on the screen changes. You reload the page from scratch and still get the old code. Two working sessions blamed a leftover program squatting on port 5173 — the numbered door on this machine where the development server answers. They restarted it. A brand-new server was just as stale.

**The sign meant for one cupboard.** The development server here is vite: it rebuilds the app while you work and hands the result to the browser. Its settings file, `vite.config.ts`, carried one instruction for the part that watches files for edits. Ignore `**/AgentMonitoring/**` — meaning any folder called AgentMonitoring, at any depth, and everything inside it. It was aimed at the data folder this project writes its own records into. But the repository itself sits at `C:/Code/AgentMonitoring`. Its own name is AgentMonitoring. So the pattern matched every file in the project, and the watcher ignored all of them.

It is like a do-not-enter sign meant for one cupboard, hung on the front door of the house instead.

With nothing watched, vite never hears that a file changed. It keeps serving the converted copy it made the first time anyone asked for that file, for as long as it runs. It could not see edits to its own settings file either, so it never restarted itself. That is why the leftover-server guess survived: a server seconds old is already stale for anything you edit after it starts.

**How it surfaced.** A scroll-position helper added in WORK-0039, `src/lib/useScrollRestoration.ts`, was completely dead against a server started minutes earlier. Fetching one served file straight from the server showed the day's edits missing from it. The new file itself worked, because it was first requested after the server started.

The settings file now points at one exact folder instead of a pattern: the AgentMonitoring data folder directly inside the repository, spelled out in full, with everything under it.

**The probe.** Against a running server, one throwaway line was appended to that scroll helper. It showed up in what the server served within two seconds. It vanished again when the line was deleted. A blind watcher would never have shown the line at all; a half-working one would have kept it after deletion. Neither happened, and the server was not restarted.

Editing frontend files works again, live, while the app runs. The original intent holds: writes into the AgentMonitoring data folder still do not jog the server, and the app keeps noticing them by asking for updates on its own. The proof was a person watching one file once. Nothing automatic now guards the setting, so the next person who edits it repeats that check by hand. Left out here: the exact text of the new setting. It does not change what you see.

A pattern that skips folders by name will skip the one you are standing in.
