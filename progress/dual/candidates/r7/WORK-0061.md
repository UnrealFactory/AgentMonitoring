In another project, ElmwoodOnline, an agent keeps a note named `unrealnetcore-index`. It maps that project's other notes. Its rows name them: `[[unrealnetcore-mission-decisions]]`, `[[unrealnetcore-queue]]`. On screen those rows sat there as plain text, double brackets and all. Nothing to click.

**The spelling nobody was reading.** Record ids like `WORK-0061` already turn into chips — small badges you click to open that record. Note names did not, on purpose. A note's name is lowercase words joined by hyphens, and prose is full of words like that. Linking all of them would link the wrong things. But agents write the double-bracket form anyway. That form is not a guess. It is someone pointing.

It is like putting quotation marks around a word so nobody has to work out whether you meant it as a name.

**`WIKILINK_RE`.** That is the new pattern, added to `src/lib/markdown-parse.ts`, the file that turns written text into what the screen shows. It joins `INLINE_RE`, the list of patterns that file tries inside a line. It accepts only the shape a real note name has: 2 to 64 letters, digits or hyphens, no hyphen at either end. A match becomes the same link a record id becomes. Chips, tooltips, right-click menus and the unknown-name state came free.

**The bracket that was not a link.** An ordinary link can have brackets in its own visible words: `[[label](url)`. That opens with two brackets too. Testing only the opening characters would have swallowed it, so the code re-tests the whole pattern before deciding.

**Korean particles.** The app also flattens a written line back to plain text. My first version dropped the brackets there. Running the checks over Elmwood's real folder broke three of them: in Korean the grammatical ending is typed straight onto the closing brackets — `unrealnetcore-queue]]의` — so eating the brackets ate part of the sentence. Flattening now puts them back.

`node scripts/markdown-smoke.mjs` is our text checker: it feeds prepared samples through the parser and checks each result against what we wrote down. All 443 of its checks pass. The new group, fixture 17, is the one that rules out the near misses — a bare hyphen-word stays text, code stays literal, `[[label](url)` stays a link, flattening restores the brackets. The same checker over Elmwood's live folder passes 106, the three broken ones included. The type checker read the code without running it and reported nothing. A screenshot of that Elmwood note, `progress/shots-wikilink/note-detail-full.png`, shows every map row as a chip.

Double brackets now click through, in prose and in table cells alike. A record id inside them, `[[WORK-0004]]`, resolves too. A name written without the brackets still goes nowhere; that stayed deliberate, and it is what to remember when a link fails to appear. The rule is written down now, in `SPEC.md`, the document saying what the app must do, and `docs/AGENT_MANUAL.md`, the guide agents read. How notes are stored did not change. Left out: the parts that already knew how to turn a name into a page, and the flag the new link carries. Neither changes what you see.

A link you have to guess at is a link you will get wrong.
