# 작업 기록 — AgentMonitoring

이 프로젝트의 작업 이력과 지식은 AgentMonitoring이 관리합니다. 이곳의 기록을
읽는 것은 사람만이 아닙니다 — 다음 세션의 에이전트, 병렬로 일하는 다른
에이전트가 이 기록을 공유 메모리 삼아 이어서 일합니다. 자체 메모리 파일이나
임시 노트를 만들지 말고, agentmon MCP 도구로 여기에 기록하세요. 모든 기록은
**한국어 존댓말**로 작성합니다.

## 세션 시작

- `note(action: "list")`부터 실행하세요. 이전 세션들이 남긴 노트(메모리·핸드오프·
  결정·참고)가 이 프로젝트의 기억입니다. `status`로 진행 중인 작업과 열린
  버그도 확인하세요.

## 작업을 마치면

- 의미 있는 작업 하나를 끝낼 때마다 `log_work`로 기록하세요. outcome까지 채우면
  한 번의 호출로 완료됩니다.
- 긴 작업은 outcome 없이 먼저 열어 두고(WORK id를 받습니다), 진행은
  `update_work`의 note로, 완료는 outcome으로, 중단은 abandon으로 닫으세요 —
  실패도 기록입니다.
- 지나간 일을 나중에 기록할 때는 started_at / finished_at에 실제 시각을 넣으세요.

## 버그와 노트

- 버그를 발견하면 `report_bug`(재현·기대·실제), 고치면 `resolve_bug`(원인
  comment + resolution). 관련 WORK id를 refs로 연결하세요.
- 다음 세션에 필요한 사실·결정은 `note(action: "write")`로 남기세요. 작업을
  중간에 멈출 때는 반드시 handoff 노트를 남기고, 틀린 노트는 갱신하거나
  remove하세요.
- 이 기록 시스템(AgentMonitoring) 자체의 버그나 아쉬운 기능은 `app_feedback`으로
  남기세요 — 프로젝트가 아니라 앱 관리자에게 가는 기록입니다.

## 읽는 이를 위해 쓰기

- 그 자리에 없던 독자가 기준입니다. 파일 경로·명령어·화면 이름을 구체적으로
  적고, 이 대화에서만 통하는 약어를 만들지 마세요. 본문에 WORK-NNNN /
  BUG-NNNN을 쓰면 자동으로 해당 기록으로 가는 링크가 됩니다.
- 본문은 마크다운으로 풍부하게 렌더링됩니다. 표, 코드 블록, 체크리스트,
  `> [!note]` 콜아웃, 코드 블록 안의 ASCII 다이어그램을 적극 사용하세요.
- 다이어그램·이미지는 `AgentMonitoring/assets/`에 파일로 넣고
  `![무엇을 보여주는지](assets/파일.svg)`로 참조하세요(svg·png·jpg·gif·webp,
  10MB 이하). 앱 배경이 어두우니 SVG에는 배경색을 넣으세요. 외부 URL 이미지와
  raw HTML은 렌더링되지 않습니다.

## 규칙

- 실제로 한 일만, 한 대로 기록하세요. 검증하지 않은 것을 검증했다고 쓰지 마세요.
- 레코드 파일을 직접 만들거나 수정하지 마세요 — 기록은 도구로만 씁니다. 직접
  써도 되는 파일은 assets/의 이미지뿐입니다.
- 닫힌 로그의 정정은 `Correction:`으로 시작하는 note로 덧붙이세요.
