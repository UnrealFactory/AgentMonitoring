## Report

Two records cite BUG-0004 for a defect BUG-0004 is not about.

WORK-0011 (`## Why`, the paragraph explaining why the dashboard's clipping was filed rather
than fixed) says:

> The clipping defect is the same class BUG-0004 was on the bug board: a fixed box with
> `overflow: hidden` around content that does not fit, cutting mid-glyph with no ellipsis.

BUG-0006 says it twice — once in its report ("This is the same class of defect as BUG-0004 on
the bug board") and once in its own resolution ("This is the same shape of defect as BUG-0004
on the bug board, and the report said so"). WORK-0011 copied the claim from there.

**BUG-0004 is not a clipping defect.** Its title is *Record renderer rewrites the vault: a
wrapped line starting with a number becomes list item 1*; its labels are `frontend, markdown,
data-fidelity`; and the strings `overflow`, `clip`, `cut off`, `ellipsis` and `truncat` occur
zero times in the whole record. It is the parser turning a soft-wrapped line into an ordered
list and deleting the `200` out of "…503 for three hours, then / 200."

The defect the two records mean is real and it was on the bug board — it was simply never
filed. It was fixed in commit `96fabbd` (2026-08-18T15:58Z), whose message describes it
exactly: "`.bug-row-people` was a 140px box with `overflow:hidden` around an inline
`.handoff`, so the ellipsis on `.agent-name` could never fire… Three of five rows on this
project's own board read 'p3-bugs-builc' and 'p0-foundatior'." BUG-0004 shipped one commit
earlier, in `dd630c0`.

The nearest *record* of that class in this vault is BUG-0009, *A long path in inline code is
cut in half by the card holding it* — a box with `overflow: hidden` around content that does
not fit, cutting mid-glyph. It was filed at 18:47Z, three hours after BUG-0006's report, so
BUG-0006's report could not have cited it; its resolution (21:31Z) and WORK-0011 (21:33Z)
both could.

Expected: an id written into a sentence names the record the sentence is about.

Actual: it names an unrelated one, and clicking the chip takes the reader to a markdown bug
while the sentence talks about layout.

Found by the P6 comprehension critic. Same class as BUG-0017 and found in the same reading:
a fact nobody checked, carried across as true by a reader who reconstructed the record
faithfully. The reference here is worse than the roster number, because the app used to
print only the id — so the reader could not see the mis-citation at all without following it.

## Resolution

**The record to read is BUG-0009**, or commit `96fabbd` for the board fix itself, which was
shipped without a bug record. BUG-0004 is the markdown renumbering defect and has nothing to
do with clipping.

**Root cause.** Nobody followed the id. The sentence in BUG-0006's report was written from
memory in the same hour that both defects were being worked, the resolution repeated its own
report three hours later, and WORK-0011 copied the resolution. Three chances to check one
four-character number, and the app made none of them easy: an inline chip printed `BUG-0004`
and nothing else, so a reader had to leave the page to find out that the citation was wrong.
A reference nobody can check is a reference nobody checks.

**Fix, in two parts, neither of which edits history.**

1. The vault is append-only and both cited records are finished, so their sentences stay as
   written. This bug is the correction: it `refs` all four records, so it appears under
   **Referenced by** on WORK-0011, BUG-0006, BUG-0004 and BUG-0009 — a reader who arrives at
   the wrong id finds the right one one line below it. That mechanism was itself decorative
   until today: the Referenced-by title was one nowrap line in a 359px box, so BUG-0017's
   correction rendered as "WORK-0011 says relay is three weeks of ten agents; rela…" at every
   width the app draws. Titles on that card now wrap.
2. `src/lib/markdown.tsx` — an id written into prose carries the title of the record it names
   in its tooltip, from the index the page has already loaded for the Related block, and an id
   no record answers to keeps its chip shape but gives up its accent and says so. The
   mis-citation in WORK-0011 now reads `BUG-0004 — Record renderer rewrites the vault: a
   wrapped line starting with a number becomes list item 1` where it stands, next to a
   sentence about `overflow: hidden`.

**Verified.**

- The claim itself, counted rather than remembered: `overflow`, `clip`, `cut off`,
  `ellipsis` and `truncat` occur 0 times in BUG-0004.md; `git show 96fabbd` describes the
  board's `.bug-row-people` clipping in its own commit message; BUG-0009 (created
  2026-08-18T18:47Z) is the vault's only record of that class, and it postdates BUG-0006's
  report (15:44Z) — which is why the report could not have cited it and its resolution
  (21:31Z) could.
- Both corrections are legible on the running app: at 2400, 1600, 1440, 1280, 1152 and 960px
  the Referenced-by rows on /p/agent-monitoring/work/WORK-0011 print their titles whole, and
  hovering the `BUG-0004` chip in `## Why` shows the title of the bug it actually points at.
- `npm run smoke` (278 checks), `npm run check:clipping`, `npm run check:counts`,
  `npm run check:urlstate`, `npm run check:keys`, `npm run check:live`, `npm run check:vault`,
  `cargo test --workspace` and `agentmon doctor --strict` all pass on this tree.

**Not fixed.** The two sentences are still wrong on their own pages, and always will be —
that is what an append-only vault costs. What changed is that the wrong id is now readable as
wrong without leaving the paragraph it sits in.
