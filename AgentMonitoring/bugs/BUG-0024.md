## Report

Repro (intermittent — roughly one full-workspace run in five on this machine):

1. `cargo test --workspace`
2. `concurrent_writers_never_share_an_id_or_lose_an_event` (crates/agentmon-core/tests/write_roundtrip.rs) fails with `Io { path: ".../.agentmon.lock", source: Os { code: 5, kind: PermissionDenied }`.

Expected: eight threads doing `work start` at once all succeed — the lock is the thing that serialises them.

Actual: a thread errors out with exit-7-shaped io_error instead of waiting. On Windows, `create_new` against a file that another process's Drop is mid-deleting returns ERROR_ACCESS_DENIED (the delete-pending state), not AlreadyExists — and `ProjectLock::acquire` only retries on AlreadyExists, so a normal release/acquire race surfaces as a filesystem failure. Any two agents writing to one project at the same moment can hit this; the test just rolls the dice faster.

## Resolution

**Root cause.** Windows reports a `create_new` against a delete-pending file as ACCESS_DENIED rather than AlreadyExists. `ProjectLock::acquire` (crates/agentmon-core/src/fsx.rs) treated PermissionDenied as fatal, so the ordinary race — one holder's Drop removing the lock while the next writer creates it — became an io_error.

**Fix.** PermissionDenied now takes the same wait-and-retry path as AlreadyExists, with the same deadline; a directory that is genuinely unwritable still fails at the deadline with the real error instead of instantly.

**Verified.** `cargo test --workspace` three consecutive full runs green (the failing test included); before the fix the concurrent test failed roughly one run in five on this machine.

## For humans

Running `cargo test --workspace`, the command that runs every test in the project, about one run in five on this machine ended with a permission error from Windows. The test that failed is `concurrent_writers_never_share_an_id_or_lose_an_event`: it starts eight writers at the same instant and checks that none of them takes another's number or drops an entry. One writer was refused outright instead of waiting its turn.

**They take turns by creating a file.** The turn belongs to whoever holds `.agentmon.lock`, a file whose presence means "someone is writing, wait". A writer asks to create it and refuses to overwrite. If it is already there, Windows says "already exists", and the code waits a moment and asks again. That was the only answer it treated as "wait"; anything else it treated as a real failure and gave up on the spot.

**Windows has a middle state we never handled.** When the writer holding the turn finishes, it deletes the file — and for a sliver of time the file is neither there nor gone, because Windows has accepted the delete and not finished it. Ask to create it in that sliver and Windows does not say "already exists". It says "access denied", the same words it uses for a folder you have no right to write in. The code heard the words for a locked door and stopped.

It is like a shop door in the moment between the closed sign coming down and the bolt being drawn: pull it then, and it feels exactly like a shop that never opens.

**"Access denied" now waits too.** It takes the same wait-and-ask-again path, with the same deadline. A folder that genuinely cannot be written to still fails, at the end of that deadline and with the real error, rather than at once.

**Three full runs of the suite passed end to end, the once-failing test included.** Both numbers — those three clean runs, and one failure in five runs before the fix — were measured on this one machine.

**Any two agents writing to one project at the same moment could hit this.** The test with its eight writers only rolls the dice faster. Two writers now wait for each other, which is the whole point of taking turns.
