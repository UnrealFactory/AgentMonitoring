## Report

WORK-0011 (`## How`, the paragraph justifying the self-scaling time axis) says:

> Both projects have to look right, and their histories are different shapes: relay is three
> weeks of ten agents, agent-monitoring is one working day of six.

**Relay has four agents.** Counted, not remembered — the union over every record type in
`vault/projects/relay/` is `nova, sable, patch, quill`:

* 4 distinct `agent:` values across all 12 work logs;
* 4 distinct `reporter` / `assignee` / `resolved_by` values across all 8 bugs;
* 4 distinct actors across all 85 lines of `events.jsonl`;
* the same four in `scenario/BRIEF.md`, which specifies the roster: "nova (backend), sable
  (frontend), patch (infra/CI), quill (docs/API design)";
* and `git show d0b7e69:vault/projects/relay/events.jsonl` — the commit that generated the
  project — already has exactly those four, so this is not drift: the number was never ten.

The string "ten agents" occurs once in the whole repository, in WORK-0011.md itself.

Worse, the source comment written in the same commit (`src/lib/dashboard.ts`, the Time
buckets block) said "relay is three weeks of five agents, this app's own history is one
working day of six" — a third number. The code and the record disagreed with each other and
both disagreed with the vault.

The other three figures in that sentence hold up, which is what makes the tenth so cheap:
relay's events run 2026-07-28 to 2026-08-18 (22 days, "three weeks"); agent-monitoring's ran
from 10:36 to 21:33 on 2026-08-18 when the line was written ("one working day"); and its
roster at that moment was six builder agents (p0-foundation, p1-cli, p1-polish, p2-work,
p3-bugs, p4-dashboard), plus `scenario-generator`, which wrote relay rather than this app.

Expected: every number in a record is a number somebody counted.

Actual: a decorative figure, contradicted on screen by the app's own dashboard — /p/relay
draws exactly four rows in its Agents card, in the very screen WORK-0011 is describing.

Found by the P6 comprehension critic, who reconstructed WORK-0011 from the rendered page and
carried "three weeks of ten agents" across as fact. The reconstruction was right; the record
was wrong. This product's whole promise is that the record is true, and this is the class of
error that spends that promise for nothing: the decision the sentence justifies (a
self-scaling bucket axis) is sound, and the roster size never entered the calculation at all.

**On the fix.** The vault is append-only and `agentmon work update` refuses a finished work
log on purpose ("a finished work log is a historical record"), so WORK-0011's line stays as
written. This bug is the correction: it `refs: WORK-0011`, so it appears on that work log's
page under **Referenced by** — a reader who arrives at the wrong sentence finds the right
number one line below it.

## Resolution

**The number is four.** relay's roster is `nova`, `sable`, `patch`, `quill` — that is the
whole team, in the brief, in every work log, in every bug, in all 85 events, and on the
Agents card of /p/relay.

**Root cause.** Nobody counted. The sentence was written to justify a design decision (the
time axis picks its own bucket from the span of the project), the decision only ever used the
*span*, and the roster size rode along as scene-setting. Scene-setting is not checked, which
is exactly why it is the cheapest place to lose a reader's trust in a record.

**Fix, in two places, neither of which edits history.**

1. `src/lib/dashboard.ts` — the Time buckets comment no longer carries a roster at all. It
   now says what the calculation actually uses ("relay spans three weeks, this app's own
   history about a day"), and a parenthesis records that the old comment said five, the work
   log said ten, and the vault says four, so the next reader of that block knows the number
   was wrong rather than re-deriving the confusion. A comment that states a fact the code
   does not use is a fact nothing can keep true.
2. This bug, which `refs: WORK-0011`. WORK-0011.md is unchanged: it is a finished work log,
   the vault is append-only, and `agentmon work update` refuses to append to a done record on
   purpose. The correction therefore lives where the reader will meet it — the **Referenced
   by** block on /p/agent-monitoring/work/WORK-0011 now carries this bug's title, which
   contains both the wrong claim and the right number.

**Verified.**

* Recount from the files, by union over every record type in `vault/projects/relay/`:
  4 distinct `agent:` in 12 work logs, 4 distinct reporter/assignee/resolved_by in 8 bugs,
  4 distinct actors in 85 events — `nova, quill, patch, sable`. Same four in
  `scenario/BRIEF.md` and in `git show d0b7e69:vault/projects/relay/events.jsonl` (the commit
  that generated the project), so the roster has been four since the day it existed.
* `grep -rn "ten agents"` over the repository: one hit, WORK-0011.md, and no other record
  repeats it.
* The screen: /p/relay's Agents card renders four rows.
* The cross-link renders — the work log page shows this bug under Referenced by, with its
  status pill, and the bug page shows WORK-0011 under References.

**Not done here.** WORK-0011's sentence is left standing. Rewriting a shipped record to make
it look like it was never wrong is the failure this product exists to prevent; the honest
form of a correction in an append-only vault is a new record that points at the old one.
