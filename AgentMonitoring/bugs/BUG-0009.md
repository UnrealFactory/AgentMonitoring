## Report

A path or test name inside inline code is one unbreakable word. When it is longer than the
column, it leaves the card that holds it — and the card is `overflow: hidden`, so the tail
is cut with nothing to tell the reader anything was lost.

Found by the rebuilt `scripts/check-clipping.mjs` on its first walk of every record, which
is also the point: the record it happens on is relay's BUG-0001, which no previous run of
that script had ever opened.

Reproduce:

1. `npm run dev`, open `/p/relay/bugs/BUG-0001` in a 1152px-wide window.
2. Read the Resolution, second paragraph. It names the regression test:
   `relay-api/tests/deliveries_list.rs::lists_deliveries_with_an_in_flight_attempt`.
3. The last characters are missing. There is no ellipsis and no scrollbar: the card's edge
   simply arrives in the middle of the word.

    node scripts/check-clipping.mjs --widths 1152
    CLIPPED 1152  /p/relay/bugs/BUG-0001  div.outcome-card cuts code by 13.4px
                  — "relay-api/tests/deliveries_list.rs::lists_deliveries_with_an"

Expected: the token wraps. A test name broken across two lines is still readable and still
copyable; a test name missing its last eleven characters is neither, and on a page whose
whole job is to reproduce a record faithfully that is a correctness bug rather than a
cosmetic one.

Actual: `.prose code` sets no `overflow-wrap`, so the default `normal` keeps the token
whole, it overflows the prose column, and `.outcome-card` (and `.update-card`, in a comment)
cuts it.

Careful with the fix: the same rule must not reach *code blocks*. Wrapping a line inside a
`<pre>` changes what the code says, and those already scroll (`.prose pre` is
`overflow-x: auto`), so they need the default behaviour back.

## Resolution

**Root cause.** `.prose code` inherited `overflow-wrap: normal`, so a token with no spaces in
it — `relay-api/tests/deliveries_list.rs::lists_deliveries_with_an_in_flight_attempt` — is one
unbreakable word. It overflowed the prose column, and the card around it
(`.outcome-card`, or `.update-card` when the path is in a comment) is `overflow: hidden`, so
the tail was cut mid-glyph with no ellipsis and nothing to scroll.

**Fix**, two rules in `src/styles/app.css`:

- `.prose code { overflow-wrap: anywhere }` — these records are full of paths, test names and
  identifiers, and a wrapped one loses nothing;
- `.prose pre code { overflow-wrap: normal }` — inside a block, a line break would be a change
  to the code itself, so blocks keep the default and scroll instead (`.prose pre` is already
  `overflow-x: auto`).

**Verified.** `npm run check:clipping` at 1152px on `/p/relay/bugs/BUG-0001`, which reported
`div.outcome-card cuts code by 13.4px` before the change, is clean after it; the full walk —
21 records, both projects, five widths, 215 screen loads — reports nothing cut anywhere. The
test name is now readable and selectable across two lines.

The same walk taught the checker one more thing while this was being fixed: a `<pre>` that
scrolls its own content is not a clip, so the code blocks inside a card are no longer
reported. It clamps a descendant's ink to any scrollable box between it and the clipping
ancestor, which is what the reader actually sees.

## For humans

In a window 1152 pixels wide, one bug page named the test that guards its fix, and the last eleven characters were missing. No dots, no scrollbar: the card's edge simply arrives in the middle of the word. That page was relay's `BUG-0001`, a bug record in the other project this app tracked, and the name is `relay-api/tests/deliveries_list.rs::lists_deliveries_with_an_in_flight_attempt` — a file, and the test inside it, written as one word with no spaces. A missing tail can be neither read nor copied.

**The checker found it on a page it had never opened.** `npm run check:clipping` loads every record page at a set of window widths and reports any text a box has cut off — the loss where a reader never learns a word went missing. I had just rebuilt it to walk every record, and this came out of the first walk.

**A word with nowhere to break runs off the page.** Text wraps at spaces and this name has none, so it stayed one piece and overflowed its column. The card around it trims whatever sticks out, and the tail went.

It is like a long name on a narrow label: with nowhere to hyphenate, the end runs off the sticker.

**Names in a sentence may break anywhere now; blocks of code may not.** The rule on them is `overflow-wrap: anywhere`, which lets a word break between any two letters, and these records are full of paths and test names, where a break loses nothing. Inside a block of code a break would change what the code says, so blocks keep the old behaviour and slide sideways instead.

**The same fault was hiding one component over.** A reviewer had named 1104 and 1056 pixels as where a separate overlap starts, and neither was on the checker's list. Widening it to seven widths and 329 page loads turned up another row: on `WORK-0001`, a work record of this project's own, a long title had pushed the timestamp, "8h ago", off its card. A floor holding that title to about 24 characters had moved the damage onto the one column with no dots to fall back on. The title may shorten now, and the date survives.

**A grey label was sitting on the code it names.** The same wider run turned up a third one, on this project's own `BUG-0001` — a different record that happens to carry the same number as relay's. A block of code that says which language it holds carries that word over its own first line, in grey: RUST, there. The first line of the code was reading underneath it, the two sharing 12.7 pixels. Blocks with that label now start 24 pixels lower, so the label gets a band to itself and the code begins below it.

**The page that reported 13.4 pixels cut is clean afterwards.** The full walk — 21 records across both projects at five widths, 215 page loads — reports nothing cut anywhere. The test name reads across two lines and can still be copied. The checker also stopped reporting a loss that was not one: a block of code that slides sideways inside its own bar has not lost anything, so blocks sitting in a card no longer come up. It still only looks at the widths on its list, which is how the second one hid.

If a box cannot fit a word, it should break it, not eat it.
