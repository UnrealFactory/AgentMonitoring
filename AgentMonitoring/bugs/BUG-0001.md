## Report

`cargo build --workspace` fails in `agentmon-core`. `Vault::status` builds the per-agent
rollup for the dashboard with a closure that appends to `agents` and returns the index of
the row, then the loop body indexes `agents` with it.

Repro:

```
cargo build --workspace
```

Expected: the workspace builds.

Actual: 8 errors, `E0499` and `E0502`, all pointing at the same closure:

```
error[E0499]: cannot borrow `agents` as mutable more than once at a time
   --> crates\agentmon-core\src\vault.rs:383:43
    |
365 |         let mut push = |name: &str| -> usize {
    |                        --------------------- first mutable borrow occurs here
...
392 |             let i = push(&b.meta.reporter);
    |                     ---- first borrow later used here
399 |                 agents[i].bugs_resolved += 1;
    |                 ^^^^^^ second mutable borrow occurs here
```

The closure captures `agents` mutably for its whole lifetime, so every later use of the
vector inside the same scope is a second borrow. Nothing to do with the logic — the
rollup itself is correct — but the workspace does not build, which blocks everything
downstream.

## Comments

### 2026-08-18T10:49:00Z — p0-foundation-builder

Two options: collect into a `HashMap<String, AgentActivity>` and sort at the end, or lift
the closure to a free function that takes `&mut Vec<AgentActivity>`. Going with the free
function: the vector keeps insertion order, the sort at the end stays explicit, and the
rollup is small enough that a linear `position()` lookup is cheaper than hashing.

## Resolution

Replaced the capturing closure with a free function:

```rust
fn agent_slot(agents: &mut Vec<AgentActivity>, name: &str) -> usize {
    if let Some(i) = agents.iter().position(|a| a.agent == name) {
        return i;
    }
    agents.push(AgentActivity { agent: name.to_string(), ..Default::default() });
    agents.len() - 1
}
```

Each call now borrows `agents` only for the duration of the call, so the loop body is free
to index it afterwards. Call sites became `agent_slot(&mut agents, &w.meta.agent)`.

Why it works: the borrow ends when the function returns, instead of living as long as the
closure value did.

Verified with `cargo build --workspace` — clean, 542 crates, both binaries produced — and
`cargo test -p agentmon-core`, which exercises `status()` through the test that parses this
repo's own vault.

## For humans

The project would not build. `cargo build --workspace`, the single command that turns all of this project's source into runnable programs, stopped with 8 errors instead of finishing. Every one of them pointed at the same handful of lines.

**The counting those lines do was never wrong.** They build the dashboard's per-agent summary: one row for each agent, tallying things like the bugs that agent resolved. The sums were right; the program simply would not be built.

**One small helper kept its hold on the list.** The tally was written with an unnamed helper tucked inside the surrounding code, whose job was to add a row to the list of agents and hand back where that row landed. Rust, the language this part is written in, lets only one piece of code at a time hold a changeable grip on a list. That helper held its grip for as long as it existed, not merely while it was adding a row. Every later line that touched the same list therefore counted as a second grip, and the language said no.

It is like a library book. While one person has it out nobody else can, and this borrower kept it out all afternoon rather than for the ten minutes they were reading it.

**I gave the helper a name and lifted it out.** It is now `agent_slot`, an ordinary named function that is handed the list, does its bit and gives it straight back, so the grip ends when the call ends. I weighed keeping the tally in a lookup table and sorting it at the end, then dropped that: the list is short, and keeping the order the rows were built in is plainer.

**The build is clean.** That same command now finishes with no errors, 542 packages built and both programs produced. `cargo test -p agentmon-core`, the automatic checks over the shared code both programs sit on, passes as well, and one of them runs this very tally against this project's own real records. Nothing a reader sees on the dashboard changed; what changed is that there is something to run.

Code that is correct and will not compile is still code nobody can run.
