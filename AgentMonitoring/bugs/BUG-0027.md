## Report

Reported through app feedback (FB-0001 on the RookissAi-WorkSpace machine): one project is worked on from two PCs (C:\Weed and E:), records synced through git. Both sessions ran agentmon independently on 2026-08-22 and each allocated BUG-0006, BUG-0007, WORK-0011..WORK-0014 for completely different work. When the second PC fetched, git pull refused (untracked files would be overwritten) and the events.jsonl history referenced the same ids with two meanings.

Repro:

1. Clone the same repo on two machines, both with agentmon pointing at AgentMonitoring/.
2. On machine A, log_work -> WORK-0011. On machine B (without pulling), log_work -> also WORK-0011.
3. Push from A, pull on B -> path collision on worklogs/WORK-0011.md, and events.jsonl conflicts.

Expected: ids that cannot collide across machines, or at least a tool to renumber a record and rewrite its refs/events.

Actual: the sequential counter derives from local state only, so two machines allocating offline must collide. Recovery had to be done by re-creating six records through log_work/report_bug with the original timestamps and hand-editing events.jsonl (see WORK-0018 in that project). Compounding it, `work update` rejects a note whose --at precedes the log's close time, so an in-progress note from the original record could not be replayed at its real time.

## Resolution

Shipped in WORK-0079, verified independently by this critic against the exact reported accident. The id scheme is unchanged, per the owner's direction; the repair is `agentmon reconcile --theirs <incoming copy> [--apply]` plus a sanctioned `--replayed` flag on `work update` and `bug comment`.

What shipped: reconcile compares the local project against the incoming copy (a git worktree of the fetched branch), re-keys the LOCAL, unpushed record where one id holds different content on the two sides, and rewrites everything pointing at it in the same move — file rename, frontmatter id, refs: entries, bare prose mentions by the app's linkify grammar (`[[note-names]]` never), and events.jsonl ref fields and summary mentions. Dry run by default with the full plan and mapping; `--apply` executes it, logs one project_updated event carrying the mapping, and installs `events.jsonl merge=union` in the project's .gitattributes. The compounding defect is fixed by `--replayed` (requires --at and --message): the ceilings are waived for reconstruction only, the started/created floor and the future rule stay, the entry is inserted in timeline order, and the event summary opens `Replayed:`.

Verified end to end in a sandbox (temp dirs, AGENTMON_REGISTRY_DIR): a bare origin and two clones both allocated WORK-0011 and BUG-0006 for different work, with an in-progress note on the unpushed side; `git pull` refused exactly as reported. Running docs/AGENT_MANUAL.md Recipe 5 verbatim re-keyed WORK-0011→WORK-0012 and BUG-0006→BUG-0007 with zero stale pointers (word-boundary grep across the re-keyed records), refs lists and prose and events consistent, the pull then merging clean (events.jsonl by union) and `doctor --strict` exit 0 on the merged folder; the re-keyed record's human area byte-identical in `work view --json`. Also verified: dry run byte-identical sweep; second `--apply` a no-op; chained collision (naive target occupied by a local-only record) skipped correctly to ids free on both sides; identical ids skipped with the reason and refused under `--only` (exit 5); diverged same-identity records left to git; `[[work-0011-recovery]]` untouched; an id inside a code fence rewritten (the documented choice); replay succeeding at a time before the close, refused without the flag (exit 2), refused without --at, before started, and in the future; `work start` without --human still refused. Gates: cargo test --workspace 190 passed, release build clean, check:humanstyle clean, markdown-smoke 942 checks, doctor --strict clean on this project. check:mcp is 201/202 — the one red is the pre-existing contract-size budget tracked as BUG-0028 (verified inherited: budget set at 07b3f9c when the doc was 22,213 chars, over budget since ae6383e), not this work.

## For humans

The accident that cost an afternoon of hand-rebuilding now has a one-command repair, and the reviewer proved it by staging the whole accident again on purpose. Two copies of a project handed out the same record numbers, the sync refused exactly as this report describes, one command renumbered the unshared side and fixed every mention of the old numbers in the same move, and the sync then went through with the project's health check finding nothing wrong. The note that could never be put back at its real time now can be, through a switch that only exists for reconstruction and stamps the history line with the word Replayed so a copy can never pass for an original. The numbering scheme itself did not change - the records everyone already links to keep their names.
