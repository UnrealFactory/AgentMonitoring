## Report

Found while reading `progress/shots/work-list.png` against the reference shots. The
excerpt column shows the first paragraph of `## What` as literal markdown source:

```
Stood up the repository skeleton described in SPEC.md and made the vault format real in
code: a Cargo workspace with three members (`src-tauri`, `crates/agentmon-core`,…
```

Repro:

1. `npm run screenshot`
2. Open `progress/shots/work-list.png`, or `curl http://localhost:5173/vault-api/projects/agent-monitoring/worklogs`.

Expected: a one-line preview reading as prose — backticks, `**bold**` markers and link
syntax are formatting instructions, not content.

Actual: every markdown marker in the first paragraph is printed verbatim. It shows up in
three places that all share `excerpt()`: the work table, the bug list and any future
preview built on the summary DTOs.

The excerpt is also the one string in the record that is *not* rendered by
`src/lib/markdown.tsx` — the detail pages parse the body, but list rows print a plain
string, so nothing downstream strips the markers. Fixing it in the renderer would be the
wrong layer: both readers (agentmon-core and scripts/vault-fs.mjs) already produce the
excerpt, and they must keep producing the same bytes.

Not urgent — nothing is wrong, unreadable or lost — but it is the first thing a critic
comparing the work list against a GitHub issue list will see.

## Comments

### 2026-08-18T11:14:00Z — p0-foundation-builder

Careful with the strip rules. The obvious "delete `*` and `_`" mangles the identifiers
these records are full of: `resolved_by`, `&mut Vec<AgentActivity>`, `*ptr`. Bold in
agent-written bodies is always `**`, never `__`, so the safe set is: drop backticks, drop
`**` pairs, rewrite `[label](href)` to `label`, and leave single `*` and `_` alone. One
stray asterisk is a much smaller cost than a corrupted identifier.

## Resolution

Added `strip_inline()` to `crates/agentmon-core/src/body.rs` and its twin `stripInline()`
to `scripts/vault-fs.mjs`, applied inside `excerpt()` before the whitespace collapse (so
markers that leave a gap behind do not leave a double space).

The rules are the conservative set from the comment above: backticks removed, `**`
removed, `[label](href)` reduced to `label` (backticks inside the label removed too),
single `*`/`_` untouched. The Rust version scans characters instead of using a regex —
`agentmon-core` has no regex dependency and should not grow one for this.

Verified:

- `cargo test -p agentmon-core` — 10 passing, including a new
  `excerpt_drops_inline_markdown_but_keeps_identifiers` case that asserts `resolved_by`
  and `&mut *ptr` survive intact.
- Byte-parity between the two implementations, which is the property that actually
  matters here, checked on the real vault:
  `agentmon work list -p agent-monitoring --json` against the Node reader's
  `listWorklogs`/`listBugs` — all four records produce identical excerpt strings.
- Re-shot `progress/shots/work-list.png`: the preview now reads "…a Cargo workspace with
  three members (src-tauri, crates/agentmon-core,…".

## For humans

Every row of the work list carries a one-line taste of what that record says. Those tastes were coming out with the writer's formatting marks still in them. They kept the back-quotes that go around a file name, the doubled stars meaning "print this in bold", and the brackets of a link. I noticed it in `progress/shots/work-list.png`, a screenshot of that list. Nothing was lost and nothing was wrong; it simply read like something half-typed.

It is like a recipe card that prints the words "underline this" instead of underlining.

**That one line is the only part of a record nobody tidies.** The step that makes it is `excerpt()`. Open a record in full and the app reads the marks and does what they say. A list row just prints the stored line as it stands, so whatever is in it goes to the screen.

**So I cut the marks out inside `excerpt()` itself.** That line is made twice over: `strip_inline()` trims it for the desktop app, and its twin `stripInline()` trims it for the browser version. The same narrow rule went into both.

**The obvious version of this would have wrecked the words it was cleaning.** "Delete every star and underscore" is the one-line fix, and these records are full of names built from them. The field `resolved_by`, which says who closed a bug, would come out as "resolvedby". So the rule is deliberately narrow. Back-quotes go, doubled stars go, a link keeps its words and loses its address, and a lone star or underscore is left where it sits.

One stray star on a page costs far less than a name that no longer says what it said.

**I checked the wrecking case on purpose.** `cargo test -p agentmon-core`, the automatic checks over the shared code both versions sit on, passes all 10. One of them is new: `excerpt_drops_inline_markdown_but_keeps_identifiers`. It feeds in text holding that field name, and `&mut *ptr`, a scrap of code with a lone star in it. It fails if either comes out changed.

**I ran both readers over this project's real records too**, and compared their lines letter by letter, and all four came out identical. Then I took the screenshot again, and the row reads as a plain sentence.

Two programs now have to agree on what that line looks like, and only a comparison someone runs says whether they still do.

A formatting mark the reader can see has stopped being formatting.
