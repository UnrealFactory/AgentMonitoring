## Report

The status strip on the bug record — Filed → Claimed → Resolved — overflows its card in a
narrow window and paints its stops on top of each other. Nothing is cut, so nothing looks
broken in a thumbnail: two facts are simply drawn in the same pixels, and the reader gets
a word that does not exist.

Found by the round-2 design critic on this project's own board, then measured here with
`node scripts/tmp-strip-probe.mjs` (element rects inside `.status-strip`).

Reproduce:

1. `npm run dev`, open `/p/agent-monitoring/bugs/BUG-0003` — an agent named
   `p0-foundation-builder` filed, claimed and resolved it, so all three stops carry a long
   name and a full timestamp.
2. Resize the window from 1600px down.

Measured on that record (viewport → what leaves the card, what shares pixels):

    1600   clean
    1280   clean
    1056   "Resolved" leaves the card by 13px; "3m" and "Claimed" share 10px
    1024   leaves by 29px; the claimed timestamp and the resolved actor share 4px
     960   leaves by 61px; "18 Aug 2026, 11:13" is drawn across
           "p0-foundation-builder" for 36px

960px is not a hypothetical width: it is this app's own `minWidth` in
`src-tauri/tauri.conf.json`, so it is a size a user can actually put the window at.

Expected: the strip stays inside its card at every width the window can be, and no two
pieces of text ever occupy the same pixels — truncate, stack or drop something, but never
overprint.

Actual: at 960px the third stop is outside the card and the second stop's date is written
over the third stop's agent name.

Cause, from `src/styles/app.css`:

- `.strip-step:not(:first-child) { flex: 1 }` is `flex: 1 1 0%` — those steps have a
  flex-basis of 0, so when the row runs out of room they collapse toward nothing;
- `.strip-node { flex: none }` with `white-space: nowrap` on `.strip-meta` cannot shrink,
  so the node overflows the step that is supposed to contain it;
- `.status-strip` is `overflow: visible`, so the overflow is not clipped — it is painted
  over the neighbour.

That last point is why this was invisible to `scripts/check-clipping.mjs`: a clipping test
looks for ink that a box cut off, and this box cut nothing.

## Resolution

**Root cause.** The strip was a flex row that could not shrink. `.strip-step:not(:first-child)`
was `flex: 1`, which is `flex: 1 1 0%` — a zero basis, so under pressure those steps collapse
toward nothing instead of giving up width in proportion to what they carry. Inside them,
`.strip-node` was `flex: none` around `.strip-meta { white-space: nowrap }`, so the node kept
its full width whatever the step did and simply hung out of it. `.status-strip` is
`overflow: visible`, so nothing was clipped: the escaping text was painted over the next
stop's text.

**Fix**, all in `src/styles/app.css` plus one attribute in `src/pages/BugDetailPage.tsx`:

- steps shrink proportionally — `flex: 0 1 auto` on every step, `flex: 1 1 auto` on the ones
  that also carry a connector, so an `auto` basis makes the three stops give up width
  together rather than two of them collapsing;
- `.strip-node` is `flex: 0 1 auto; min-width: 0`, so whatever the step is given, the node
  lives inside it — the overflow cannot happen in the first place;
- `.strip-label` and `.strip-who` truncate with a real ellipsis, and `.strip-meta time` is
  `flex: none`: when something has to go, it is a few letters of the agent's name (which is
  in the byline, the sidebar and now a `title` tooltip) and never the date, which is the one
  fact on the strip a reader cannot reconstruct;
- below 1260px the name and the date stack instead of sharing a line, so at 960px both are
  shown in full rather than either being cut. Vertical space is the cheaper currency here.

**Verified.** `node scripts/tmp-strip-probe.mjs` re-measured BUG-0003 at 1600 / 1280 / 1104 /
1056 / 1024 / 960: no element leaves the card and no two elements share a pixel at any of
them, and at every width from 1260 down both the full name (`p0-foundation-builder`, 115px)
and the full timestamp are on screen. The same run before the fix reported 61px outside the
card and 36px of overprint at 960.

The permanent check is `npm run check:clipping`, rebuilt in the same round: it walks all 21
records of both projects at five widths and reports ink painted over ink as well as ink cut
off — 215 screen loads, clean. Reverting these four declarations turns it red again with 20
`OVERLAP` lines, including
`time.tabular over span.strip-who by 36.4px — "18 Aug 2026, 10:48" / "p0-foundation-builder"`,
so the gate now fails on this defect rather than sleeping through it.

**Cost.** The strip is one line taller below 1260px, and an agent name longer than about
180px will now end in an ellipsis with the full name in its tooltip.
