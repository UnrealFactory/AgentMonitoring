## Report

재현: AgentMonitoring 개발 앱을 켜 둔 채 프로젝트·폴더 기능의 소스 패치를 반영합니다. 기대: 변경 사항이 화면에 적용되거나 자동으로 정상 재로딩되어 앱을 계속 사용할 수 있어야 합니다. 실제: 사용자 첨부 화면처럼 앱 전체가 검은 배경만 남으며, 사용자는 개발 앱 재부팅으로 복구하고 있습니다. 원인은 아직 확인하지 않았습니다. WORK-0116에서 실제 갱신 오류를 수집하고 수정합니다.

## Comments

### 2026-09-08T11:12:29Z — codex

실제 실행 파일을 WebView2 CDP로 연결한 뒤 ko.ts/en.ts에 주석을 동시에 추가해 재현했습니다. 정상 렌더링된 #root 내용 36,745자가 패치 후 0자가 되었고, useWindowTitle → useApp에서 'useApp must be used inside <AppProvider>'가 발생했습니다. 스택의 App.tsx와 AppContext.tsx는 서로 다른 HMR 시각으로 교체되어 있습니다. 공유 컨텍스트 객체가 모듈 교체마다 새로 만들어져 제공자와 소비자가 서로 다른 컨텍스트를 참조하는 문제를 수정하겠습니다.

### 2026-09-08T11:20:20Z — codex

다섯 React 컨텍스트를 stableContext로 생성하도록 바꿨습니다. 개발 모드에서는 Vite hot.data에 컨텍스트 객체를 보관하므로 제공자와 소비자의 모듈이 다른 갱신 묶음으로 교체되어도 같은 객체를 참조합니다. 빌드된 앱에서는 기존 createContext 동작을 유지합니다.

## Resolution

실제 WebView2에서 번역·공유 모듈을 세 차례 변경하고 복원하는 총 6회 갱신 동안 화면 문구 변경, 오류 0건, 재로딩 없음, 작성 중 폴더 이름 유지를 확인했습니다. check:hmr 자동 검사도 6회 통과하고, --without-fix 대조 실행은 첫 패치에서 같은 useApp 오류로 실패했습니다. npm run build와 check:project-folders 22개, git diff --check가 통과했습니다. 진단 실행을 종료하고 5175 일반 tauri dev로 다시 실행했습니다.

## For humans

검은 화면을 만들던 코드 교체 중 공유 상태 연결 끊김을 수정했습니다. 실제 앱에서 화면을 다시 켜지 않고 코드를 바꾸고 되돌리는 검사를 여섯 번 통과했으며, 작성 중인 입력도 유지됐습니다. 일반 개발 앱으로 다시 실행해 두었습니다.
