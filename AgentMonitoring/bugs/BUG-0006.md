## Report

The dashboard's Agents table is wider than the card that holds it, and the card has
`overflow: hidden`, so the right-hand columns are cut off with nothing to scroll and no
ellipsis. At 1600px the "Last seen" header loses its final glyph and every "4h ago" under it
is sliced; below 1300px whole columns vanish.

Measured with `node scripts/check-clipping.mjs --port <p>` (walks every screen at
1600/1440/1280/1152/960 and reports any element whose ink leaves a clipping ancestor):

    1600  /p/agent-monitoring   section.card cuts th        by   6.4px — "Last seen"
    1280  /p/agent-monitoring   div.app      cuts td.muted  by  69.4px — "30m ago"
    1152  /p/agent-monitoring   section.card cuts th        by 166.4px — "Last seen"
    1152  /p/agent-monitoring   section.card cuts th.num    by  78.6px — "Bugs fixed"
    1152  /p/relay              section.card cuts th        by  34.9px — "Last seen"

Reproduce:

1. `npm run dev`, open `/p/agent-monitoring` (its agent names are the long ones:
   `p0-foundation-builder`, `scenario-generator`).
2. Look at the right edge of the Agents card: "LAST SEEN" ends flush against the border with
   its N clipped, and the relative times under it have no right padding.
3. Narrow the window to 1152px. "Bugs fixed" and "Last seen" are gone — the numbers are
   still rendered, just outside the card, and the reader has no way to know a column exists.

Expected: the table fits the card at every width the app supports — the agent name column
gives ground first (it is the one with an ellipsis and a tooltip), or the card scrolls
horizontally and says so. A number a reader cannot see is worse than a number that is not
there, because the layout still promises it is complete.

Actual: the widest content wins and the card silently amputates whatever does not fit.

This is the same class of defect as BUG-0004 on the bug board (a fixed box with
`overflow: hidden` around content that does not fit, cutting mid-glyph rather than
ellipsising) — the dashboard is the other place in the app where it survived.

Severity medium: nothing is lost from the vault and the numbers on the left are correct, but
a dashboard whose columns disappear without a trace is exactly the screen where a reader
cannot tell absence from truncation. Filed rather than fixed because the dashboard is P4's
piece and it is being iterated on; the fix that worked on the bug rows was to make the cell
a flex container with `min-width: 0` down to the text and let the name ellipsise, plus
sizing the name column from the project's own agent names (`src/lib/columns.ts`).

## Resolution

**Root cause.** The Agents card held an HTML `<table>`. A table lays itself out from its
content: each column takes what its widest cell wants, the table becomes as wide as the sum
of those, and no amount of room-shortage makes it give any of it back. The card around it is
`.card { overflow: hidden }`, so once the table exceeded the card the card guillotined
whatever stuck out — with no ellipsis, because nothing inside the table ever learned it did
not fit. `text-overflow` cannot fire on an element that fits its own box; it is the ancestor
that is too small. This is the same shape of defect as BUG-0004 on the bug board, and the
report said so.

**Fix, in `src/pages/DashboardPage.tsx` and `src/styles/app.css`.** The table is gone. The
Agents card is now a header row and a list of rows sharing one CSS grid:

    grid-template-columns:
      minmax(0, var(--agent-col))   /* agent name  */
      minmax(56px, 1fr)             /* activity bar */
      46px 46px 46px                /* done · filed · fixed */
      78px                          /* last seen  */

Three things do the work. `minmax(0, …)` on the name track lets it shrink below its ideal
width instead of pushing the row past the card, and `.agent-cell-name { min-width: 0;
overflow: hidden }` carries that all the way down to `.agent-name`, which is the one element
in the row with `text-overflow: ellipsis` and a tooltip holding the full name — so the name
is what gives ground, visibly, and a number never is. The ideal width itself comes from the
project's own agent names through `agentColumnWidth` (`src/lib/columns.ts`, `chrome: 40` for
the status dot, the avatar and the two gaps), so `nova` and `p0-foundation-builder` each get
a column that fits them. And the numeric columns are fixed and few: three counts and a
relative time, sized with room for their headings, so "Last seen" cannot lose its N again.

The row is also now a link to that agent's records, and carries a work/bugs split bar — but
the bar is decoration over the numbers, never instead of them: every value the bar encodes
is printed as text in the same row.

**Verified.** `node scripts/check-clipping.mjs`, with the dashboard exclusion removed from
the script in the same change — 50 screens (41 records across both projects) at
1600/1440/1280/1152/1104/1024/960, 350 screen loads: *"clean: nothing is cut without an
ellipsis, nothing is painted over anything"*. Every width the report named is in that set,
including the two it measured, 1600 (`th` cut by 6.4px) and 1152 (`th` cut by 166.4px,
`th.num` by 78.6px).

A gate that reports nothing is worth nothing unless it can still report something, so the
probe was checked against this screen rather than assumed: with the agent grid forced to
`300px` per column in the page, the same measurement reports

    app cuts "Done" by 249.0px
    app cuts "Filed" by 561.0px
    app cuts "Fixed" by 873.0px
    app cuts "Last seen" by 1185.0px

and with the shipped grid it reports nothing. The gate is live on the dashboard, and the
dashboard passes it on its own merits.

**Consequence.** `--include-dashboard` is gone from `scripts/check-clipping.mjs`, along with
the `gate: false` machinery that let a screen be walked without being judged. Every screen
this script visits now counts. A gate with a hole in it says nothing about the hole.
