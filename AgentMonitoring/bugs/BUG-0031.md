## Report

재현: node scripts/check-i18n.mjs --locale ko --port 5240 --ko-port 5244를 실행하면 mcp-client-registration 노트의 1600px 에이전트 화면에서 '입니다'가 두 줄로 나뉘었다고 실패합니다. 기대: 여러 줄로 표시된 인라인 코드는 검사에서 제외하고 그 뒤 한 줄로 표시된 한국어는 통과해야 합니다. 실제: BREAK_PROBE의 locate가 평탄화된 문자열의 시작 경계에서 이전 텍스트 노드 끝을 선택하여, 검사 제외된 코드까지 DOM Range에 포함합니다. 실제 화면 캡처에서는 '입니다'가 한 줄이며 앞 코드만 줄바꿈합니다.

## Comments

### 2026-09-08T12:24:36Z — codex

WORK-0119 배포 검증 중 발견했습니다. BREAK_PROBE.locate가 시작 offset과 이전 노드 끝 offset이 같을 때 이전 노드를 선택한 것이 원인입니다. 시작은 다음 포함 텍스트 노드, 끝은 이전 노드를 선택하도록 경계 규칙을 분리했습니다.

## Resolution

scripts/check-i18n.mjs의 단어 시작/끝 경계만 수정했습니다. 실제 1600px 노트 캡처에서 '입니다'가 한 줄임을 확인했습니다. Playwright로 구 코드에서 오탐이 발생함을 재현했고, 수정 코드에서 앞/뒤 다중 줄 인라인 코드 제외와 텍스트 노드 내부/인라인 요소 사이의 실제 한국어 잘림 감지 4개 검사가 통과했습니다. 앱 소스와 표시 내용은 변경하지 않았습니다. 전체 한국어 화면 검사는 WORK-0119에서 이어 확인합니다.

## For humans

한국어 단어를 측정할 때 바로 앞 코드가 섞이지 않도록 검사 경계를 수정했습니다. 수정 전의 오탐을 재현했고, 수정 뒤에는 정상 단어를 통과시키면서 실제 두 종류의 단어 잘림은 계속 감지했습니다. 앱 화면을 바꿀 필요는 없었습니다.
