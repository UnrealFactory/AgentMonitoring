## Report

Repro:

1. Open the work list of a project with zero work logs (a fresh `agentmon init`).
2. Read the empty state's command line.

Expected: a command the v2 CLI accepts, e.g. `agentmon work start --agent <name> --title "<title>" --body "…"` (v2 resolves the project from the directory, like git).

Actual: `agentmon work start -p <projectId> --agent <name> --title <title>` — `-p` is the v1 project flag. The v2 CLI rejects it at parse time (there is even a test, `there_is_no_project_flag_left_to_type`), so an agent or human copying the app's own hint gets exit 2.

Found in src/pages/WorkListPage.tsx while building the notes list's empty state from the same template.

## Resolution

**Root cause.** The empty-state hint in src/pages/WorkListPage.tsx was written in the v1 era, when every command addressed a project with `-p <slug>`. The v2 rearchitecture (WORK-0035) removed the flag from the CLI and swept the docs, but this one string — agent-facing advice inside the app — was missed.

**Fix.** The hint now prints `agentmon work start --agent <name> --title "<title>" --body "…"`, with a comment beside it saying why there is no project flag. The new notes list's empty state was written against the v2 syntax from the start.

**Verified.** `npx tsc --noEmit` clean; the CLI's own test `there_is_no_project_flag_left_to_type` still proves `-p` does not parse, which is what made the old hint wrong.

## For humans

Open the work list of a project that has nothing logged yet and the app shows an empty page with a suggested command on it — the line you copy into a terminal to record your first piece of work. That line was out of date. It still carried `-p`, the flag that used to say which project you meant, from an older version of the tool.

The tool stopped taking that flag. It now works out the project from the folder you are standing in, the way `git` does. So the command is refused before it starts, and nothing is written down. That hint is advice aimed at the agents working inside the app, and an agent copying the app's own words got an error for its trouble.

I found it while building the same kind of empty page for the new list of notes from the same template. The line now shows the current form — your name, a title, a body — with a comment beside it in the code saying why no project is named.

Two things back that up. The frontend's type checker, `npx tsc --noEmit`, which reads the screen code for mistakes before anybody runs it, comes back clean. And the tool's own test, named `there_is_no_project_flag_left_to_type`, still shows the old flag is refused outright — which is exactly what made the printed hint wrong.

Copy that line now and the tool takes it. A screen that teaches you a command is documentation, and it goes stale like documentation.
