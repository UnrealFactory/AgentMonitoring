## Report

Editing any frontend file while `npm run dev` / `npm run tauri:dev` is running changes nothing in the served app: no HMR, and even a full page reload gets the old code — vite serves the transform it cached when the server started, forever. Two sessions hit it as 'a stale leftover server on 5173' before the real cause surfaced: the server can be seconds old and still be stale for any file edited after it started.

Cause: vite.config.ts told chokidar to ignore `**/AgentMonitoring/**` so that data writes into the project folder would not trigger dev-server reloads. But this repo's own directory is *named* AgentMonitoring (C:/Code/AgentMonitoring), so the any-depth glob matches every path in the repository — src/, scripts/, vite.config.ts itself — and the watcher ignores the entire codebase. Invalidation never fires; module transforms are cached at first request and never refreshed. vite cannot even see changes to its own config file, so it never self-restarts either.

How found: WORK-0039's new hook (lib/useScrollRestoration.ts) verified as completely inert against a server started minutes earlier in the same session; `curl /src/App.tsx` showed the served module graph without the day's edits while the new file itself transformed fine on first request.

## Resolution

vite.config.ts anchors the data-folder ignore to the repo root: resolve(process.cwd(), 'AgentMonitoring') + '/**' (forward slashes for chokidar) instead of '**/AgentMonitoring/**', which also matched the repo directory itself and made the watcher ignore every source file. Verified live against a running tauri:dev server: appending 'export const __watchProbe = 1' to src/lib/useScrollRestoration.ts appeared in the served transform within 2s and disappeared after removal — invalidation works both ways with no restart. The intent of the original pattern is preserved: writes into the repo's own AgentMonitoring data folder still do not trigger dev-server reloads (the app keeps noticing them through /project-api/cursor polling).
