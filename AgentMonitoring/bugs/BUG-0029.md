## Report

check_app_update (src-tauri/src/update.rs, fetch_latest) GETs api.github.com/repos/.../releases/latest unauthenticated. That endpoint shares a 60-requests/hour per-IP quota; when it is exhausted GitHub answers 403, fetch_latest returns Err, and the sidebar card's contract is 'an Err means could not check and the card simply does not appear' — so the user sees nothing, indefinitely, with no hint.

Observed 2026-08-24 ~18:10 KST on the dev machine right after releasing v1.1.0: installed app 1.0.5, release live and public, no card after a restart. curl with the app's own headers reproduced HTTP 403 'API rate limit exceeded for 211.218.251.243', rate_limit core remaining 0 (the day's critic runs launched the real app dozens of times; each launch spends one check). Card returned after the hourly reset.

Expected: the check should not depend on the API quota, or the card should distinguish 'could not check' from 'up to date'. Cheapest fix: resolve the latest tag from the un-metered redirect — HEAD https://github.com/<repo>/releases/latest and read the Location header's tag — and keep the API call only for the release notes (or fetch notes lazily when the card is opened). Alternatives: ETag conditional requests, or surfacing a quiet 'update check unavailable' state after repeated failures.

## Resolution

Fixed in WORK-0084 by removing the API from the check's critical path entirely
(src-tauri/src/update.rs):

1. `latest_tag()` — HEAD `https://github.com/UnrealFactory/AgentMonitoring/releases/latest`
   with redirects disabled (`ureq::AgentBuilder::redirects(0)`); the newest tag is read out
   of the 302 `Location` header by `tag_from_location` (unit-tested, query/fragment/no-tag
   shapes covered). This redirect is not metered — the 60/hr API quota cannot touch it.
2. `find_installer()` — one un-metered HEAD on the conventional asset URL scripts/release.mjs
   uploads (`AgentMonitoring_<version>_x64-setup.exe` under the tag's download path):
   existence check plus `Content-Length` as the card's size. A release without the asset
   still yields None, same as before.
3. `release_notes()` — the one remaining API call, only made when a newer version actually
   exists, and best-effort: a 403 under the quota now costs an empty tooltip, never the card.

Verified live while resolving: the redirect answered `302 → …/releases/tag/v1.1.0`, and the
installer HEAD answered 200 with Content-Length 8096174. `cargo test` green, including the
two new update tests; the whole MCP suite (208 checks) also green.

## For humans

The app asks GitHub once in a while whether a newer version exists. GitHub answers that kind of anonymous question only 60 times an hour for a whole internet address; on the day version 1.1.0 shipped, the test launches spent all 60, and the app's rule for a failed check was to show nothing. So the owner restarted the app, saw no update offer, and had no clue why until the quota reset at the top of the hour.

**The asking now goes through a door GitHub does not meter.** GitHub keeps an address that always forwards to a project's newest release page, and following that forward costs nothing against the quota. The check reads the version out of the forward, then confirms the installer file exists with the same kind of free request — which also reports the file's size for the card. It is like reading the notice taped to a shop's door instead of phoning a switchboard that stops answering after 60 calls.

**Only the release notes still use the counted channel.** They fill a small tooltip on the card, and they are only fetched when a newer version really exists. If that one request is refused, the tooltip is blank — the card itself still appears.

**How I know:** I asked the free forwarding address for this app's releases by hand and it pointed at version 1.1.0 without spending quota; the installer's free check answered with the file's exact size; and the automated tests, including two new ones pinning how the forward is read, all passed.

A spent quota can now blank one tooltip, and nothing else — the update card can no longer be starved.
