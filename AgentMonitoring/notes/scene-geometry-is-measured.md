# 무엇을 그릴지 먼저 정하세요

2026-09-06 WORK-0108의 `docs/HUMAN_STYLE.md` v4가 현재 정책입니다. 문단마다 SVG나 세로 밴드를 만들던 규칙은 폐기했습니다. 실행 순서는 시간축, 관계는 연결·포함, 변경은 전후 비교, 화면은 실제 캡처 주석, 대안은 표, 성능은 측정 그래프를 사용합니다. 문장을 상자에 옮기는 것만으로 설명을 완성하지 않습니다.

관측한 결과, 코드에서 읽은 동작, 검토 중인 제안, 설명용 가정을 구별하세요. 그림의 화살표와 점선이 무엇을 의미하는지 밝히고 필요한 대기·해제·실패 상태도 보여주세요. 단순 진척 수치나 경로 변경은 그림이 필요하지 않을 수 있습니다.

# 저장과 표기

- 파일은 `AgentMonitoring/assets/`에 둡니다. 이름은 설명할 주제가 드러나게 짓습니다. 기존 record-beat 형태 이름도 지원합니다.
- 이미지 참조는 설명 가까이에 독립 문단으로 쓰고 앞뒤 빈 줄을 둡니다. raw HTML과 외부 이미지 URL은 사용하지 않습니다.
- SVG에는 어두운 배경과 양수 고정 width·height 및 viewBox를 넣습니다. percentage·0·글꼴 상대 root 크기는 검사에서 거부합니다. 시스템 글꼴은 기기별 폭이 다르므로 여유가 필요합니다.
- 뷰박스와 root 크기의 비율이 같다면 `min(395/viewBoxWidth, 560/viewBoxHeight) × 유효 글자 크기`를 적용합니다. 11px 이상을 유지하고 가장자리는 SVG 단위 14 이상 비웁니다. 비율이 다르면 실제 root viewport의 여백과 변환까지 계산해야 합니다.

# 검사 명령

```sh
# 기록을 쓰기 전에 아직 인용되지 않은 그림 하나를 검사합니다.
node scripts/check-scenes.mjs --dir C:/프로젝트/AgentMonitoring --asset readiness.svg
# 기록에서 인용한 전체 SVG와 기존 장면 이름 파일을 검사합니다.
node scripts/check-scenes.mjs --dir C:/프로젝트/AgentMonitoring
# 검사기 자체의 회귀 사례입니다.
npm run check:scene-tests
```

전체 검사는 실제 이미지 인용과 기존 장면 이름 파일을 읽습니다. 코드 펜스·인라인 코드의 표기 예시는 인용으로 보지 않습니다. 참조한 파일이 없거나 기존 장면 이름 파일이 어디에서도 참조되지 않으면 오류를 보고합니다. --asset은 새 그림을 먼저 검증할 수 있도록 해당 파일만 검사하며, 경로 이동이나 없는 파일을 허용하지 않습니다.

기본·넓은 서체로 텍스트 경계를 측정합니다. .s/.m 클래스뿐 아니라 상속·인라인 글꼴과 tspan도 검사합니다. 조상 이동·축소, root viewport/viewBox 비율, 0이 아닌 viewBox 원점을 반영합니다. 2026-09-06에 이 경우들의 회귀 검사가 추가됐습니다.

# 통과의 의미와 한계

검사기는 글자의 겹침·가장자리 침범·표시 크기를 확인합니다. 내용의 진실성, 화살표의 의미, 사람이 이해하는지는 판정하지 않습니다. 반드시 렌더링도 열어 보시고, 독자가 연결 조건이나 실행 순서를 설명할 수 있는지 별도로 확인하세요. `check-clipping`은 페이지 검사이므로 이미지 내부 검사와 다릅니다.

이 검사기는 AgentMonitoring 소스 저장소에 있습니다. 설치 앱만 사용하는 프로젝트에 검사 스크립트가 있다고 가정하지 마세요. 해당 환경에서는 실제 실행 가능한 도구로 측정하고, 수행하지 않은 검사를 통과했다고 기록하지 않습니다.

## For humans

그림은 설명 문장을 담는 상자보다, 어떤 대상이 언제 연결되고 무엇이 바뀌는지 보여주어야 합니다. 필요에 따라 시간축, 연결도, 전후 비교나 표를 선택합니다.

새 그림은 기록에 넣기 전에 검사할 수 있습니다. 검사기는 실제 표시 크기와 글꼴, 도형 이동·축소를 반영해 글자 배치를 확인합니다. 검사 통과만으로 설명이 이해하기 쉽다고 단정하지 않으며, 렌더링과 내용을 별도로 검토합니다.
