# 현재 작성 정책

2026-09-06 WORK-0108에서 `docs/HUMAN_STYLE.md`를 v4로 개정했습니다. 핵심 변화·작동 방식·근거와 한계를 설명하며, 짧은 진척이나 기억은 한두 문단으로 충분합니다. 다섯 단계 사건 서사, 비유, 마지막 교훈, 문단마다 SVG를 요구하던 v3 규칙은 폐기했습니다. 관계·순서·분기·해제·전후 변화가 핵심이면 그 구조를 보여주는 그림을 사용합니다.

이 변경과 EOF 수정은 2026-09-06 공개한 v1.5.2에 포함되어 있습니다(WORK-0110). 설치 앱을 업데이트하고 MCP 연결을 다시 연결해야 새 코드와 안내를 사용합니다. 이 기기의 설치 프로그램은 이번 배포 작업에서 실행하지 않았습니다.

# 저장·검사 책임

- `crates/agentmon-core/src/human.rs`가 split·attach·require·reject_reserved를 담당합니다. `write.rs`가 각 쓰기 동작에 필수 human 규칙을 적용합니다. CLI·MCP·앱은 코어 규칙을 공유합니다.
- 시작·완료·영구 중단, 버그 생성·해결, 노트 생성·본문 갱신, 앱 피드백 생성에는 human이 필요합니다. 작업 진척·버그 코멘트도 메시지를 넣으면 그 변경을 설명하는 human이 필요합니다. 내용 없는 반복 업데이트는 하지 않습니다.
- 작업·버그의 메시지와 human은 같은 시각의 항목으로 **덧붙입니다**. 종료도 결말을 덧붙입니다. human만 보내는 갱신은 **전체 human 교체**입니다. 교체에서 빠진 설명은 그 페이지에 보존되지 않으므로 의도적인 정리에만 사용합니다. 노트는 현재 지식이므로 본문을 갱신합니다.
- 도구 한 호출이 내부적으로 두 CLI 동작을 수행할 때 동일 human은 중복 추가하지 않습니다. 과거 시각의 replay 항목은 시각 순서에 삽입합니다. 날짜가 아닌 `###` 제목은 사용자 본문의 일부입니다.
- `## For humans`는 저장 형식의 예약 제목입니다. 작성자가 본문에 삽입하지 않습니다. human 필드 안의 `##` 헤딩도 거부됩니다. 짧은 문단·필요한 굵은 도입문·목록·표는 사용할 수 있습니다.

- WORK·BUG의 최종 저장 본문은 `body::render`에서 개행 하나로 끝납니다. FB-0002/WORK-0109에서 파일 끝 빈 줄 때문에 Git 공백 검사가 실패하던 문제를 수정했습니다. 내부 문단·표·코드 공백은 유지합니다. 새로 생성하거나 도구로 다시 저장하는 기록에 적용되며, 과거 파일을 일괄 변경하지 않습니다.

# 파서 변경 시 주의

제목·펜스·공백 인식은 `body.rs`의 정의를 따릅니다. Rust와 JavaScript의 trim 차이, BOM, 눈에 보이지 않는 문자, 비슷하게 보이는 다른 알파벳, 들여쓰기·탭으로 예약 제목 검사가 우회됐던 이력이 있습니다. 관련 변경은 `scripts/project-fs.mjs`의 대응 함수와 같은 커밋에서 맞추세요.

공유 사례는 `crates/agentmon-core/tests/reserved-heading-shapes.json`이며 코어 human_area 테스트와 `scripts/markdown-smoke.mjs`가 함께 사용합니다. 기록의 기술 본문에 열린 코드 펜스가 있으면 human이 코드 속으로 들어가므로 쓰기 경로에서 거부합니다.

# 규칙을 전달하는 경로

`crates/agentmon-core/build.rs`가 HUMAN_STYLE의 compact-rules 구간을 빌드할 때 추출합니다. CLI의 human 누락 오류와 MCP 첫 응답이 같은 규칙을 전달하며 `status(mode:"human_style")`는 전체 문서를 제공합니다. 문서 편집 후 CLI를 반드시 재빌드하고 `node scripts/check-humanstyle-drift.mjs`로 원문·내장 전체·내장 압축 규칙을 대조하세요.

450단어는 한 설명의 경고 상한이며 목표 분량이나 기록 전체 제한이 아닙니다. doctor는 실제 그림 참조의 빈 줄·SVG 크기 문제를 검사하지만, 굵은 문단이 있다는 이유로 그림을 요구하지 않습니다. 경고 안내도 v4 규칙을 따라야 합니다.

화면은 `src/lib/human.ts`와 HumanView가 읽습니다. v4의 짧은 문단·표·목록·그림과 기존 서사형 기록을 보존합니다. 마지막 짧은 문단이 강조 영역으로 표시되는 기존 동작은 남아 있습니다.

## For humans

사람 설명은 실제로 달라진 내용과 이유, 근거를 이해할 수 있게 쓰시면 됩니다. 짧은 진척까지 다섯 단계 이야기나 비유를 채울 필요는 없습니다. 관계나 순서가 중요하면 그 구조가 보이는 그림을 함께 설명합니다.

저장 방식은 유지됩니다. 진척 설명은 날짜별로 쌓이며, human만 보내는 갱신은 설명 전체를 교체합니다. 작성 규칙을 바꾸면 CLI를 다시 빌드해야 실제 도구 응답에도 반영됩니다. 이 정책과 파일 끝 빈 줄 수정을 1.5.2에 포함해 공개했습니다. 설치 앱 업데이트와 MCP 재연결 후 사용할 수 있습니다.

작업·버그 파일 끝에 생기던 불필요한 빈 줄도 정리됩니다. 새 버전의 도구로 생성하거나 갱신하여 저장할 때 적용되며, 과거 기록을 일괄 수정하지는 않습니다.
