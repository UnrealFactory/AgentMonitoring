## What

Add `updated_by` to the note frontmatter — set by every `agentmon note update` — and
surface it everywhere one agent stands next to a note's words: the list row, the palette
row and the MCP list now show the last rewriter (falling back to the author), the detail
byline and side card show the author *and* the rewriter when they differ, and the agent
filter slices on the same agent the rows display.

## Why

The owner pointed at the defect after opening the desktop app: a note is shared and
mutable, other agents keep rewriting it, and every surface paired the body with the one
fixed creator — so a body B rewrote sat under A's name, beside an updated-time that was
B's. The full edit trail was always on the event feed, but the name printed next to the
words has to be the name the words belong to.

## How

`Note.updated_by: Option<String>` (spec-exact `updated_by` on disk, `updatedBy` on the
wire, mirroring resolved_by), `current_agent()` = updated_by else agent. `note add`
writes null; `note update` stamps the caller. The JS twin, CLI list/view, MCP renderers
and both app screens read it; the ko fixture now rewrites one handoff cross-agent so the
Korean gates render the two-agent byline. Same-author revisions stay a quiet timestamp —
the second chip appears only when the rewriter is somebody else.

## Outcome

Shipped `updated_by` end to end: frontmatter (spec-exact key, camelCase wire), CLI list/view, JS twin, both app screens, palette and MCP renderers, with the display rule — the agent beside a note's words is its last rewriter, the author stays in the byline and side card, and the list's agent filter slices on what the rows show. SPEC and the manual now say a rewrite makes the words yours.

Verified: cargo test --workspace green (the update test now asserts updated_by and current_agent()); tsc clean; check:mcp 105 with a new frontmatter assertion on the rewrite step and tools/list still 6,070 bytes; check:i18n ko + en clean at 142 screens each, with the ko fixture's cross-agent rewrite putting the two-agent byline in front of both sweeps; check:clipping ko + en clean.

## For humans

Notes in this app are shared writing. Any agent can rewrite one, and they do. The owner opened the desktop app and found a note wearing the wrong name. The words were one agent's rewrite; the name printed beside them was the agent who first created the note. The time next to that name was the rewriter's.

**A note now records who touched it last.** I added a line called `updated_by` to the block of labels at the top of every note file. `agentmon note update`, the command an agent runs to rewrite a note, stamps its own name there. A brand new note leaves the line empty, because nobody has rewritten it yet.

**The name beside a note's words is now the last rewriter's.** `current_agent()` is the small rule that decides it: the rewriter if there is one, otherwise the author. That holds on the list, the quick-search row and the note's own page. It holds too in the copy handed out through MCP, the go-between other programs read this app with.

**Both names appear together when they differ.** The filter that narrows the list to one agent now matches the name the rows show.

It is like a library book: the cover says who wrote it, and a stamp inside says who last corrected it.

**Revising your own note adds no second name.** You get a fresh time and one name, not the same name twice.

**None of our Korean sample notes had been rewritten by a second agent.** So the two-name row never appeared in front of the checks that read every Korean screen. I changed one sample so a second agent rewrites it.

**`check:i18n` then passed in both languages, 142 screens each.** A sweep of that kind hunts for text left in the wrong language, and for words broken across a line. Those are what make a page unreadable to the reader it was translated for. `cargo test`, which runs every test written against the Rust code, passed across the project. The rewrite test now checks the new line, and the rule picking which name to show.

Every edit a note ever had was already listed in the app's feed of events, and still is. What changed is the name printed beside the words.

The name under a piece of writing should belong to whoever wrote the words you are reading.
