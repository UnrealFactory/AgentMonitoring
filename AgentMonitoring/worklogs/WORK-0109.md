## What

기기 공용 앱 피드백 4건(FB-0002~FB-0005)을 모두 읽고 현재 소스의 해결 여부를 확인합니다. 미해결인 기록 파일 EOF 빈 줄 문제를 수정하고 처리 근거와 피드백 상태를 정리합니다.

## Why

사용자께서 앱 피드백을 전체 확인하여 처리해 달라고 요청하셨습니다. 해결된 항목이 열린 상태로 남아 있고, 생성된 WORK·BUG 파일이 Git 공백 검사를 실패시키는 항목은 아직 미해결입니다.

## How

FB-0002를 격리된 프로젝트와 Git 저장소에서 재현하고 공용 기록 렌더링 경로를 수정합니다. 생성·갱신 경로의 회귀 검사와 실제 git diff --check로 검증하며 FB-0003~0005의 구현·기존 검증 근거도 점검합니다. 완료 조건은 전체 4건의 판단 근거 및 남은 배포 범위를 명시하고 실제 해결된 피드백을 완료로 전환하는 것입니다.

## Outcome

앱 피드백 전체 4건(FB-0002~FB-0005)을 읽고 처리했습니다. FB-0002는 body::render가 마지막 섹션 뒤에도 개행 두 개를 남기는 원인이었습니다. 마지막 구분자 개행 하나만 제거하여 본문·코드·표의 내부 공백과 빈 섹션을 보존합니다. 생성·진척·완료·정정 및 버그 생성·할당·코멘트·해결 뒤 EOF 검사를 추가했습니다.

수정 전 재현: 격리 MCP 프로젝트 C:/Users/User/AppData/Local/Temp/agentmon-fb0002-a40kNn/project에서 WORK·BUG를 만들고 git diff --cached --check를 실행하자 두 파일 모두 new blank line at EOF, 종료 2였습니다. 새 EOF 회귀 assertion도 수정 전 실패했습니다.

검증: cargo test -p agentmon-core -p agentmon-cli 전체 199개 통과, release CLI 재빌드 성공, node mcp/test/server.test.mjs 267개 통과. 새 CLI의 격리 MCP 프로젝트 C:/Users/User/AppData/Local/Temp/agentmon-fb0002-4ooNrY/project에서는 같은 Git 검사가 경고 없이 종료 0입니다. 모든 CLI init은 AGENTMON_REGISTRY_DIR로 실제 레지스트리와 격리했습니다. 소스 git diff --check(기존 AgentMonitoring 기록 제외)도 통과했습니다.

독립 에이전트 feedback_audit가 FB-0003~0005의 본문·WORK-0108·현재 구현을 대조하고 refs 회귀 1개와 SVG 회귀 7개를 재실행하여 통과했습니다. FB-0002의 끝 빈 섹션·내부 공백·재파싱 경계도 읽기 전용 리뷰에서 추가 결함을 발견하지 못했습니다. FB-0003(목적 단위 WORK·메모리·그림 정책), FB-0004(work-/bug- 노트 refs), FB-0005(SVG 기하)의 기존 수정 근거가 충분함을 확인했습니다.

FB-0002 사람 설명에 원인·수정·검증·한계를 갱신하고 4건 모두 CLI app-feedback done으로 완료 처리했습니다. 다시 목록을 읽어 전체 4 / open 0 / done 4를 확인했습니다. human-area-enforcement 노트에 EOF 저장 규칙을 추가했습니다.

현재 소스와 개발용 CLI에 반영됐습니다. 설치 앱·설치 MCP 공개 배포와 과거 프로젝트 기록의 일괄 정규화는 수행하지 않았습니다. 과거 기록은 새 버전의 도구로 정상 갱신할 때 끝 빈 줄이 정리됩니다.

## For humans

앱 피드백 4건을 확인하고 남은 문제를 처리합니다. 기록 파일 끝에 불필요한 빈 줄이 생기는 현상은 재현부터 확인합니다. 앞서 수정한 세 항목도 근거를 점검한 뒤 완료 상태로 정리하겠습니다.
