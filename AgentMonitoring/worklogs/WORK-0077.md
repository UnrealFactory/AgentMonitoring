## What

Make the always-on doc surfaces run. `README.md`'s "Start to finish" block gains
`--human` on `work start` and `work done`, its ids corrected WORK-0004 -> WORK-0001, a
clause on the work-log bullet (README.md:21-24) and a paragraph after the block naming the
flag and `agentmon human-style`. `docs/AGENT_MANUAL.md` gains the
`(--human <text> | --human-file <file|->)` line in the `work abandon` synopsis
(1150-1154) and `--human "..."` in the stuck-record cure (1733). The same defect, found in
three in-app empty states, is fixed there too: `src/pages/WorkListPage.tsx`,
`src/pages/NotesPage.tsx` and `src/pages/BugsPage.tsx` printed copyable commands with no
`--human`, and BugsPage still printed the v1 `-p <id>` flag the v2 CLI cannot parse (its
now-unused `projectId` prop comes off `BoardEmpty` with it). Two SPEC claims corrected:
`work start`'s body bracketed as optional though it is required, and "the full contract
prints inside every rejection" when what prints is the compact extract — and the unclosed-
fence rejection prints no rules at all.

## Why

D1-D5 changed what a record is — every one carries a human area, and every verb that opens
or closes a record refuses to write without one — but README was never on D5's ablation
list. It was the one always-on surface the whole initiative never touched, so the front
page still sold the pre-D1 product and its quickstart exited 2 on two of its three
record-writing commands. A newcomer's first command failing is the worst place this defect
could sit. The manual's `work abandon` synopsis was the only required-verb synopsis
missing its `--human` line, and the stuck-record cure it belongs to is reached by an agent
that is already stuck with no other page open. The three in-app hints are the same class: a
command the product itself prints has to be one the product accepts.

## How

Reproduced first, at the binary, in a sandboxed project (AGENTMON_REGISTRY_DIR redirected,
live data untouched): the README block run verbatim gave exit 0 on `init`, exit 2 on
`work start`, exit 2 on `work done`, and exit 3 on `work update WORK-0004` — a second,
independent break nobody had named, because a project this new numbers its first log
WORK-0001.

Re-verified by extraction rather than by retyping, so the thing checked is the file and not
a copy of it: a script pulls the fenced block straight out of README.md, rewrites only the
`cd` line, and runs it — exit 0 on every command, and `doctor --strict` clean on the
project it produced. The `work start` retelling is the manual's own (recipe 1, line 507),
so the front door and the manual now say the same words about the same example; the
`work done` one is a two-beat compression carrying no number README does not already
state.

The three in-app lines render only on a project with nothing in it, which no standing gate
reaches, so they were checked by booting the dev server against an empty fixture project
and reading `.empty-code` off the Work, Bugs and Notes screens — text, painted size, and a
scrollWidth/clientWidth clipping probe. Dropping `-p {projectId}` left `projectId` unused
in `BoardEmpty`, which `noUnusedLocals` catches; the prop and its type came off with it.

## For humans

The front page of this project shows a newcomer a short list of commands to copy into a
terminal. Two of them stopped with an error the moment anybody ran them.

**Every record here has two halves, and the front page knew about one.** Since a change in
August, each saved record carries a plain retelling of itself for a reader who does not
program, handed over in a `--human` setting on the command that saves it, and the command
now refuses to save without one. `README.md` — the page GitHub shows first — was written
before that and never revisited, so the commands it prints were the old, refused shape.

**I put the missing half into the commands that print, and said in one line that the half
exists.** The manual agents read got the same repair, including the entry that tells an
agent how to close a job it has walked away from: that entry was prescribing a command that
is refused.

**The block had a second break, and only running it found that one.** It saves its first
work log and then addresses it as `WORK-0004`, while a brand-new project numbers its first
one `WORK-0001` — so the two commands after it could not find the record at all. Three
screens inside the app had the first fault as well, on the lines they print when there is
nothing to show yet, and one of those still passed `-p`, a setting the program stopped
accepting a version ago.

**I ran the page rather than a copy of it.** A script lifts the commands straight out of
`README.md` and runs them against a throwaway project; every one finished cleanly, and
`agentmon doctor`, the command that checks a project for damage, found nothing wrong with
what they wrote. It is like cooking a recipe off the packet instead of reading it over —
the only way to find the step that does not work. I opened the three screens in a browser
and read their lines back off the page.

Nothing about the app looks different; its instructions now work. Those three screen lines
have no automatic check watching them — I read them myself, once.

Instructions nobody runs are a claim, not a fact.
