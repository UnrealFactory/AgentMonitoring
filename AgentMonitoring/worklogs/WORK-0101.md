## What

첨부 화면의 프로젝트 우클릭 메뉴에서 4개의 생성 항목을 지침 쓰기 / MCP 추가하기 두 항목으로 묶고, 각 하위 메뉴에서 Claude 또는 Codex를 선택하도록 변경합니다.

## Why

사용자께서 옵션이 많고 이름이 잘리는 화면을 지적하시며 목적을 먼저 고르고 도구를 선택하는 구성을 제안하셨습니다.

## How

공통 컨텍스트 메뉴에 하위 메뉴 열기와 위치 계산, 방향키·Escape로 돌아가기, 포커스 복원을 추가합니다. 기존 파일 생성 경로는 그대로 사용하며 실제 생성과 키보드 동작을 확인할 예정입니다.

## Outcome

프로젝트 우클릭 메뉴의 생성 항목 4개를 지침 쓰기 / MCP 추가하기 2개로 정리했습니다. 각 항목을 클릭하면 Claude와 Codex를 선택하는 하위 메뉴가 열리고 파일명이 오른쪽에 보입니다. src/components/ContextMenu.tsx에 1단계 하위 메뉴, 화면 가장자리에서 좌우 전환 및 세로 위치 보정, 방향키·Enter·Escape·Tab 동작과 부모·호출 행 포커스 복원을 구현했습니다. 파일 생성 API와 새 프로젝트 화면은 유지했습니다. 사용하지 않는 기존 메뉴 번역을 정리하고 docs/MCP.md를 갱신했습니다.

검증: npm run build와 git diff --check가 통과했습니다. AGENTMON_BIN=target/debug/agentmon.exe로 npm run check:instructions의 23개 검사와 npm run check:keys -- --port 5224의 276개 검사가 통과했습니다. 한국어·영어 하위 메뉴에서 실제 파일 생성, 반복 실행, 방향키·Escape·포커스 복원, 960x620 화면 양쪽 아래 모서리의 위치·문구 잘림을 확인했습니다. 처음 위치 검사는 resize 이벤트 완료 전 메뉴를 열어 실패했으며, resize가 끝나기를 기다리도록 검사 코드를 수정했습니다. 좌표 없는 일반 이벤트를 사용하던 모서리 검사는 MouseEvent로 바꾸고 실제 위치·전환 방향도 확인하도록 보완했습니다. 한국어 오른쪽 모서리와 영어 왼쪽 모서리 이미지를 직접 확인했습니다.

개발 앱 PID 10664와 Vite 세션 78270은 계속 실행 중이며 Vite HMR 갱신 출력을 확인했습니다. 별도 검사 서버는 종료했습니다. 커밋·배포는 수행하지 않았습니다.

## For humans

사용자께서 프로젝트 메뉴에 생성 항목이 많고 이름이 잘리는 화면을 보여 주셨습니다. 지침 쓰기와 MCP 추가하기를 먼저 고르고, 안에서 Claude 또는 Codex를 고르는 구성으로 정리합니다.

**메뉴를 두 단계로 나누는 작업을 시작합니다.** 서랍 이름을 먼저 보고 안에서 필요한 도구를 고르는 것과 같습니다. 기존 파일 생성 기능은 유지하며, 클릭과 키보드 동작을 확인할 예정입니다.

![프로젝트 메뉴에서 MCP 추가하기를 누르면 Claude와 Codex가 열립니다](assets/project-mcp-submenu.png)

프로젝트 우클릭 메뉴의 생성 항목을 지침 쓰기와 MCP 추가하기로 묶었습니다. 어느 항목이든 클릭하면 Claude 또는 Codex를 선택할 수 있습니다.

**도구 이름과 파일명을 다음 단계에서 보여 줍니다.** 처음부터 네 항목을 늘어놓지 않아 메뉴가 짧아졌습니다. 서랍 이름을 먼저 보고 필요한 도구를 고르는 것과 같습니다. 파일 생성 기능은 그대로 연결했습니다.

**키보드로도 열고 돌아올 수 있습니다.** 오른쪽 화살표나 Enter로 하위 메뉴를 엽니다. 왼쪽 화살표나 Escape로 부모 항목에 돌아오고, 다시 Escape를 누르면 원래 프로젝트 행으로 돌아옵니다.

**생성과 메뉴 동작을 확인했습니다.** 파일 생성과 선택 동작을 확인하는 검사 23개, 기존 키보드 동작 검사 276개가 통과했습니다. 화면 양쪽 아래에서도 하위 메뉴와 파일명이 잘리지 않았습니다.

개발 앱은 켜 두었으며 이번 화면 변경이 반영됩니다.
