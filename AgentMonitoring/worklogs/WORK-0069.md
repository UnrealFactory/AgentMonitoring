## What

The four record surfaces — work detail, bug detail, note detail and the app-feedback board — get an Agent / Human segmented control in the record head, and a human view under it that renders the record's `human` field.

## Why

D2 shipped `human: string | null` on both transports and WORK-0068 closes with "the frontend still does not read `human`. That is D3." SPEC's Desktop app screens section is the contract: the toggle defaults to Human when the record has a human area, the choice persists for the session, and a record without one shows a designed empty state naming the exact CLI command that adds it.

## How

A session store (`src/lib/recordView.ts`), a beat reader (`src/lib/human.ts`, on top of `splitLabelledSections`), one component (`src/components/HumanView.tsx`), and the four pages wiring them in. The gates that walk record screens each say which half they are reading.

## Updates

### 2026-08-22T13:40:00Z

The human view is not a second `.prose` block: `docs/HUMAN_STYLE.md` asks every beat to open with one bold sentence, and every retelling in this project is written that way, so `src/lib/sections.ts` — which already finds exactly that shape for a resolution's **Root cause.** / **Verified.** labels — is called with `min: 1` and its `raw` label (punctuation kept, because a lead-in is a sentence and a heading is not). Beats become numbered blocks; the closing one-sentence paragraph becomes the takeaway.

## Outcome

**Shipped.** `RecordViewToggle` (src/components/HumanView.tsx) is the app's own segmented control, two `<button role="tab" data-value>`s, in a new `.record-head-top` row beside the title on all four surfaces. `useRecordView(hasHuman, key)` (src/lib/recordView.ts) keeps the choice in `sessionStorage` — one value for the window, so a reader walking a week of records presses nothing twice — and falls back to Human when the record has a human area, Agent when it does not.

**The default is latched to the record, not recomputed from every refresh.** This app is live: an agent running `agentmon note update --human` on a legacy note adds a human area to a page somebody is mid-sentence in, and without the latch that page swapped itself from the agent's sections to a retelling with no click. `scripts/check-live.mjs` is what found it (its note page went blank waiting for `.note-lead`), and it is the one place this deviates from a literal reading of SPEC's "defaults to Human when the record has a human area": that is a claim about opening a record, not a licence to move the page under the reader.

**The human view is the record's own shape, not a second body block.** `src/lib/human.ts` reads the beats docs/HUMAN_STYLE.md asks for — an opening paragraph, then paragraphs each opening on one bold sentence, then a closing line — using `splitLabelledSections` with a new `min` option (1 here, still 2 for a resolution) and a new `raw` field, because a lead-in keeps the full stop a heading would drop. Beats are numbered in the gutter; the closing sentence becomes the takeaway block; the body renders through `Markdown ... figures`, so `WORK-`/`BUG-` chips and `[[note-name]]` wiki-links work inside it and the numbers are marked the way the resolution's verification block already marks them. Nothing is extracted, paired or recomputed.

**Design.** Two new tokens: `--text-read: 15px` (the one surface in this app that is read rather than scanned) and `--human-measure: 62ch`. The sheet is `--bg-surface` on the app floor, one measure wide, beats separated by hairlines, one accent-soft block for the takeaway, a tertiary byline naming who retold it. No new fonts, no light panels, no emoji. `.human-beat-lead` and `.human-takeaway` join the author-text keep-all group in tokens.css (they are the author's Korean, at the largest size this app prints a sentence in) and the empty box's own four sentences join the app-sentence group.

**Empty state.** A record with no retelling gets a bordered card: what the missing half is, that an agent writes it, the exact update verb with this record's real id (`agentmon bug comment BUG-0025 --agent fable-tray-gestures --human "…"`) behind a copy button, `agentmon human-style` for the rules, and a button back to the agent's half. It is capped at 720px rather than the reading measure because a hyphen carries a line-break opportunity and the command wrapped inside `--human`.

## For humans

A record here is written by the agent that did the work, and — since the rule came in — retold in plain language for someone who was not there. Until today only the first of those was ever on screen. Now every record page carries two buttons at the top, Agent and Human, and opens on the plain half when the record has one.

**The plain half is not the technical page with softer words.** It is a different page. The head of the page stays put and the middle swaps. File lists, progress notes and section headings go, and one column of prose takes their place. It is set to `--text-read`, a size this app uses nowhere else, because this is the one surface meant to be read rather than scanned.

**The writing already had a shape, and the screen now shows it.** `docs/HUMAN_STYLE.md`, the rule agents write these by, asks for an opening paragraph. Then one short bold sentence to start each turn of the story, and a line worth repeating at the end. `src/lib/human.ts` reads those back: each bold sentence becomes a numbered heading, and the last line gets a box of its own. Nothing is summarised or reordered, links to other records and to notes still work inside it, and the sheet says who did the retelling.

It is like the difference between a recipe card and someone telling you how they cooked it.

**Most records here are older than the rule and have no plain half.** Those show a box that says so and prints the one command that adds it, with that record's own number already in it.

**One thing nearly broke a reader's page.** These screens refresh themselves while you read. An agent writing the plain half of a record you had open would have flipped your page mid-sentence. The page now picks a half once, when you open it. `check-live`, which watches the parts of the app meant to redraw themselves, is what caught it.

**`check-keys` passes 272 checks over both languages.** Sixteen are about this switch. It opens on the plain half, the keyboard reaches and works it, and a record without one answers with that box. When that check goes red, somebody working without a mouse is stranded.

**Nothing on the new screens is cut off.** `check-clipping` opens every screen at eight window widths in each language, 114 screens a run, and reports any text its own box slices. It found none. The type checker and the build both ran clean too.

**One check is red, and none of it is this round's own screen furniture.** `check-i18n` reads every screen in Korean and flags the words that are not Korean. It stands at 38: 37 were already on the books, and the 38th is one of those same sentences turning up once more, because the list of related records is drawn on both halves.

Still missing: every bug this project has filed about itself predates the rule. So a bug's plain half has only been seen on a made-up project.

A page you can hand to someone who was not there is worth more than one only its author can read.
