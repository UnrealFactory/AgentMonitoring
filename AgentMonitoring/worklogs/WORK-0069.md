## What

The four record surfaces — work detail, bug detail, note detail and the app-feedback board — get an Agent / Human segmented control in the record head, and a human view under it that renders the record's `human` field.

## Why

D2 shipped `human: string | null` on both transports and WORK-0068 closes with "the frontend still does not read `human`. That is D3." SPEC's Desktop app screens section is the contract: the toggle defaults to Human when the record has a human area, the choice persists for the session, and a record without one shows a designed empty state naming the exact CLI command that adds it.

## How

A session store (`src/lib/recordView.ts`), a beat reader (`src/lib/human.ts`, on top of `splitLabelledSections`), one component (`src/components/HumanView.tsx`), and the four pages wiring them in. The gates that walk record screens each say which half they are reading.

## For humans

Every record in this app is written twice: once by the agent that did the work, for other agents, and once in plain language for a person who was not there. Until today only the first half was ever on screen. Now every record page has two buttons at the top — Agent and Human — and opens on the plain half when there is one.

**The plain half is not the technical page with softer words.** It is a different page. The record's name, who did the work, what state it is in and when it happened stay exactly where they were, and the middle of the page swaps: the file lists, the progress notes and the section headings go away, and a single column of prose takes their place, set larger than anything else here because it is meant to be read start to finish rather than scanned.

**The writing already had a shape, and the screen now shows it.** The rule agents write these by asks for an opening paragraph, then one short bold sentence to start each turn of the story, then a line worth repeating at the end. So the page reads those back out: each bold sentence becomes a heading with a small number beside it, and the last line gets a box of its own. Nothing is summarised or reordered, and the numbers an agent wrote stay exactly where they wrote them — they are only set in a weight your eye lands on.

It is like the difference between a recipe card and someone telling you how they cooked it.

**Most records here are older than the rule and have no plain half.** Those show a box that says so and prints the one command that adds it, with that record's own number already in it, next to a copy button. It also offers the way back to the technical half, because an empty page that strands you is worse than no page.

**One thing nearly broke a reader's page.** These screens update themselves while you read. An agent writing the plain half of a record you already have open would have flipped your page from the technical half to the new one mid-sentence. The page now decides which half to open once, when you open it, and after that only you change it. The check that watches for live updates is what caught it.

**What is still missing.** Every bug this project has filed about itself was written before the rule, so a bug's plain half has only been seen on a made-up project, not on this one. Filling in the real records is the next piece.

A page you can hand to someone who was not there is worth more than one only its author can read.
