## What

사전 조사 결과를 바탕으로 AgentMonitoring/notes/work-boundaries-and-explanatory-visuals-proposal.md 참고 노트와 assets/entity-readiness-visual-proposal.svg 시안을 작성하고 start-here 색인에 안내를 연결했습니다. 이 WORK의 시각은 시안 파일 작성부터 제안서·색인·피드백 정리 완료까지입니다. 앱 자체 개선 요청은 FB-0003, 노트 참조 오류는 FB-0004로 남겼습니다.

## Why

사용자께서 ElmwoodOnline 45~47번 작업처럼 같은 주제의 질문·제안·정정이 매번 완료 WORK로 남는 문제와, 사람 설명용 SVG가 상자 속 문장 위주여서 이해하기 어렵다는 문제를 제기하셨습니다. 지침·도구 설명·기존 프로젝트 갱신 경로를 포함한 패치 방향을 검토할 수 있게 만드는 작업입니다.

## How

agentmon으로 두 프로젝트 필수 색인과 상태, ElmwoodOnline 45~47번 기록 전문을 읽었습니다. 한·영 템플릿, MCP 설명·노트 목록 출력, HUMAN_STYLE, claude_md.rs의 기존 파일 감지, 그림 검사 코드를 조사했습니다. 기존 세 이미지를 Chromium으로 폭 393px에 렌더링했습니다. 새 시안은 47번의 검토안을 바탕으로 자체 준비·참조 확인 후 연결·대상 부재 시 해제를 도형과 선으로 표현했습니다. 노트 생성은 성공했지만 work- 접두사 노트 이름을 refs에 넣으면 WORK 번호로 오인해 거부하는 실제 오류를 발견했습니다. 해당 refs 항목 없이 본문에 이름을 명시하여 색인 갱신을 완료하고 앱 피드백을 남겼습니다.

## Outcome

채택 전 패치 제안서와 SVG 시안을 준비했습니다. Chromium getBBox에서 system-ui·Verdana 두 서체의 글자 겹침·14단위 가장자리 침범이 없었고, 395px 폭 환산 최소 글자는 약 12.41px였습니다. node scripts/check-scenes.mjs --dir C:/Code/AgentMonitoring/AgentMonitoring은 종료 코드 0으로 참조된 그림 26개를 통과했습니다. 시안을 직접 렌더링해 확인했습니다. 실제 지침 템플릿·MCP·실행 코드를 수정하거나 배포하지 않았고 ElmwoodOnline 기존 기록도 변경하지 않았습니다. 이해도 개선·새 기록 정책의 행동 효과는 검증 전이며, 제안을 사용자와 조율한 뒤 구현할 수 있습니다.

## For humans

사용자께서 작업 기록이 대화마다 늘고 그림이 상자 속 문장처럼 보인다고 알려 주셨습니다. WORK는 개발 이력을 모으는 기록입니다. 현재 안내는 ‘의미 있는 작업’이라고만 적어 질문과 개발 작업의 경계를 정하지 않습니다.

**작업 목적을 기준으로 기록하고, 필요한 관계를 그림으로 보여주는 안을 준비했습니다.** 개발과 별도로 맡긴 조사는 WORK에 남기고, 설계 대화에서는 이후에도 필요한 사실만 노트에 반영하는 방향입니다. 템플릿과 MCP 도구 설명을 함께 바꾸도록 제안했습니다.

**두 물체가 준비하고 연결을 사용하는 조건을 시안으로 그렸습니다.**

![자체 준비와 관계 사용을 구분하는 설명 시안](assets/entity-readiness-visual-proposal.svg)

Entity는 게임 물체를 나타내는 대상입니다. 두 물체는 각자 준비하고, 양쪽 준비와 참조 확인 뒤 연결합니다. 대상이 사라지면 연결을 풉니다. 기존 검토안을 표현했으며 게임 실행 결과를 측정한 그림은 아닙니다.

**배치 검사는 통과했지만 이해도는 아직 평가 전입니다.** check-scenes.mjs는 그림의 글자 겹침과 크기를 검사하는 도구입니다. 이번 프로젝트의 그림 26개가 통과했습니다. 기존 프로젝트 지침은 같은 제목이 있으면 갱신을 건너뛰는 점도 확인했습니다. 안내서 원본을 고쳐도 이미 나눠 준 사본이 남는 것과 같습니다.

현재 결과물은 패치 제안서와 시안이며, 실제 기록 정책 변경은 아직 적용하지 않았습니다.
