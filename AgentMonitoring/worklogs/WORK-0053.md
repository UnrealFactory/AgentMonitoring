## What

The New-project dialog's two options, reachable after creation. CLI: `agentmon project
claude-md --lang ko|en`, the twin of `project mcp-json`. Desktop: two Tauri commands
(write_project_claude_md / write_project_mcp_json) and two rows in the project context
menu, with a toast that conjugates the outcome (created / appended / updated / already
up to date). Browser mode: POST /project-api/projects/:id/{claude-md,mcp-json} shelling
those CLI verbs with --dir. Also, the switcher card now says "진행 중 1개" instead of
"9개 중 1개 진행 중" (owner call — the total sits on the 작업 row right below, and the
old phrasing read as nine things still moving; tooltips keep the denominator).

## Why

The CLAUDE.md template and the .mcp.json server path move with the app, and a project
created last month had no way to catch up short of re-creating it; a repo that moves
machines has a dead server path in .mcp.json for the same reason. Both writes were
already conservative in core (append without touching the human's text; replace only the
agentmon entry), so the only thing missing was a place to press.

## How

No new write logic — core's write_claude_md / write_mcp_json are called from the CLI,
the Tauri commands and (via the CLI) the browser route, so one implementation serves
three transports. check-keys' expected menu item lists gained the two ids; check-i18n
learned .mcp.json and FB-NNNN as technical tokens, and its foreign-word test now takes
the intersection of two stripping orders (vault words first / fixed tokens first) so a
tag named `mcp` cannot bite "json" out of ".mcp.json" and /v\d+/ cannot bite
"rearchitect" out of a handle. Verified: cargo test --workspace 10 suites green, sandbox
CLI runs (create → already_present → bad-lang refusal), browser-route sandbox run
(created/created/already_present), tsc, check:keys 257, check:i18n clean both locales,
menu screenshot read.

## Outcome

Existing projects can (re)write CLAUDE.md and .mcp.json from the project menu, the CLI (project claude-md / mcp-json) and the browser route — one core implementation, outcome-aware toasts; switcher card counts only what is in progress. All gates green (cargo, tsc, check:keys 257, check:i18n ko+en), sandbox e2e on all three transports.

## For humans

When you create a project here, the app offers to write two files into it. One is `CLAUDE.md`, the standing instructions every agent reads before it touches that repo. The other is `.mcp.json`, which holds the path to the small program agents talk to this app through. Both keep changing as the app does, and a project made last month kept the old ones. Catching up meant making the project again. Move a repo to another machine and the path inside the second file points at nothing.

**Both are now a menu item on any project you already have.** They also exist as commands you can type, and as a request the browser version sends. All three run one piece of code, so there is one behaviour to get right instead of three.

It is like three doors into one kitchen.

**This was only ever a button, because the writing was already careful.** The instructions file is added to at the end, leaving whatever a person wrote in it untouched. The other file has only this app's own entry replaced. Afterwards the app tells you which of four things happened: created, added to, updated, or already correct.

**The awkward part was a check on wording, not on writing files.** `check:i18n` reads the app's on-screen text in each language and flags words that look like they were left in the wrong one, so a Korean screen does not quietly serve English. It first strips out the bits meant to look technical, and it had to be taught that `.mcp.json` is one of them.

**Stripping can bite a word in half.** A project tag named `mcp` could be cut out of that filename, leaving a bare `json` standing there to be flagged. The check now strips twice, in two different orders, and trusts only the words both passes agree on.

**I ran it all in throwaway folders first.** Typed as a command it created both files, said they were already there on a second run, and refused a language it does not carry. The browser version's request behaved the same way. Every group of tests passes, all ten, and I opened the menu in a screenshot and read it.

**One line of counting changed too.** The card at the top of the project switcher said "one of nine in progress", which read as nine things still moving; it now says only how many are in progress. The total sits on the row directly beneath, and hovering still shows both numbers.

A file the app once wrote for you is a file the app should still be able to write.
