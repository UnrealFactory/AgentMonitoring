## What

Released v1.0.5: bumped the version in package.json, src-tauri/tauri.conf.json and
Cargo.toml (with Cargo.lock refreshed by a release build), pushed main, then ran
`npm run release` — NSIS installer built and the GitHub release created at
https://github.com/UnrealFactory/AgentMonitoring/releases/tag/v1.0.5 with
AgentMonitoring_1.0.5_x64-setup.exe attached. Handoff note moved to v1.0.5.

## Why

WORK-0063 (the FB-0001 essential-demotion guard) sat on main unreleased; installed
apps keep running the old MCP server and CLI until a release carries the change, and
the owner asked to ship it.

## How

The release flow the handoff note documents: all three version fields must agree or
release.mjs refuses; `npm run release` builds the frontend, the Tauri bundle and the
installer, then creates the release via the logged-in gh CLI. Installed apps see the
update from the sidebar card on their next check.

## Outcome

v1.0.5 is live: tag and asset both from main at 072ad52 — verified via gh release view (AgentMonitoring_1.0.5_x64-setup.exe, 8,008,286 bytes, target main). release.mjs exited 0. Installed apps get the offer on their next launch or half-hour recheck.

## For humans

Version 1.0.5 of this app went out on 22 August 2026. An installed copy is offered it by a card in its sidebar, either at its next launch or at one of its half-hourly checks.

**What it carries is a warning nobody could hear before.** `WORK-0063` added a guard: when a rewrite takes `essential` off a note, the tools now say so, and name the command that puts it back. That mark is what makes a note required reading. The guard existed only in the shared source. Every installed copy went on running its own older tools, silent as before, so the owner asked for it to be sent out.

**Three files hold the version, and they have to agree.** They are `package.json`, `tauri.conf.json` and `Cargo.toml`. The release script stops before it starts if they say different things, which spares you a download labelled one version and built from another. I set all three to 1.0.5, pushed the change, then ran `npm run release`. That single command builds the app, wraps it into a Windows installer, and publishes it for people to fetch.

It is like a form that asks for the same date in three boxes. The clerk will not take it until they match.

**Then I asked the published page what it was actually holding.** `gh release view` reads back what went up. `AgentMonitoring_1.0.5_x64-setup.exe` is there, 8,008,286 bytes of it, and the published version is tied to the shared main line of code the build came from. The release command itself ended without an error. That check reads the page, and it cannot tell you how the update behaves on somebody's machine.

**From this version on, the tool talks back.** An agent that takes required-reading status off a note is told, in the same breath, how to give it back. A copy that never accepts the offer keeps the quiet behaviour.

Shipping is the last step of a fix, not a step after it.
