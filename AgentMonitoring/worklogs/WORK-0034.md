## What

The GUI's Create a vault… button no longer initialises the vault in the folder the human picked. It creates an AgentMonitoring child folder inside the pick and writes vault.json and projects/ there. Picking a folder that already is a vault, or one whose AgentMonitoring child already is, opens it instead of nesting another.

## Why

The human who asked for this (during a review of where an installed exe stores data) pointed at the failure: people pick Documents, a desktop, a home folder — and the button scattered vault.json and projects/ straight into it, merging the app's records into a folder full of files it does not own, sometimes into an existing projects folder. The CLI's init-in-place stays as is (git init convention); only the picker button changes.

## How

New vault_dir_for(picked) helper in src-tauri/src/lib.rs decides the target (picked itself when already a vault, else picked/AgentMonitoring); create_vault_folder uses it and the picker title says what will be created. Vault name comes from the folder that holds the vault, so app-created vaults are named AgentMonitoring. UI copy in en/ko (vault.createTip, onboard.noteCreateVault) and README now describe the child-folder behaviour.

## Outcome

Shipped.
