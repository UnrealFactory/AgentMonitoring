## What

The GUI's Create a vault… button no longer initialises the vault in the folder the human picked. It creates an AgentMonitoring child folder inside the pick and writes vault.json and projects/ there. Picking a folder that already is a vault, or one whose AgentMonitoring child already is, opens it instead of nesting another.

## Why

The human who asked for this (during a review of where an installed exe stores data) pointed at the failure: people pick Documents, a desktop, a home folder — and the button scattered vault.json and projects/ straight into it, merging the app's records into a folder full of files it does not own, sometimes into an existing projects folder. The CLI's init-in-place stays as is (git init convention); only the picker button changes.

## How

New vault_dir_for(picked) helper in src-tauri/src/lib.rs decides the target (picked itself when already a vault, else picked/AgentMonitoring); create_vault_folder uses it and the picker title says what will be created. Vault name comes from the folder that holds the vault, so app-created vaults are named AgentMonitoring. UI copy in en/ko (vault.createTip, onboard.noteCreateVault) and README now describe the child-folder behaviour.

## Outcome

Shipped. Create a vault… now targets picked/AgentMonitoring; the reworked unit test seeds the pick with a projects folder and a stray file, asserts the vault lands in the child, the pick itself gains no vault.json, a second pick resolves to the same vault, and a pick that is itself a vault is used as-is. cargo test -p agentmonitoring --lib: 8/8 pass. tsc --noEmit clean, npm run check:keys 223 checks pass (en and ko copy updated together).

## For humans

You press Create a vault…, the app opens a folder picker, and you choose Documents. Documents is then where the app keeps every record it has: a settings file called `vault.json` and a `projects` folder, dropped in among everything else you keep there — sometimes on top of a `projects` folder you already had.

**People pick the folders they live in.** Documents, a desktop, a home folder. The owner spotted this while going over where an installed copy of the app stores its data.

**The button now makes its own folder first.** It creates a folder named `AgentMonitoring` inside whatever you picked, and writes the records in there, so Documents gains one folder and nothing else. The picker's own title, and the app's wording in English and Korean, now say what will be created. It is like being handed a drawer instead of having your papers tipped onto the table.

**Picking the same place twice does not nest a second one.** If what you picked already holds the app's records, or already is that folder, the app opens it rather than building another one inside.

**A test now picks a dirty folder on purpose.** It seeds the picked folder with a `projects` folder and a stray file, then checks that the records land in the child, that the picked folder itself gains no `vault.json`, that picking it again lands on the same records, and that picking a folder which already is one uses it as it stands. Eight of eight pass.

**What is different: the app no longer moves in among your files.** Typing the command by hand is the exception, and deliberately so — there you have named the folder yourself, so it is made where you stand, the way `git init` does.

A program that writes into a folder it did not create is a guest rearranging your shelves.
