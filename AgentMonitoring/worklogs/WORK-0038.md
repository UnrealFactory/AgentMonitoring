## What

Two shell features the human asked for: (1) closing the window hides it to a system tray icon instead of quitting, so the watchers keep running; (2) right-drag mouse gestures (U/D/L/R/UD/RU/DR) with a trail overlay and action bubble, mirroring C:/Code/AgentCodeGUI's engine.

## Why

The app is a monitor: agents write records while no one is looking at the window, and a closed window today means a dead process — nothing watches, nothing refreshes. And the human uses AgentCodeGUI daily; its right-drag gestures are the muscle memory they want here too.

## How

Rust: tauri tray-icon feature, TrayIconBuilder in setup (open/quit menu in the settings.json language, rebuilt by set_locale), on_window_event intercepts CloseRequested -> hide, but only while the tray icon exists (a hidden window with no tray would be unrecoverable). tauri-plugin-single-instance surfaces the hidden window on a second launch. Frontend: src/components/MouseGestures.tsx ports AgentCodeGUI's recognizer (start 14px, stroke 24px, dominant-axis segments off a moving anchor, one-shot capture-phase contextmenu swallow) with this app's actions: scroll top/bottom, back/forward, reload, maximize/restore, close-to-tray. Gestures stand down while a dialog is up (lib/modal.ts) — the P12 rule.

## For humans

This app watches while nobody looks at it: agents write their work into records and the window keeps up. Press the X, though, and the whole program ended, and nothing watched until somebody started it again. The owner also draws short strokes with the right mouse button in another program every day, `AgentCodeGUI`, and wanted those strokes here.

**The X now hides the window and leaves the program running.** A small icon stays in the Windows tray, the row of tiny icons beside the clock, and its menu offers open, or quit for good.

**A hidden window with no icon would be a program you cannot reach.** So the X only hides while that icon is really there. If it never appeared, the X quits the way it always did. Start the app again and it brings the hidden window back rather than opening a second copy.

**Seven strokes, drawn with the right button held down.** Up and down scroll the page to its ends, left and right go back and forward. Up-then-down rereads the records, right-then-up maximizes or restores the window, down-then-right closes to the tray. `src/components/MouseGestures.tsx` reads them, draws a line following the mouse, and names the action in a bubble at the middle.

It is like tracing a shape in the air to call somebody over: what you drew is the whole message.

**A drawn stroke must not also open the right-click menu.** Letting the button up would normally pop it, so that same file swallows exactly one menu, the next one, and stands the strokes down while a dialog is on screen.

**I had five of the seven strokes drawn and watched what happened.** Playwright, a tool that drives an app the way a person does, drew them in the browser version: the trail and bubble appeared mid-draw with the action named, history moved, the page scrolled, the records reread. The drawn stroke opened no menu, a plain right-click still opened the app's own, and nothing fired while the quick-search panel was open.

**I pressed the X on the real desktop app too**, through `connectOverCDP`, which attaches to a running window and drives it like a browser tab. The window went invisible with the program still alive, and the tray icon brought it back. `cargo test`, the desktop app's own automatic checks, passed six of six.

You can leave the window closed all day now, and the watching carries on.

A monitor you have to keep on screen is not really watching for you.
