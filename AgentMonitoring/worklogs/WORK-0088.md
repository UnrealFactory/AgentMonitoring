## What

Change the human area's update semantics from replace to append on work logs and bugs. `work update`/`bug comment` with a `--message` now append the supplied `--human` as a `### <ts>` node inside `## For humans`, stamped like the entry it travels with; closing verbs (`work done`/`work abandon`/`bug resolve`) append the ending as the page's last node; `--replayed` inserts the telling at its time (`insert_telling_by_time`); `--human` alone stays a whole-page replace (the curation path). New core helpers `append_telling`/`insert_telling_by_time`/`last_telling` in crates/agentmon-core/src/human.rs; `longest_telling` treats a dated node as a telling edge; an unchanged telling is appended once (one MCP call is legally two CLI steps sending the same `human`). Frontend: `readHumanTellings` in src/lib/human.ts splits the page at dated nodes (fence-aware, date-gated like `starts_with_date`), and HumanView draws each telling with a quiet dated seam, continuous beat numbers, standfirst on the first lede only. Docs rewritten: SPEC.md "The human area", HUMAN_STYLE.md compact rules + long-form bullet, AGENT_MANUAL.md matrix + recipes, CLI after_help/hints, MCP tool wording.

## Why

The replace rule kept deleting history. WORK-0087 tried to fix the loss by teaching (compact rules: "retell the whole record so far, carry earlier tellings forward") and it did not hold: ElmwoodOnline's WORK-0017 reached ~20 agent update nodes with exactly one round's story on the page — every save carried only the newest chapter, wiping the rest at exit 0. The owner reviewed that file on 2026-08-25 and directed the structural fix: one human node per agent node, append like `## Updates`. Rules that depend on agent discipline have now been bypassed three times (notes-as-bypass, newest-chapter-only, its recurrence); appending makes the loss impossible to write while the refresh keeps deliberate curation possible.

## How

The page's shape: the opening (from `work start`/`bug create`, or a legacy record's first touch) carries no heading; every appended telling is a `### <ts>` node so the human page pairs node-for-node with `## Updates`/`## Comments` by timestamp. Node edges are date-gated exactly as the agent side's entries are, so an author's own `### Background` subheading stays inside its telling and a dated heading inside a code fence is code. `WORDS_MAX` already bounded one telling and doctor already read `longest_telling`, so the ceiling machinery needed only the new edge. The once-dropped doctor heuristic (telling count vs update count) is now unnecessary — the pairing is structural. Existing records need no migration: their one blob reads as the opening and nodes accrue after it.

## For humans

The plain-language half of a work log kept losing its earlier chapters. In another project's record, WORK-0017, the technical half had grown to about twenty dated entries while the plain half held only the newest round's story — each save was a whole-page overwrite, and agents kept sending just the latest chapter, so everything before it vanished without a warning. An earlier fix, WORK-0087, only rewrote the instructions agents see; the file above is proof the instructions were not followed.

**The owner chose a structural fix over more teaching.** From now on, when an agent adds a progress note or a bug finding, the plain telling that must come with it is added to the page as its own dated entry — the same way the technical entries stack — instead of replacing the page. Finishing or abandoning a record adds the ending as the last entry. Deleting older tellings by accident is now impossible to do; merging them into one story is still possible, but only through a deliberate separate command that replaces the page on purpose.

**The reading screen keeps up.** The app now draws each dated telling under a quiet dated seam, numbers the story's beats straight through the page, and gives only the very first paragraph the large opening type.

**How we know it works.** All 205 Rust checks and all 209 checks of the agent-facing tool server pass, the three written copies of the style rules are byte-identical, and a scratch project run end to end shows a page that keeps its opening, gains one entry per note, gains the ending, and still collapses to one story when the deliberate replace is used.

A rule that only lives in instructions gets skipped; a rule built into the file format cannot be.
