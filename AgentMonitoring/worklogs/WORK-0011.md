## What

Rebuild the per-project dashboard so somebody who was not watching can open it and know
the current state of the project in seconds: a NOW strip (who is working right now and for
how long, open bugs by severity, what moved in the last 24 hours), a grouped-by-day
activity timeline, and three real charts (work completed over time, bugs opened vs
resolved, per-agent activity split). Every item on the screen links to the record behind
it. Also fix BUG-0006 — the Agents table amputated by its own card — and take the
dashboard exclusion out of `npm run check:clipping` so the gate covers it from now on.

## Why

The dashboard is the screen this app is judged against play.grafana.org on, and it was the
weakest screen in the product: five flat counters, a 14-row event dump with no day
structure, an agents table that ran off the edge of its card, and not one chart. The
numbers it did show were the ones easiest to compute, not the ones a reader needs — "72
recorded events" answers nothing, while "who is holding what right now, and how long has
it been going" is the question somebody opening this app actually has.

The clipping defect is the same class BUG-0004 was on the bug board: a fixed box with
`overflow: hidden` around content that does not fit, cutting mid-glyph with no ellipsis.
It was filed rather than fixed because the dashboard was about to be rebuilt; rebuilding it
is the moment to fix it, and to put the dashboard back inside the gate so it cannot happen
again.

## How

Charts are hand-written SVG — no charting dependency — following the data-viz rules:
sequential single-hue where the job is magnitude, categorical slots (in fixed order,
validated for colour-blind separation) only where the job is identity, 2px gaps between
touching marks instead of borders, hairline solid gridlines, values on the axis rather than
on every mark, and a hover/focus tooltip on every mark with a table-view twin so no value
is only reachable by hovering. Colours come from tokens.css and keep the meaning they have
everywhere else in the app: blue = in progress, green = done, purple = resolved, and the
severity ramp on severity.

Both projects have to look right, and their histories are different shapes: relay is three
weeks of ten agents, agent-monitoring is one working day of six. So the time axis picks its
own bucket — hours when the project's span is short, days when it is long — instead of
hard-coding a daily grid that would draw agent-monitoring as a single bar.

The clipping fix follows the bug board's: the agents table becomes a list of flex rows with
`min-width: 0` down to the name, so the name (which has an ellipsis and a tooltip) is what
gives way, sized from the project's own agent names via `src/lib/columns.ts`.

## For humans

A project's summary screen is where somebody who was not watching finds out what is going on. `src/pages/DashboardPage.tsx` had five plain counters, a dump of the last fourteen things that happened with no days in it, and not one chart. Its table of agents ran off the edge of its own card, cutting names mid-letter. That was `BUG-0006`.

**The top band answers "what is happening right now".** How many agents are holding unfinished work, each one with a clock counting up beside it and how long since anybody touched it. Then the bugs nobody has closed, as coloured buttons by seriousness, each one a way straight into the bug list already narrowed to those. Then the last twenty-four hours: a count, and a bar per hour so you can see when the day was busy. That band ignores the date range chosen below it, because now is not a range.

**The middle band is two charts.** Work started against work finished, and bugs filed against bugs fixed. The gap between each pair of lines is shaded, because that gap is what a reader came for: what is still running, what is still broken. They are running totals rather than a column per day — eight bugs over three weeks drawn as columns is mostly empty air. The dates along the bottom step in hours or in days depending on how long the project has existed, so a project one day old is not drawn as a single bar.

**The bottom band says who did it, and when.** One row per agent, with a bar split between work and bugs and measured against the busiest agent's total, and the same counts written out beside it. Below that, everything that has happened is cut into days: today is open, and each older day folds into one line carrying its count and who was in it. Every row on the screen goes somewhere — a work log, a bug, a narrowed list.

**The chart colours were measured, not picked by eye.** I ran them through a validator. That kind of tool checks whether colours stay far enough apart to be told apart, including by readers who cannot see some differences. It found this app's `--blue` and `--purple` are all but one colour under deuteranopia, a common form of colour blindness. They sit 0.5 apart there, where every other pair these charts draw together measures 19 to 27.

It is like two keys cut so nearly alike that half the building cannot tell which one opens which door.

So no chart here draws both. The trend is two charts of two lines each, not one of four.

**The table that amputated names is rebuilt.** The name gives way now, with a "…" and a hover label under it. `src/lib/columns.ts` sizes its column from that project's own names. That table had been left out of `npm run check:clipping`, which opens every screen at seven widths and reports text cut off or painted over. It is back inside that check, and passes. To be sure the check can still bite there I squeezed that table's columns to 300px: it reported four cuts, and reported none at the real width.

**Five smaller things came off the reviewers' list from the round before.** A web address naming somebody the project has never had — a filter for an agent who does not work here — used to leave you staring at an empty list; it now falls back to no filter at all. A bug's side panel names everyone who has spoken on it and who spoke last, with how long ago, read from the times written down, so a comment dated into the past cannot claim the last word.

In a narrow window a bug's seriousness keeps its first letter rather than dropping the word, so the row is never four colours and nothing to read. A record's id is tied to the last word of its title and can no longer be left stranded alone on a line — swept across all 41 records at 91 title widths, where the old markup strands it at 14 of them. And asking for a record that does not exist now says "This project has no BUG-9999", with a way back, instead of "Could not read the vault".

**I got four things wrong here, and a later reader wrote the corrections in rather than editing them out.** Two matter to you. `relay`, the companion project, has four agents and I wrote ten — counted in `BUG-0017`. And I promised that every value in a chart could also be read as a table, which was never built. What is true is weaker: every number a hover shows is also on the axis or in the key.

A colour two readers cannot tell apart is not carrying the meaning you gave it.
