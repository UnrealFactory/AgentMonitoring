## What

A fifth note type `essential` (ko 필수) — the MEMORY.md of a project: required reading before a session works, and the index that points at the rest. Every list surfaces essentials first: core sort (store.rs), CLI `note list` (plus a 'N essential note(s) — required reading' banner), MCP renderNoteList header ('read the N essential first'), the browser-mode middleware (project-fs.mjs), and the app's notes screen (new 필수 tab, red pill/dot). MCP server now sends initialize `instructions` telling clients to start sessions with note list and keep knowledge in notes, not model-side memory; the note tool's type enum gained essential with a one-line meaning. CLAUDE.md now says plainly: do not manage knowledge in your own memory — the notes ARE the memory; both generated claude-md templates (en/ko) say the same. Live data gained the first essential note, `start-here`.

## Why

Owner direction: the notes replace Claude's memory outright, and per-account model-side memory diverges when several accounts work one repo. What was missing versus a MEMORY.md was the required-reading entry point — a type, not a flag, so it reads as its own kind everywhere (tabs, pills, filters) at zero schema cost beyond the enum.

SPEC.md updated (five types, sort contract — deliberate SPEC change on owner request, recorded here). ## For humans

More than one account works on this project, and each kept its own private memory of what it learned. Those memories drift apart. The notes stored in the project are meant to be the one memory everybody shares. But a list ordered newest-first gives a fresh session nowhere to start.

**There is now a fifth kind of note, `essential` — 필수 in Korean.** It means: read this before you do any work. It is also the index, pointing at the others worth reading. The project's own notes gained the first one, `start-here`.

**Every list puts that kind on top, ahead of anything newer.** One ordering rule, `Store::notes()`, does it, and the notes screen, the command line, the agents' tools and the browser version all follow it. On the notes screen the kind also gets a tab of its own, 필수, and a red tag. `agentmon note list`, the command that prints a project's notes, now opens with a count: "1 essential note(s) — required reading".

**A kind, not a mark.** I could have flagged certain notes as important instead. As a kind, every screen that already sorts, tabs and filters by kind picks it up for free. It did change `SPEC.md`, the document that fixes what this project's data and screens must do — deliberately, at the owner's request.

**The reminder arrives before the first question now.** The moment an agent connects, the server handing it these tools sends one instruction. Start by listing the notes, and keep what you learn in them, not in your own memory.

**The standing orders say it too.** `CLAUDE.md` is the file an agent reads before it touches this repo, and its wording is now plain: do not manage knowledge in your own memory, the notes are the memory. The two starter copies of that file this app writes into a brand-new project, one English and one Korean, say the same thing.

It is like the safety card in the seat pocket — not filed with the reading matter, but where you cannot begin without seeing it.

**A new check pins the order.** `cargo test` runs 59 checks over the core. One of them writes an essential note beside a newer ordinary one, and insists the essential come out first. A list quietly falling back to newest-first would look right until that check ran.

The handbook asks agents to keep this kind rare. `check-i18n`, which reads every screen in each language, left seven advisory remarks about code names sitting inside Korean text.

Knowledge kept in private memories is not shared knowledge; it is several versions of it.
