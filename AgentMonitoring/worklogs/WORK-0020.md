## What

A Node stdio MCP server in `mcp/` that puts `agentmon` in an agent's tool list, plus its
test suite and `docs/MCP.md`. Five tools — `log_work`, `update_work`, `report_bug`,
`resolve_bug`, `status` — shell out to `target/release/agentmon.exe --json` and boil its
envelope down to a couple of lines. Identity (vault, default project, default agent) is
given once on the server's command line, so no call repeats it; `--vault` is required and
the CLI's `./vault` discovery is deliberately disabled. `npm test` in `mcp/` drives the
server over real stdio frames against a throwaway vault and asserts the budgets.

## Why

An agent that has to write `agentmon work start -p x --agent y --body "$(cat <<'EOF' ...`
gets the body contract wrong, loses the heredoc to its harness, or writes to whichever
`./vault` its working directory happens to contain. A tool call has none of those failure
modes: the three body sections are three required fields, and the vault is fixed at
startup.

The reason not to do the obvious thing — one tool per CLI command, schemas describing every
flag — is that a tool list is re-sent to the model on every turn of every conversation the
server is enabled in, and every result stays in the transcript for the rest of the session.
Sixteen tools with full flag documentation would cost more context per turn than the
records they write. So the budget came first and the feature list second: <= 6 tools,
<= 6 KB for the whole `tools/list` response, <= 600 characters for a result.

## How

Consolidation is by workflow rather than by command: `log_work` is `work start` and
`work done` in one call (leave the outcome off and it stays open under the id returned),
`resolve_bug` is `bug claim` + `bug comment` + `bug resolve` in one call, and `status` is
all four read commands behind a `mode` parameter. Prose is handed over on stdin via the
CLI's `--body-file -` family, so nothing has to survive a shell.

Nothing is validated twice. The server assembles the markdown body from what/why/how and
otherwise passes arguments straight through, so the timestamp rules, the state transitions,
the id allocation under lock and the body checks are the CLI's own. Failures come back as
the CLI's message with its exit code named, trimmed of the blocks that only make sense to a
shell caller (the "Example that works" heredoc, the markdown template this server writes
itself).

Result rendering is arithmetic rather than hope: a summary computes the room its fixed
lines leave and truncates the one elastic part (the outcome, or the report) to fit, so a
long title or a deep vault path shrinks the quote instead of blowing the budget.

## Updates

### 2026-08-19T11:13:00Z

Two defects in how the wrapper talks to the CLI, both found by reading `--help` output
rather than by a failing test, both fixed in `mcp/lib/cli.mjs`.

**Blanked environment variables are values, not absences.** The child was spawned with
`AGENTMON_PROJECT: ""` and `AGENTMON_AGENT: ""` to stop a stray export redirecting a write.
But clap reads an empty env var as an explicit empty value: `AGENTMON_PROJECT="" agentmon
work list --json` fails with `invalid id ''` rather than asking for `-p`. Harmless while
every call passes `-p` explicitly, and a trap for the first one that does not. They are now
deleted from the child environment instead of blanked.

**The body-rejection message is mostly for a shell caller.** Exit 4 prints the diagnosis
(`missing the ## Why section`), then the full markdown template, then a heredoc example —
about 1,500 characters, of which the first ~80 are the actionable part. An MCP caller
writes fields, not markdown, and has no shell, so the trim now cuts at `Expected structure`
as well as at `Example that works`. The diagnosis survives verbatim.

## Outcome

Shipped `mcp/` — an MCP stdio server over the agentmon CLI — with its test suite,
`docs/MCP.md` and a README section. `claude mcp add agentmon -- node
C:/Code/AgentMonitoring/mcp/server.mjs --vault <dir> --project <slug> --agent <handle>` is
the whole install.

**Five tools, not sixteen.** `log_work` (start and finish in one call, or leave the outcome
off to keep the id open), `update_work` (note, close, or abandon), `report_bug`,
`resolve_bug` (claim + comment + resolve in one call, any subset), and `status` (project
snapshot, work list, bug list, or one record, behind a `mode` parameter). Every call shells
to `target/release/agentmon.exe --json`, so nothing about the body contract, the timestamp
rules, the state machine or the locking is reimplemented here.

**Measured against the budgets, on the bytes that cross stdio.** The whole `tools/list`
frame, schemas and descriptions included, is 4,650 bytes against a 6 KB ceiling.
Descriptions run 66-159 characters, one verb-first sentence each, against a 200 limit. A
write returns 144-242 characters (id, file path, one line of confirmation); the largest
default read is 594 characters against a 600 ceiling, and `status(mode="view", full=true)`
is the only call allowed past it. The numbers are asserted, not documented: `npm test`
fails if any of them moves.

**Identity is configuration.** `--vault`, `--project` and `--agent` are given once at
startup and no call repeats them; a call may still override project or agent. `--vault` is
required and the CLI's `./vault` discovery is switched off — an MCP server's working
directory is whatever its client chose, so a fallback would let a real write land in a
vault nobody named. `AGENTMON_*` is stripped from the CLI child for the same reason.

**Verified.**

- `npm run check:mcp` — 85 assertions, 0 failed. It spawns the server, speaks raw
  JSON-RPC frames over stdio, and runs a full work lifecycle (open, note, close, correct a
  closed record, and a backdated one-call record), a full bug lifecycle (file, comment
  without claiming, then claim + comment + resolve), every read mode, and the error paths
  (exit 5 on a closed log, exit 3 on an unknown id, exit 2 on a future timestamp — which
  also asserts the rejected call left no file behind).
- `agentmon doctor --strict` over the vault the tests wrote — exit 0, no problems.
- Two guards on the live vault: the suite starts a server from the repository root with no
  `--vault` and asserts it refuses (exit 2) rather than finding `./vault`, and it
  fingerprints every file under `vault/` before and after and asserts nothing changed.
- Read-only probe against the live vault (19 work logs, 18 bugs): the snapshot renders in
  172 characters, `mode="view"` on WORK-0002 and BUG-0002 in 600 each.

## Alternatives considered

An MCP *resource* per record was the obvious way to expose reads. Rejected: resource lists
are another thing the client fetches and holds, and a vault of 19 work logs would put 19
descriptions in front of the model to say what one `status` call says on demand.

## For humans

An agent writing one of these records types a long command with the record's whole text wedged inside it. It gets the shape of that text wrong, or its surroundings swallow the text before the command runs, or it writes into whichever folder of records it is standing in.

**These records are now tools an assistant can call.** `mcp/server.mjs` sits between the assistant and `agentmon`, the command-line tool that writes the records. It speaks MCP, the usual way to hand a program to an assistant as a tool.

Five tools, not one per command: `log_work` and `update_work` write a piece of work and note something on one, `report_bug` and `resolve_bug` file and close a bug, and `status` reads the project. The three parts of a record — what, why, how — arrive as three separate fields, so the shape cannot come out wrong.

**The list of tools is re-read on every turn, so it costs rent.** The obvious build was one tool per command with every option spelled out: sixteen tools. That list would cost more room, turn after turn, than the records it writes. So the budget came first: six tools at most, 6 KB for the whole list, 600 characters for one answer.

It is like a menu you must read from the top before every bite.

**I turned down the obvious way to offer reading, too.** Every record could have been handed over as its own entry in a list the assistant carries. Nineteen work logs would then put nineteen descriptions in front of the model, all of the time, to say what one call to `status` says when it is asked.

**A blank setting is a value, not an absence.** The wrapper handed the tool an empty `AGENTMON_PROJECT`, the setting naming which project a write goes to, to stop a stray one in the surroundings redirecting a write. But the tool read that emptiness as an answer and called the name invalid, instead of asking which project.

Harmless while every call names its project; a trap for the first that does not. Those settings are deleted from the child now, and reading the tool's own help is what turned this up.

**The tool's refusal was written for a person at a terminal.** Turned down for a missing section, it prints the diagnosis, then the whole shape it wanted, then an example to paste into a terminal: around 1,500 characters, of which the first eighty are the part that helps. An assistant filling in fields has no terminal and no use for either extra. The wrapper cuts both now and passes the diagnosis on word for word.

**87 checks, none failed.** `npm run check:mcp` starts the server, talks to it exactly as an assistant would, and reads back every answer. It walks a piece of work from open to close, a bug from report to resolution, every way of reading, and the refusals. The sizes are measured, not just written down: the whole list is 4,650 bytes against a 6 KB ceiling, and the largest ordinary answer 594 characters against 600.

**Nobody repeats who they are or where to write.** The folder, the project and the agent handle are given once at startup. Started with no folder named, it refuses rather than guessing, so a real write cannot land in records nobody chose.

**Installing it is one line.** One command registers the server with the assistant and hands it those three things at the same time. `docs/MCP.md` is the page that describes it, and the repository's front page points at that page.

A list of tools is read again on every turn, so every word in it is paid for twice over.
