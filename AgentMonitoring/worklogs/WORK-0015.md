## What

Round 3 of the shell/portability piece: make the command palette a real modal — one that
keeps its keys wherever focus is and cannot be escaped from by accident — stop the sidebar
claiming the reader is in two places at once, and bring browser mode's vault reader to CRLF
parity with agentmon-core.

## Why

The round-2 design critic failed the piece on the palette: Escape/arrows/Enter were bound to
the search input alone, the result rows were tab stops, and one Tab was enough to leave the
dialog unable to close from the keyboard while the arrows drove the list screen behind the
scrim (Enter there navigated the page underneath). Against linear.app's own Cmd+K that is a
loss. The same critic found two rows carrying aria-current="page" on /projects when the
sidebar overflows to "<N> more…". The portability critic's biggest gap is CRLF: vault-fs.mjs
keeps \r where crates/agentmon-core strips it, so a vault cloned on Windows with
core.autocrlf=true renders with its dashboard notes collapsed into one paragraph — the exact
sentences earlier rounds worked to surface.

## How

Palette: options become non-tabbable li[role=option] driven by aria-activedescendant from a
combobox input; Escape/arrows/Enter/Tab move to a window-level capture handler guarded by
open, so they work from anywhere and cannot reach the page below; focus is trapped in the
dialog and restored to whatever had it on close. A module-level modal lock (src/lib/modal.ts)
makes useListKeyboard stand down while any modal is open. Sidebar: the overflow row stops
being a NavLink. Parity: one normalisation of \r\n at every file read in vault-fs.mjs. New
headless gate scripts/check-keys.mjs proves the keyboard contract; check:vault grows a CRLF
parity case.

## Updates

### 2026-08-19T02:00:00Z

The palette is a modal now, in the sense the word is supposed to carry.

Its keys are bound to `window` in the **capture** phase for as long as it is open, so esc,
the arrows, Home/End and ↵ are answered wherever the focus is and `stopPropagation` keeps
them off the screen behind the scrim. The result rows stopped being `<button>`s: they are
`li[role=option]` the input names with `aria-activedescendant`, which is the standard
combobox pattern and removes the tab stops that let the focus out of an `aria-modal`
dialog in the first place. Tab is trapped inside the dialog and wraps; a focus that lands
outside by any other route is pulled back by a `focusin` guard; and on close the keyboard
goes back to whatever had it before Ctrl+K.

The other half of the same defect was that the two list screens' `window` keydown handler
had never heard of modals: with the palette open, ↓ moved the *board's* cursor and ↵
navigated it. src/lib/modal.ts is now a module-level lock (`isModalOpen()`, mirrored onto
`<html data-modal="open">` so gates and CSS can see it), and useListKeyboard stands down
while it is held.

New gate: `npm run check:keys` (scripts/check-keys.mjs), 44 checks. It reproduces the
critic's exact route — Ctrl+K, one Tab, three ArrowDowns, esc — on /p/relay/bugs?tab=all,
a work detail and /projects, and also drops the focus on `<body>` and presses the same keys
from there. Proved it has teeth twice: removing the modal lock fails "the list cursor
behind the scrim did not move"; making the palette answer only events targeted at its input
fails all three "esc closes it with the focus dumped on body".

### 2026-08-19T02:07:00Z

Sidebar: the shell no longer says you are in two places at once, and the gate found two
cases where it did rather than the one that was reported.

Reported: with more than 8 projects the "<N> more…" row was a NavLink to /projects, so on
/projects both it and "Projects" carried aria-current="page". Found while writing the gate:
the vault footer at the bottom of the column is also a link to /projects and was also a
NavLink — a third row lit on the same screen; and the project rows under VAULT were
NavLinks that match by prefix, so standing on /p/relay/work lit both "Work" and "Relay".

Rule applied: exactly one element may claim aria-current="page", and it is the nav item
that names the screen. The project rows are places in the vault, not screens, so they carry
aria-current="location" when you are inside them (still one, and a different fact). The
overflow row and the vault footer are plain links that mark nothing; the overflow row now
reads "<N> more on Projects…" so it says where it goes.

check:keys asserts this on /projects, /p/relay, /p/relay/work and /p/relay/bugs, and on a
scratch 12-project vault built in a temp dir with the real CLI (never ./vault), where the
sidebar lists 8 + an overflow row.

Also in this pass, all from the round-2 critic's nit list: the switcher menu is a real
role="menu" (arrows walk it, Home/End jump, esc closes it and hands focus back to the
button, Tab leaves); the project rows' "2 open" count has the title every other count in
the column already had.

### 2026-08-19T02:12:00Z

Portability: browser mode now reads CRLF the way agentmon-core does.

`scripts/vault-fs.mjs` had one raw `readFileSync(path, "utf8")` per record type; the Rust
core parses with `str::lines()`, which drops the `\r`, and the JS twin kept it all the way
to `noteOutline()` in src/lib/dashboard.ts, which splits paragraphs on /\n{2,}/ — never
true of `\r\n\r\n`. Same vault, two transports, and the browser lost exactly the sentences
the last two rounds worked to surface. Every text read now goes through one `readText()`
that normalises `\r\n`, and the exported `splitFrontmatter()` normalises too, because it
can be handed a string that never came from the reader.

check:vault grew three cases (32 checks now): a CRLF copy of the whole vault — 55 files
converted, which is what `git clone` on Windows with core.autocrlf=true produces — must
serve payloads byte-identical to the LF original on all 11 list routes and 12 record
bodies, with no carriage return in any decoded value. Sabotaged the normalisation to prove
the gate bites: 3 failures, 7/11 and 0/12.

Carried over in the same pass:
* a record deleted under an open detail page now says so (StaleRecordBar, the shell's amber
  bar one page down) instead of rendering the deleted copy indefinitely — useAsync keeps the
  status of a failed *refresh* so the bar can say "no longer in this vault" rather than
  blaming the vault;
* desktop mode has the health half of subscribeVaultChanges it was missing: a 15s heartbeat
  read, because a notify watcher on an unplugged drive stops firing rather than failing, and
  browser mode could say so where the product could not;
* the "no vault open" screen prints the real directory in its `agentmon init` line (taken
  from the message the backend wrote) and no longer points at a "New project" button that
  is not on that screen; backticked commands in backend errors render as code instead of
  printing backticks;
* an archived project's row no longer shows a live dot and "Active just now" — archiving is
  itself an event, and it was the event lighting the dot;
* the Open bugs card gives a title three lines before clamping, which is what this vault's
  longest titles need, in space the card already had.

## Outcome

### Shipped

**The palette is a modal.** Escape, ↑ ↓, Home/End and ↵ are bound to `window` in the capture
phase while it is open, so they work wherever the focus is and never reach the screen behind
the scrim; the result rows are `li[role=option]` named by `aria-activedescendant` from a
`role=combobox` input, so there are no tab stops inside the dialog at all; Tab is trapped and
wraps; a focus that escapes by any other route is pulled back; the keyboard goes home when
the palette closes. src/lib/modal.ts holds a module-level modal lock (mirrored on
`<html data-modal="open">`) and src/lib/useListKeyboard.ts stands down while it is held, which
is what stopped the arrows driving the bug board behind the palette and ↵ navigating it.

**One place at a time.** aria-current="page" is now carried by exactly one element on every
screen: the nav item that names the screen. The sidebar's "<N> more on Projects…" row and the
vault footer are plain links (both were NavLinks to /projects, so /projects lit three rows at
once), and the vault's project rows carry aria-current="location" — where you are in the
vault, a different fact from which screen you are on — instead of matching by prefix and
lighting "Relay" as the current page while standing on /p/relay/work.

**CRLF parity.** scripts/vault-fs.mjs reads every file through one `readText()` that
normalises `\r\n`, matching `str::lines()` in agentmon-core. A vault cloned on Windows with
core.autocrlf=true renders identically in browser mode now; it used to lose every paragraph
break in the dashboard's note outlines, which is exactly the material the P4 round wanted
surfaced.

**Also:** switcher menu answers its arrows (Home/End/esc/Tab too, esc hands focus back);
a record deleted under an open detail page says so instead of rendering the deleted copy for
ever; desktop mode has the health heartbeat browser mode already had; the "no vault open"
screen prints the real directory and renders backticked commands as code; archived projects
stop claiming to be live; open-bug titles get three lines in space the card already had;
the nav project rows' bug counts carry the title every other count has.
