## What

CLAUDE.md's notes bullet and the MCP note tool description now state the curation contract explicitly: the notes are the agents' persistent memory across sessions, so keep them current — rewrite a note when work changes the fact it states, remove one that would now mislead. The MCP type field also gained one-line meanings (memory: durable gotcha/how-to · handoff: state for whoever continues · decision: settled choice and why · reference: pointer to a resource), which were previously only in docs/AGENT_MANUAL.md.

## Why

User observation: the notes replace Claude's memory, but the two places agents actually read on session start (CLAUDE.md, the MCP schema) never said to maintain freshness or delete stale knowledge — the manual's 'stale knowledge misleads' rule lived three hops away.

## How

CLAUDE.md bullet rewritten around 'curate, don't hoard'. mcp/lib/tools.mjs note description rewritten within the test's contract (<=200 chars, one sentence, opens with an allowed imperative — 'Share'); type enum got a description. tools/list frame 6856/7168 bytes.

## Outcome

Shipped. mcp npm test 115/115 green — the description-budget checks (200 chars, one sentence, verb-first, 7KiB tools/list) all pass; first draft failed them and was tightened, which is what the checks are for.

## For humans

The agents that build this project keep nothing in their own memory from one session to the next. What they know lives in shared notes, written by whoever worked last. So a note gone out of date is not just a stale document — it is the next agent's memory, and it is wrong.

A rule about that already existed. It sat in `docs/AGENT_MANUAL.md`, the long handbook, three steps away from the two things an agent actually opens when a session starts.

**The rule now sits where the session starts.** I rewrote the notes paragraph in `CLAUDE.md`, the file an agent reads when it opens this project, around one line: curate, don't hoard. If your work changes a fact a note states, rewrite that note before you finish. If a note would now mislead, remove it. The blurb on `note`, the tool an agent writes notes with, says the same.

It is like a house rule that was pinned up in the basement and is now on the front door.

**Each kind of note explains itself on the spot now.** Filing a note means picking a kind, and each kind now carries its meaning in one line. Memory holds a lasting how-to or a trap that catches people. Handoff holds the state of things for whoever continues. Decision holds a settled choice and why, and reference points at a resource.

Those four lines lived only in the handbook before.

**That blurb has a hard budget, and my first try broke it.** It must be one sentence, under 200 characters, and open with one of a short list of verbs. All the tool blurbs together must fit inside about 7 kilobytes. I tightened the wording in `mcp/lib/tools.mjs` until it fit, which is what a limit is for. `npm test`, which guards those tools, then passed all 115 of its checks, the budget ones included.

**There is not much room left.** The blurbs together now measure 6,856 bytes against a ceiling of 7,168 — roughly 300 to spare for whatever gets described next.

Knowledge nobody prunes stops being knowledge and turns into a rumour with a date on it.
