## What

Draw each dated telling in the Human view as a card mirroring the agent timeline's `.update-card`: a header strip with a node number (`view.tellingN` — ko "N번째 노드", en "node N") and the node's local time + relative time (UTC on hover), the telling inside (`.human-telling` / `-head` / `-body` in app.css; HumanStoryView refactored so the opening renders bare on the sheet and dated tellings render inside cards via one shared `storyBlocks`). Also repair scripts/ko-vault.mjs: five `--message` calls carried no `--human`, refused by the CLI since the 2026-08-24 rule — check-i18n swallowed the ko-vault exception as a finding and still exited 0, so it sat unnoticed.

## Why

Owner feedback on the first shipped seam (a hairline with a date): the boundary between tellings did not read, and the agent half already draws the paired note as a numbered card — symmetry ("1번째 노드" on both sides = the same event, same timestamp) is both the clearer boundary and the pairing made visible. Node numbers count dated nodes only and run chronologically like the agent side's; the opening is the page's own start, not node zero.

## How

The card reuses the update-card recipe (border, header strip at rgba .015, body padding) sized for the reading sheet; beat numbers still run through the whole page; the first beat inside a card drops its divider hat (the header is the edge). The ko-vault repair adds each note's own Korean telling per the append model — the fixture now exercises the real rule instead of bypassing it.
