## What

crates/agentmon-core/src/feedback.rs — FB-NNNN.md files in ~/.AgentMonitoring/feedback
(beside the registry, same AGENTMON_REGISTRY_DIR override), frontmatter id/title/type
(bug|idea)/agent/status (open|done)/created/done + free prose body, ids under the
folder's lock, atomic rewrites, open-first newest-first ordering. CLI: agentmon
app-feedback add/list/view/done/reopen — machine-level, works from any directory, no
--dir. MCP: a seventh tool, app_feedback (type, title, optional body — and no dir, the
one tool without it); tools/list grew 6,070 → 6,664 bytes against a budget raised

browser middleware (answered before any project resolution, so it works with zero

open count. Both CLAUDE.md templates now point agents at app_feedback for complaints

reference) updated; check-i18n walks the new screen, exempts feedback titles/bodies as
author content, and knows MCP / app_feedback as technical tokens.

## Why

The owner wanted one place to read what agents wish this app did and where it failed
them, then work through it — and filing had to be mistake-proof about scope, which named
the thing: app_feedback, not feedback, because a tool named feedback would collect
project feedback (owner's own catch). Machine-level rather than in any project because
the subject is this install of the app; storing it in a repo would make app feedback
travel with whichever codebase happened to host it.

## How

The store is the project store's rules at small scale — create_new ids under the lock,
temp-and-rename writes, done as a state change instead of a delete (what was asked for
stays evidence). agent/human split by convention and affordance: the tool and CLI add
file items; done/reopen live on the board and in two human-shaped CLI verbs. The first
test run leaked two items into the real ~/.AgentMonitoring: unit tests sandboxed via the
process-global AGENTMON_REGISTRY_DIR env while the registry's own corrupt-file test
mutated the same variable from a parallel thread. Fixed by refactoring the module to
explicit-directory functions (add/list/view/set _in) with the env read confined to
one-line wrappers — tests now touch no global state; the leaked files were deleted.

## For humans

The owner wanted one place to read what agents wish this app did and where it let them down, then to work through that list.

**Agents can now file a complaint about the app itself.** It is a fourth kind of record; the other three describe a project. The agent calls one tool, `app_feedback`, with a kind — bug or idea — a title and as much prose as it likes. The item lands in a folder in your own user account, beside the list of projects kept there, and a new screen shows them all, still-open first.

**It is called `app_feedback` because `feedback` alone would have collected the wrong thing.** An agent reading a tool named feedback files feedback about its project instead. The owner caught that. The items sit on the machine rather than in a repository, because the subject is this installation; a complaint kept in a repository wanders off with the codebase holding it.

**The first test run put two made-up items into the real folder.** The tests were meant to work in a throwaway one, and they said so by setting one value the whole running program shares: `AGENTMON_REGISTRY_DIR`, the setting that names which folder to use. Another test, running at that moment, set the same value to something else.

It is like one signpost telling a building which room to leave papers in. Someone turns the sign while another person is still walking down the corridor.

**Now each step is handed the folder to work in.** Only a thin outer layer still reads that shared setting, the tests never touch it, and I deleted the two items that had leaked.

**Then I drove it layer by layer.** `cargo test`, every test written against the Rust code, passes 113: a complaint gets an id, and it refuses to be closed twice. `check:mcp` exercises the tools agents call and passes 114, one of them watching where a filed item lands — beside the throwaway folder, never in the project.

Playwright drove a real browser through the board: two items with their kind labels, Mark done pressed, the row dimmed and sank.

**An agent that hits a wall in this app now has somewhere to say so.** The `CLAUDE.md` an agent reads on arrival points it there. Filing is all a tool can do; closing an item is a person's move on the board, or a typed command. `check:keys`, the one over menus and keyboard shortcuts, went unrun, because this screen adds neither.

A complaint nobody can file is a complaint you never get to fix.
