## What

Per-history-entry scroll restoration for the app's one scroller (#main): going Back (Alt+Left, gesture L, forward too) returns the list to the exact scroll position it had, instead of the top. A fresh navigation (PUSH) now explicitly starts at the top, which also fixes the latent bug of a detail page inheriting the list's scroll offset. Filter changes (replace: true in useUrlFilters) keep the scroll where it is.

## Why

The human hit it immediately after gestures shipped: scroll down a list, open the 7th record, gesture back — and the list is at the top again, so the place they were reading is lost. The scroller is #main (not the window) and list data loads async, so the browser clamps scrollTop to the skeleton's height and the position is destroyed; no router default can fix a custom scroll container.

## How

src/lib/useScrollRestoration.ts, called once from the Shell: a module Map keyed by location.key, fed by a passive scroll listener; on POP the saved position is re-applied patiently (rAF retries until the async content is tall enough, abandoned on reader input or after a deadline), on PUSH the scroller is reset to 0, on REPLACE the current position is re-keyed to the new entry.

## Outcome

Shipped src/lib/useScrollRestoration.ts, called once from the Shell: positions per location.key in a module Map fed by a passive scroll listener on #main; POP re-applies the saved position with rAF retries until the async content is tall enough (abandoned on the reader's wheel/pointer/key or after 3s), PUSH resets to top (also fixes a detail page inheriting the list's offset), REPLACE re-keys the position and writes nothing so filter typing never yanks the board (Chrome's own scroll anchoring may lawfully adjust the number when rows above the fold disappear). Verified with Playwright on the live tauri:dev server: scroll list to 700 -> open a visible record (opens at top) -> Back restores 700 across the async re-fetch -> Forward restores the record's own 200 -> filter typing does not send the board to the top -> zero console errors; tsc + vite build clean. En route the verification exposed BUG-0025 (dev-server file watching dead: the '**/AgentMonitoring/**' ignore glob matched the repo root itself, so every running dev session served stale transforms) — fixed in vite.config.ts by anchoring the pattern to the repo root's data folder, proven by a live add/remove probe reflected in 2s without restart.
