## What

Both CLAUDE.md templates (crates/agentmon-core/templates/claude-md.{ko,en}.md) gained a
closing section: if log_work is not in the tool list, the agentmon MCP server is not
registered — register it yourself with `claude mcp add agentmon --scope project -- node
<AgentMonitoring>/mcp/server.mjs --dir <repo> --agent <handle>`, or ask the human; tools
appear from the next session. The AGENT_MANUAL init paragraph names the addition.

## Why

WORK-0042 shipped instructions that assume the MCP tools exist, but registration is a
separate manual step, so a repo whose human skipped `claude mcp add` had agents reading
orders for tools they do not have — and silently ignoring them. The owner asked for the
guidance to live at the end of the file so the agent resolves the gap itself. The exact
server path is machine-specific, so the command carries placeholders rather than a path
that would be wrong on every other machine; --scope project is shown because a committed
.mcp.json makes the registration travel with the repo, with the drop-it alternative
named for a private one.

## How

Static template text only — no substitution machinery for the server path, deliberately:
the CLI cannot know where a bundled install keeps mcp/server.mjs, and a confident wrong
path is worse than a placeholder the agent fills by finding the folder.

## Outcome

Template tests still pass (marker heading, six tool names, both languages distinct);
release CLI rebuilt with the embedded templates, and a scratch init --claude-md ko now
ends with the new section, fenced command intact. No UI or gate surface touched.
