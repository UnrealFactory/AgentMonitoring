## What

Both CLAUDE.md templates (crates/agentmon-core/templates/claude-md.{ko,en}.md) gained a
closing section: if log_work is not in the tool list, the agentmon MCP server is not
registered — register it yourself with `claude mcp add agentmon --scope project -- node
<AgentMonitoring>/mcp/server.mjs --dir <repo> --agent <handle>`, or ask the human; tools
appear from the next session. The AGENT_MANUAL init paragraph names the addition.

## Why

WORK-0042 shipped instructions that assume the MCP tools exist, but registration is a
separate manual step, so a repo whose human skipped `claude mcp add` had agents reading
orders for tools they do not have — and silently ignoring them. The owner asked for the
guidance to live at the end of the file so the agent resolves the gap itself. The exact
server path is machine-specific, so the command carries placeholders rather than a path
that would be wrong on every other machine; --scope project is shown because a committed
.mcp.json makes the registration travel with the repo, with the drop-it alternative
named for a private one.

## How

Static template text only — no substitution machinery for the server path, deliberately:
the CLI cannot know where a bundled install keeps mcp/server.mjs, and a confident wrong
path is worse than a placeholder the agent fills by finding the folder.

## Outcome

Template tests still pass (marker heading, six tool names, both languages distinct);
release CLI rebuilt with the embedded templates, and a scratch init --claude-md ko now
ends with the new section, fenced command intact. No UI or gate surface touched.

## For humans

Some agents were reading orders they could not carry out. Their instruction file told them to file every piece of work through this app's tools. Where nobody had connected the app to the agent, those tools were not there, and the agent quietly did nothing about it.

**Making that connection is a separate step a person has to take.** We had already shipped the orders, and skipping the wiring left no warning anywhere the agent would look.

It is like leaving a new worker a note that says to write every job in the office ledger, in an office where nobody put a ledger out.

**The file now ends by telling the agent how to check, and how to fix it.** Both language versions of `CLAUDE.md` — the instruction file this app writes into a repository for agents to read — gained a closing section. If `log_work`, the tool that files a record of work done, is not in your list of tools, it says, the connection was never made. Then it gives the command that makes it, `claude mcp add`, and says the tools arrive from your next session. Failing that, ask the person.

**We refused to print a real path in that command.** It carries blanks where the folder names go. No copy of the app can know where another machine keeps the small program that serves those tools, and a confidently wrong path is worse than a blank someone can fill in.

**I generated the file and read the end of it.** The template text is baked into the command-line tool, so I rebuilt that first, then had it write a throwaway Korean copy with `agentmon init --claude-md ko`. The new section was there, the command intact inside its box. The template tests still pass: they look for a heading that must be present, for all six tool names, and for the two languages differing.

**An agent landing in an unconnected repository now has a way out.** The owner wanted the guidance at the end of the file for exactly that. Nothing on the app's screens changed, and someone still has to go and find that folder by hand.

An instruction only works if the reader can tell when it is impossible.
