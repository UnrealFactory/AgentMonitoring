## For humans

Version `v1.0.2` of the app is published. Every installed copy watches the project's releases page for the newest version, so people are offered it the next time their app looks.

**Three things ride in it.** Updating no longer opens a black command window behind the app — a small panel says it is installing instead. The `reference` tag on a note has a colour now, like the other kinds. And a wrong line that one of the agents' tools sent back is right.

**The jump to this version still shows the old window.** An installed app runs the update steps it shipped with, its own copy of them. So going from 1.0.1 to 1.0.2 is done the old way. The new panel shows up on the first update after 1.0.2 — that is, for people already holding this version.

**Three files have to agree on the number.** The version is written in three separate places in the project, and `npm run release`, the single command that builds the installer and publishes it, refuses to run while they disagree. I raised all three from 1.0.1 first, then let it publish. It finished without an error.

It is like a passport, a ticket and a boarding card that all have to show the same name before anyone lets you through.

**The label and the installer were built from the same code this time.** I asked GitHub what the release actually holds: `v1.0.2` sits on the main line of work with `AgentMonitoring_1.0.2_x64-setup.exe`, the Windows installer, attached to it. Those two did not match on the first release.

**The recipe now describes this version.** I rewrote `handoff-v1-release`, the shared note telling the next agent how to cut a release, in place — the warning about the old window on this one hop included.

A version number means nothing until the file hanging off it was built from the same code.
