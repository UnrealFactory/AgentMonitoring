## What

The human area is now a real part of the record format, enforced on every write path.

`crates/agentmon-core/src/human.rs` owns it: `split()` cuts the reserved `## For humans`
section off a body (code-fence-aware, the same rules `body.rs` splits sections by),
`attach()` puts it back as the last section, `require()` validates supplied text, and
`reject_reserved()` refuses agent prose that carries the heading. `build.rs` extracts the
compact rules from between the `<!-- compact-rules -->` markers in docs/HUMAN_STYLE.md at
build time, so the rejection text and the doc cannot drift.

Models gained `human: Option<String>` on the worklog, bug and note summaries and details
and on `FeedbackItem`; `store.rs` splits the section out on read (so `body` is the agent
area only, per SPEC) and feeds it into `search_text`. `write.rs` enforces the matrix:
required on start/done/abandon/create/resolve/note add/note update --body/app-feedback
add, replaced by the closing verbs, required on the first touch of a record that has
none, and accepted alone as a refresh that logs one `human_updated` event and writes
nothing into `## Updates` / `## Comments`. `doctor` reports records without one as a
single warning plus a complete `missingHuman` list in `--json`.

The CLI gained `--human` / `--human-file` on every verb that writes prose (including
`bug claim`, for the legacy-touch rule), `agentmon human-style`, a stdin-collision
refusal, and a `## For humans` block in `work/bug/note/app-feedback view`. The MCP tools
carry a `human` field with the same required-ness and pass it through to the CLI, so the
enforcement is not duplicated. Browser mode's reader (scripts/project-fs.mjs) parses the
section the same way, and `src/lib/types.ts` carries `human: string | null`.

## Why

An owner directive (SPEC "The human area"): every record has to speak to the person who
paid for the work as well as to the next agent. Enforcement had to live in agentmon-core
rather than in the CLI, because the CLI, the MCP server and the desktop app are three
mouths on one throat — a rule in the wrapper is a rule an agent can walk around.

Reading stays lenient because 98 live records predate the feature and must keep rendering;
writing does not, because a record that is allowed to skip the human area will skip it.

## How

The refusal is the delivery mechanism: `CoreError::MissingHuman` prints what is wrong, the
exact flag to pass, the compact rules cut out of docs/HUMAN_STYLE.md at build time, and
one line naming `agentmon human-style`. Exit 2, per SPEC. `mcp/lib/cli.mjs` lets that one
message through its 600-character trim so a rejected MCP call carries the rules too.

The refresh (`--human` alone) exists so a legacy record can gain a human area without
inventing a progress note that never happened; it logs `human_updated` instead, which is
a new event type — added to `doctor`'s known list, to the SPEC event list, and to the
app's event vocabulary in both languages.

## For humans

Until now a record here was file names, flags and commands. It was written for whichever agent came next, and unreadable to the person who paid for the work. The owner's rule is that every record must speak to both. This work turned that rule into something the program refuses to break.

**Every record now ends in a plain-language half.** It sits under a heading the program reserves for itself, `## For humans`. An agent that writes that heading into the technical half is turned away. Starting a job, finishing one, filing a bug, closing one, writing a note: none of them save unless the plain half comes too.

**The check sits underneath all three ways in.** The command line, the MCP server an agent calls, and the desktop window all write the same records. All three stand on one shared piece of code, and `crates/agentmon-core/src/human.rs` is where the check went. A check placed in any one of the three is one an agent walks around by using another.

**The refusal is where the teaching happens.** When it says no, it prints what is missing and the exact option to pass. It also prints the short form of the writing rules, cut out of `docs/HUMAN_STYLE.md` at the moment the program is built, and names `agentmon human-style`, the command that prints them in full. So what an agent is shown cannot drift from what is written down.

It is like a returned form that comes back with the instructions printed on the envelope.

**Reading stayed forgiving on purpose.** Records written before this still open without a plain half. But the first time anything touches one, the missing half has to be supplied. An agent that only wants to improve the wording hands in the plain text alone, which rewrites the retelling and nothing else; the record's own history gains one line saying the retelling changed, rather than a progress note about work nobody did.

**Two things here bend the written contract, and both are set down in this record.** `SPEC.md` fixes what this app's commands must offer, and it lists no way to hand in a plain half when an agent claims a bug — but the rule says any change to a record lacking one must supply it, so claiming an older bug would have been a dead end. That verb takes the plain text now. The other is a size limit: six of the tools an agent is offered each gained the new field, and the list of them outgrew the 7 kilobytes allowed for it, so the allowance moved to 7.5 and the list measures 7,463 bytes. The writing rules themselves are not in that list at all.

**On prepared test records I compared the two paths field by field: identical.** One is the desktop path through that shared code; the other is `scripts/project-fs.mjs`, the reader behind the browser version. `cargo test --workspace` passes 147 checks, and `check:mcp` passes 139 against the tool server.

**Live records were not in that comparison.** `doctor`, the command that reads every record here and reports what is broken, simply warns that 98 of them still speak to one audience. Filling those in is nobody's work yet.

A rule that cannot refuse you is a suggestion.
