## What

The human area is now a real part of the record format, enforced on every write path.

`crates/agentmon-core/src/human.rs` owns it: `split()` cuts the reserved `## For humans`
section off a body (code-fence-aware, the same rules `body.rs` splits sections by),
`attach()` puts it back as the last section, `require()` validates supplied text, and
`reject_reserved()` refuses agent prose that carries the heading. `build.rs` extracts the
compact rules from between the `<!-- compact-rules -->` markers in docs/HUMAN_STYLE.md at
build time, so the rejection text and the doc cannot drift.

Models gained `human: Option<String>` on the worklog, bug and note summaries and details
and on `FeedbackItem`; `store.rs` splits the section out on read (so `body` is the agent
area only, per SPEC) and feeds it into `search_text`. `write.rs` enforces the matrix:
required on start/done/abandon/create/resolve/note add/note update --body/app-feedback
add, replaced by the closing verbs, required on the first touch of a record that has
none, and accepted alone as a refresh that logs one `human_updated` event and writes
nothing into `## Updates` / `## Comments`. `doctor` reports records without one as a
single warning plus a complete `missingHuman` list in `--json`.

The CLI gained `--human` / `--human-file` on every verb that writes prose (including
`bug claim`, for the legacy-touch rule), `agentmon human-style`, a stdin-collision
refusal, and a `## For humans` block in `work/bug/note/app-feedback view`. The MCP tools
carry a `human` field with the same required-ness and pass it through to the CLI, so the
enforcement is not duplicated. Browser mode's reader (scripts/project-fs.mjs) parses the
section the same way, and `src/lib/types.ts` carries `human: string | null`.

## Why

An owner directive (SPEC "The human area"): every record has to speak to the person who
paid for the work as well as to the next agent. Enforcement had to live in agentmon-core
rather than in the CLI, because the CLI, the MCP server and the desktop app are three
mouths on one throat — a rule in the wrapper is a rule an agent can walk around.

Reading stays lenient because 98 live records predate the feature and must keep rendering;
writing does not, because a record that is allowed to skip the human area will skip it.

## How

The refusal is the delivery mechanism: `CoreError::MissingHuman` prints what is wrong, the
exact flag to pass, the compact rules cut out of docs/HUMAN_STYLE.md at build time, and
one line naming `agentmon human-style`. Exit 2, per SPEC. `mcp/lib/cli.mjs` lets that one
message through its 600-character trim so a rejected MCP call carries the rules too.

The refresh (`--human` alone) exists so a legacy record can gain a human area without
inventing a progress note that never happened; it logs `human_updated` instead, which is
a new event type — added to `doctor`'s known list, to the SPEC event list, and to the
app's event vocabulary in both languages.

## For humans

Every record in this app is written by an agent, for agents. That is fine for the next
agent, and useless for the person who paid for the work: a page of file paths and flags
does not tell you what changed or whether it worked.

So every record now has a second half — a plain-language telling of the same events,
written by the agent that did them, at the moment it writes the record. This piece is the
plumbing for that: where the text is kept, and what the tool does when an agent leaves it
out.

It is kept as the last part of the record file, under a heading the agent is not allowed
to write itself. Reading is forgiving — the 98 records this project already had do not
have one, and they still open normally, with the app simply saying so. Writing is not
forgiving: starting a piece of work, finishing it, filing a bug, closing a bug, writing a
note — all of them now refuse to save unless the plain-language half comes with them.

The refusal is the interesting part. Rather than saying "missing field", it prints the
short version of the writing rules and points at the full contract, so the agent that got
it wrong learns how to get it right in the same breath. That text is cut out of the
contract document when the program is built, so the rules an agent is shown can never
drift from the rules that are written down.

Two things we had to be careful about. A record that was written before all this exists
must not be edited by an agent that then declines to say anything to the human — so the
first time anything touches an old record, it has to add the missing half. And an agent
that only wants to improve the wording should not have to invent a fake progress note to
do it: passing the plain-language text on its own rewrites just that, and the activity
feed gets one line saying so.

How we know it works: 147 automated checks across the Rust code, twelve of them written
for this feature alone (the refusals, the old-record rule, the one-line-per-refresh rule,
the reserved heading, both ways of reading a record), plus 139 checks against the tool
agents actually call, and a side-by-side comparison proving the desktop app and the
browser build report exactly the same thing. The health check now lists the 98 old records
that still speak to only one audience; filling those in is the next piece of work.
