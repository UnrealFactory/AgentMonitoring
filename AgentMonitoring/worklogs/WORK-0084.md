## What

Four fixes in one pass — the open updater bug and three tool complaints (the owner handed
two over from the app-feedback board, one relayed from another session):

- src-tauri/src/update.rs (BUG-0029): the update check no longer GETs the rate-limited
  Releases API. `latest_tag()` reads the newest tag out of the un-metered
  `github.com/<repo>/releases/latest` redirect (ureq `redirects(0)`, `Location` header);
  `find_installer()` HEADs the conventional asset URL scripts/release.mjs uploads
  (existence + Content-Length as size, also un-metered); `release_notes()` is the one
  remaining API call and is best-effort — a spent quota now costs a blank tooltip, never
  the card.
- mcp/lib/tools.mjs (owner-relayed): `note(action="write")` on an existing note now
  treats an explicit empty `tags`/`refs` array as "clear the list" (`replaceListFlag`
  passes `--tags ""` through; the CLI already honored it) — a field left off still means
  "don't touch".
- mcp/lib/tools.mjs + format.mjs (FB-0003): `full: true` reads (`status(mode="view")`,
  `note(action="read")`) are no longer truncated; `FULL_CAP` is gone. The human area is a
  record's last section, so the old 8000-char clamp cut exactly what the read was for.
- mcp/lib/tools.mjs (FB-0002): a call whose field carries leaked tool-call markup (a
  literal `<parameter …>` tag, or a field containing its own closing tag) is refused
  whole before any step runs. Also repaired the one damaged record on disk —
  C:/Code/ElmwoodOnline/AgentMonitoring/bugs/BUG-0001.md carried a literal `</comment>`
  plus the whole resolution duplicated inside its Comments section; spliced out, backup
  kept, record re-parsed clean.
- docs/MCP.md updated for all three MCP behavior changes.

## Why

BUG-0029 was left open on purpose with the fix named. The unauthenticated GitHub API
allows 60 requests/hour per address; release-day test launches spent them all and the
sidebar update card silently vanished for the owner right after shipping v1.1.0. The
three tool items each pushed agents into workarounds: file reads instead of tool reads
(FB-0003), overwriting dead refs with forced links (empty-array clearing), and a
corrupted record nobody was allowed to hand-edit (FB-0002).

## How

De-metering: GitHub's `/releases/latest` answers 302 with the tag page in `Location` for
any caller, no quota — parsed by `tag_from_location` (unit-tested). The installer URL is
constructed from the name release.mjs always gives the asset and proven with one HEAD
that follows redirects to the CDN. Only when a newer version exists does anything
metered run, and its failure degrades the tooltip only. Empty-list clearing: `listArg`
collapses `[]` to null and `flag()` drops empty values, so a dedicated
`replaceListFlag` distinguishes absent (no flag) from present-but-empty (`--tags ""`,
which the CLI already treats as replace-with-nothing). Leak detection: two signatures —
any `<parameter` tag, and a field containing `</its-own-name>` — checked in `callTool`
before dispatch, so no partial step ever runs.

## For humans

The owner restarted the app right after releasing version 1.1.0 and no update offer appeared. GitHub answers anonymous version questions only 60 times an hour for a whole internet address, the day's test launches had spent all 60, and this app's rule for a failed check was to show nothing at all.

**The app now asks through a door that is not metered.** GitHub keeps one address that always forwards to the newest release's page, and following that forward costs nothing against the quota. The update check reads the version out of the forward, confirms the installer file exists the same free way, and only asks the counted question for the release notes — where a refusal blanks a tooltip instead of hiding the whole card. It is like reading the price on a shop's door instead of phoning a switchboard that stops answering after 60 calls.

**Three complaints about the record-writing tools went out in the same pass.** The tools agents use to write records here cut long records off mid-read, and the plain-language half sits at the very end — so the part a reader paid to see was always the part cut. Full reads now arrive whole. A note also had no way to empty its list of related records — sending an empty list meant "change nothing" — and now empty means empty.

**One record had machine markup saved as text.** In the ElmwoodOnline project, a bug record's comment ended in a machine boundary-marker and repeated its whole fix twice, because the sending side once confused where one field ended and the next began. The tools now refuse a call carrying such markup before anything is written, and I cut the doubled text out of that one damaged file by hand.

**How I know:** I asked the free forwarding address for this app's releases and it answered version 1.1.0 without touching the quota, and the tool test suite ran 208 checks — three of them new for these fixes — all green.

The version question now goes through an unmetered door, so a busy office can never silently starve the update card again.
