## What

The third pass over the bug screens, fixing what the round-2 critics found and one defect
their finding uncovered:

- the status strip on a bug record no longer paints two stops in the same pixels in a
  narrow window (BUG-0007);
- filter, tab and search state on both triage screens now lives in the URL, so Back, a
  reload and a pasted link all reproduce the view (BUG-0009);
- search reaches the whole record — a bug's report, thread and resolution, a work log's
  What/Why/How, updates and outcome — instead of the title, id and one-line excerpt;
- the board stopped using one word for two things: the tabs slice the board (Open /
  Resolved / All) and the group headings name the status (Unclaimed / In progress /
  Resolved / Closed);
- the footer's sort note describes the sort that is actually on screen, on every tab;
- `check:clipping` walks every record of every project at every width and now also finds
  ink painted over other ink, which is how BUG-0007 escaped it; a long path in inline code
  turned out to be cut by the card holding it (BUG-0008), found by that walk;
- `check:urlstate` is a new gate for the behaviours a screenshot cannot show.

This continues WORK-0008. It is a new record rather than an update to that one because
`agentmon work update` refuses to touch a finished log — "a finished work log is a
historical record" — which is the right rule, so the deviation is recorded here instead.

## Why

Every item is the same failure the last round had: the screen looked right and told the
reader something the vault does not say.

**The strip.** Three stops, each carrying an agent name and a timestamp, in a row that
could not shrink: `flex: none` on the node, `nowrap` on its text, `overflow: visible` on
the card. Below about 1150px the stops overflowed and were drawn over each other; at 960px
— this app's own minimum window width — the claimed timestamp printed across the resolved
agent's name, and the reader saw a word that does not exist. A clipping test cannot see
that, because nothing was clipped, which made a second kind of check necessary.

**State in the URL.** A board is a place people navigate *from*. They narrow it to
"critical, unassigned", open a record, read it, press Back — and a board that keeps its
filters in `useState` drops them back on the default view, with the work of setting them up
gone. The same state in the query string fixes three things at once: Back returns to the
view they left, the view can be linked to somebody else, and a reload does not lose it.
Every issue tracker a reader has met behaves this way; this one did not.

**Search that stops at the row.** `pg_stat_activity` appears four times in relay's BUG-0004
— in the repro steps and twice more in the thread — and in no title anywhere in the vault.
Typing it into the board found nothing, because search only read the title, the id and the
180-character excerpt. A reader searching a record house is searching for the thing they
remember, and what they remember is usually a line from the middle of the report.

**One word for two things.** The tab said "Open 2" and the group heading under it said
"Open 1", because the tab meant "not finished" (open + in_progress) and the heading meant
the literal status. Two numbers for the same word, 40px apart. The tab keeps the word, the
group takes the more precise one: a bug nobody has claimed is **Unclaimed**, which is also
what the record's own strip calls it.

**The sort note.** "Open bugs sort by severity, then by how recently they were filed" was
printed under the All tab, where half the rows on screen are sorted by when they were
closed. A footnote that describes a different screen is worse than no footnote.

## How

`src/lib/useUrlFilters.ts` is the shared piece: defaults live in a module constant, values
come from `useSearchParams`, anything at its default stays out of the URL (so an untouched
board is `/p/relay/bugs`, not a query string of `all`s), and every write is
`{ replace: true }` so a search box does not push one history entry per keystroke. Opening
a record is the push; Back lands on the board as it was left. Unknown values (`?tab=banana`)
fall back to the default rather than filtering everything away — a URL is typed by hand and
outlives the build that produced it.

Whole-record search needed the body on the list screens, so `WorklogSummary` and
`BugSummary` gained `searchText`: every section flattened to one line with inline markdown
stripped, built in `agentmon-core/src/body.rs::search_text` and its twin in
`scripts/vault-fs.mjs`. Section headings are left out on purpose — "## Report" is the app's
furniture, and a search where "report" matches every bug is no search at all. The two
readers were diffed field by field across all 20 records in the vault before this was
called done.

The strip fix is four lines of flex: the steps shrink in proportion to what they carry
(`flex: 0 1 auto` / `1 1 auto` instead of a zero basis), the node shrinks inside its step,
the label and the agent name truncate with a real ellipsis, and the date never gives up a
pixel because it is the fact a reader cannot reconstruct. Below 1260px the name and the
date stack instead, so at 960px both are shown in full rather than one of them ellipsised.

`scripts/check-clipping.mjs` was the tool that missed all of this, so it was rebuilt: it
walks every record of every project (the row that breaks is always the one with the longest
name, and it was only ever looking at the first bug), it measures painted ink with Range
rects clipped by whatever hides overflow, and it reports two defects — text cut by an
ancestor, and text drawn over other text. The dashboard is walked but not gated: its Agents
table is BUG-0006, still open and P4's scope, and a gate that is permanently red is a gate
nobody reads. Widths run in parallel, so 215 screen loads take nine seconds.

## For humans

A reviewer opened a bug's page at the smallest window this app allows and found one line printed over another. `.status-strip`, the row across the top of that page, carries three stops — filed, claimed, resolved — each with a name and a time. Below a certain width they stopped fitting. The claimed time was drawn across the resolved agent's name: a word that does not exist. That is `BUG-0007`.

**Nothing was cut off, so `npm run check:clipping` saw nothing.** That check hunts for words spilling outside their box, before a reader meets one with its end quietly missing. Here nothing spilled. Two pieces of text simply landed in the same place.

It is like proof-reading for words that fell off the edge while two stamps come down on the same spot.

**The strip shrinks now instead of overflowing.** Each stop gives up width in proportion to what it carries, and a long name trims with a "…". The time never gives up a pixel: it is the one fact a reader cannot reconstruct. Measured at six widths, nothing leaves the card and nothing shares a pixel.

**So I rebuilt that check.** It walks every record of every project now, not just the first bug of each. It reports two faults instead of one: text cut by the box around it, and text drawn over other text. Undoing the four lines that fixed the strip turns it red with twenty overlapping pairs.

**Its first full walk paid for itself twice over.** On a record nobody had opened before, a long file path written inside a sentence was being cut off by the card around it; it wraps now. And blocks of code in a card were reported as cut when they were not — you can slide them sideways to read the rest — which was the checker's own mistake, now fixed. Code still slides rather than wrapping, because a line broken inside code is different code.

**The board also forgot where you had been, and its search stopped at the title.** Narrow the list, open a record, press Back, and your filters were gone. `src/lib/useUrlFilters.ts` keeps them in the page's address now, so a link reproduces the view.

And search read only a title, an id and the first 180 characters. `pg_stat_activity`, a printout of what a database is busy with, appears four times in one report and in no title anywhere. Typing it found nothing. `searchText`, a new line holding everything a record says, is what search reads now.

**One word meant two things, forty pixels apart.** A tab read "Open 2" while the heading directly under it read "Open 1": the tab counted every bug still needing somebody, the heading only those nobody had claimed. The headings say exactly what they mean now — Unclaimed, In progress, Resolved, Closed — and the tabs keep the looser word. The sentence at the foot of the board explaining what order the rows are in used to describe a different tab's order, and now describes the one you are looking at.

**A comment written after a fix used to appear before it.** A bug's thread runs in the order things happened now, so a correction added after the bug was closed sits below the "resolved this bug" mark, and that mark carries its own time once it is no longer the last thing there.

**No photograph can show that Back works.** `npm run check:urlstate` is new, and it drives the real app to hold down exactly what a picture cannot: that Back brings you the view you left, that a pasted link reproduces it, that a reload does not lose it. Fourteen checks, one of them typing that database printout into the search box and expecting the one bug that mentions it.

Still open: that clipping check walks the summary screen's agent table without failing on it. Those 52 findings are somebody else's work, filed as `BUG-0006`, and a gate that is always red is one nobody reads.

A check that only looks for words falling off the page will never see two of them printed in one spot.
