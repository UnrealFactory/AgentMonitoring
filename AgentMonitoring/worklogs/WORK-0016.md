## What

Close the last below-bar items from P5 and make the repository shippable, then build the
real desktop app.

Six threads: one vocabulary for every state and object across all seven screens (a shared
`src/lib/words.ts`, the way the colours live in `tokens.css`); a palette meta column that
says which of its values is a project and which is an agent; a Rust watchdog so the desktop
app raises the same stale-data banner browser mode does when the vault stops answering; a
small sweep (a designed no-data state for the burn-ups, Undo after archiving a project, a
sidebar that scrolls in a short window, "just now" for an event written this second); repo
hygiene plus a README; and the release build.

## Why

The P5 design critic passed the shell and then named the thing that survives four pieces of
review because no single screen contradicts itself: **one fact, five names.** Relay has two
work logs with `status: in_progress`, and the shell printed that as "2 active" (switcher),
"2 still open" (nav tooltip), "2 agents have work open" (dashboard) and "2 in flight" (chart
legend) — then "12 records · 2 in progress" on the list and "9 done · 2 in flight" on the
Projects row. The object itself was a "record", a "log" and a "work log" on three screens a
reader crosses in one click, and the word "open" meant *work* in four places and *bugs* in
five, sometimes 200px apart in the same column. That is the tell of a thing assembled screen
by screen, and it is the one thing Linear never does.

Second: ids are per-project by SPEC, so searching "WORK-2" from relay returns two rows both
headed WORK-0002, and the only thing telling them apart was an unlabelled meta slot reading
"quill · done" on one and "AgentMonitoring · done" on the other. The reader had to already
know which vocabulary was which.

Third, and the one that matters for the product rather than the screenshots: the desktop app
is the product, and its only source of movement is the `notify` watcher. A watcher whose
directory is renamed or unplugged does not fail — it stops firing. Browser mode polls and can
say "not reading the vault right now"; the desktop app would have sat on stale numbers
forever with no tell, and stayed frozen even after the vault came back.

## How

**Vocabulary.** `src/lib/words.ts` holds the nouns, the state labels and the count phrases;
`format.ts` keeps the date/number formatting and hands the words over. Work is *in progress /
done / abandoned*; a bug is *open / in progress / resolved / closed*; the object is a *work
log*; "open" is a bug word and never describes work. The union of open-and-in-progress bugs
— which the sidebar badge, the board's default tab, the dashboard panel and the Projects row
all count — is named *unresolved*, because spelling it "open" spends the name of one of the
two states inside it (and put a claimed bug under a heading that said nobody had it). Counts
carry their denominator: "2 of 12 in progress". The bug board's tabs are Unresolved / Resolved
/ All with `?tab=unresolved`, and its group headings are now the four real statuses.

**Palette.** `Item.meta` became a list of labelled parts; a project wears the nav's folder
glyph and the app's brighter text, an agent wears the accent tint, a state stays quiet. The
group is "Work logs & bugs" rather than "Records".

**Desktop health.** A watchdog thread in `src-tauri/src/lib.rs` probes the vault every five
seconds, emits a `vault-health` event when it stops answering, drops the dead watcher, and
re-arms it the moment the vault is back (then emits `vault-changed`, because whatever
happened during the outage never reached the window). `subscribeVaultChanges` listens for it
and feeds the same banner the browser poll raises. Two unit tests cover the decision rule and
a real vault going away and coming back.

**Sweep.** `BurnUp` takes an `empty` prop and draws a designed no-data field instead of two
flat lines at zero; Archive leaves an Undo bar that waits rather than a toast that fades;
`.sidebar` scrolls as a last resort under a 96px-minimum nav; `formatRelative` calls anything
within 45 seconds either side of now "just now", because the app's clock ticks every thirty
seconds and a write that had just landed was being stamped in the future.

**Hygiene and release.** Critic scratch removed and gitignored, README written with three
embedded screenshots, every canonical screen re-shot for both projects (`--suffix`), and the
Windows bundle built.

## For humans

Two pieces of work were running in one project. The app told you that same fact five ways on screens one click apart. Two active, two still open, two agents have work open, two in flight. On the list: twelve records with two in progress.

The thing being counted was a record here, a log there, a work log elsewhere. The word open meant work in some places and bugs in others.

**One file now holds the app's words.** `src/lib/words.ts` keeps the nouns, the state names and the counting phrases. A piece of work is in progress, done or abandoned. A bug is open, in progress, resolved or closed, and open never describes work. The two states where a bug still needs somebody are one word, unresolved.

**Two rows in the search box carried the same name.** Numbering starts over in each project, so typing WORK-2 brought back two rows both headed WORK-0002. The small grey line under each was the only thing separating them, and you had to already know how to read it. Every part of that line now shows its kind: the project wears the folder mark the left-hand column uses, the agent — whoever did the work — wears the app's accent colour, and the state stays quiet behind both. The heading over those rows says work logs and bugs instead of records.

**`npm run check:live`, one of my own checks, pointed itself at the real history.** It starts its own server against a throwaway copy, on port 5199, and when that port is busy the server quietly takes the next free one — the check accepted whoever answered. A server left by an earlier tool made it drive the live folder, and it created a project in this repository's own history. The check now asks the server which folder it has open, and the stray project was removed.

**The desktop app could have frozen without saying so.** It hears about changes from `notify`, a watcher that reports when a file in a folder changes. A watcher whose folder is renamed or unplugged does not fail; it stops reporting. A thread in the desktop half now tests the folder every five seconds and raises `vault-health` when it stops answering, drops the dead watcher, and starts a fresh one the moment the folder is back.

It is like a smoke alarm that tests its own battery: a silent alarm and a working one look the same.

**I watched that on the built app, not in the code.** I ran it against a copy of the history and moved `vault.json` away, the file marking a folder as one the app can read. Thirteen seconds later the window carried the warning line and the LIVE flag was gone. Putting the file back cleared it unaided. A `bug create` from the command line then moved the column's count from two unresolved to three — proof the watcher restarted rather than merely reported itself dead.

**Only that one file could be moved.** On Windows a running app holds its folder open, so the folder cannot be renamed underneath it; removing that file is the local stand-in.

**Four smaller things were wrong in the corners.** A project with nothing yet to draw got two flat lines along the bottom of its chart, and now gets a plain empty field of the same height. Archiving a project flashed a message that faded before you could undo it, and now leaves a bar that waits. A short window cut the bottom off the left-hand column, which scrolls now. And a thing written one second ago was reported as happening in a moment, in the future: the clock on screen only moves every thirty seconds, so anything within forty-five seconds either side of now is called just now.

**The repository had no front page.** Anyone opening it found nothing that said what this is. `README.md` — the page a code site shows first — now holds three pictures of the app and a three-command example of the command-line tool. I also deleted 206MB of scratch files left behind by earlier reviews, set that folder to be ignored from here on, and re-shot every screen for both projects.

**Last, I built the thing a person would install.** One command turned the code into a real Windows program and two installers. I started that program against the live history: it drew the dashboard, Windows reported it responding, it printed no errors, and I closed it. Before that came `npm run check:counts`, which reads the number printed on every tab, button and menu line, clicks it, and counts the rows that arrive: 714 numbers, every one of them honest. A control saying two while showing three would have been named there.
