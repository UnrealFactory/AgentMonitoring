## What

Feedback items can now be deleted: core delete_feedback(_in) in
crates/agentmon-core/src/feedback.rs, a delete_app_feedback Tauri command, `agentmon
app-feedback delete <FB-ID>` on the CLI, DELETE /project-api/app-feedback/:id in the
browser middleware (shelling to that CLI verb), and a Delete button on the board's done
rows that arms on the first click (정말 삭제할까요?, button-danger) and deletes on the
second. Open items refuse to delete — exit 5, with the fix named: mark it done first.
SPEC.md, docs/AGENT_MANUAL.md and docs/MCP.md updated; the manual now describes the
delegated-cleanup task shape (done after the fix really shipped, then delete) and MCP.md
explains why the disposal verbs are deliberately not tools.

## Why

WORK-0045 shipped the board with done-items-stay-forever, on the records-are-evidence
principle. The owner corrected the model: feedback is a work inbox, not history — the
evidence of the fix is the work log the fix produces, and a cleared board is the point.
First design made delete app-only (the project-delete precedent: agents must not erase
complaints about themselves); the owner overruled that too, because the intended workflow
is delegation — "go through the feedback list, fix it, clear it" given to an agent — so
the CLI got the verb. What survives of the original caution is the done-first rule: a
complaint cannot vanish unread, and every deletion is a two-step.

## How

The middleware's first draft was a JS twin of the delete (no CLI verb existed to shell
to); the moment the CLI verb was decided, the twin was deleted for a shell-out, keeping
one implementation of the refusal. The MCP tool stays filing-only: done/reopen/delete
would bill every conversation's context for an occasional chore.
