## What

Feedback items can now be deleted: core delete_feedback(_in) in
crates/agentmon-core/src/feedback.rs, a delete_app_feedback Tauri command, `agentmon
app-feedback delete <FB-ID>` on the CLI, DELETE /project-api/app-feedback/:id in the
browser middleware (shelling to that CLI verb), and a Delete button on the board's done
rows that arms on the first click (정말 삭제할까요?, button-danger) and deletes on the
second. Open items refuse to delete — exit 5, with the fix named: mark it done first.
SPEC.md, docs/AGENT_MANUAL.md and docs/MCP.md updated; the manual now describes the
delegated-cleanup task shape (done after the fix really shipped, then delete) and MCP.md
explains why the disposal verbs are deliberately not tools.

## Why

WORK-0045 shipped the board with done-items-stay-forever, on the records-are-evidence
principle. The owner corrected the model: feedback is a work inbox, not history — the
evidence of the fix is the work log the fix produces, and a cleared board is the point.
First design made delete app-only (the project-delete precedent: agents must not erase
complaints about themselves); the owner overruled that too, because the intended workflow
is delegation — "go through the feedback list, fix it, clear it" given to an agent — so
the CLI got the verb. What survives of the original caution is the done-first rule: a
complaint cannot vanish unread, and every deletion is a two-step.

## How

The middleware's first draft was a JS twin of the delete (no CLI verb existed to shell
to); the moment the CLI verb was decided, the twin was deleted for a shell-out, keeping
one implementation of the refusal. The MCP tool stays filing-only: done/reopen/delete
would bill every conversation's context for an occasional chore.

## For humans

A complaint marked done stayed on the feedback board for good. That was deliberate in `WORK-0045`, the work that built the board: a record is evidence, and evidence is not thrown away. The owner said that was the wrong idea here. This list is a work inbox, and an empty one is the point.

**The proof a complaint was dealt with is the work log the fix produced.** So the complaint itself can go, once the fix has really shipped. It is like a list of chores on the fridge door: what shows you did one is the tidy kitchen, not the note.

**Finished rows now carry a Delete button that asks first.** One click turns it red and puts a question on it — 정말 삭제할까요?, "shall I really delete it?" — and the second click removes the file. The same deletion exists as a typed command, `agentmon app-feedback delete`, so a person can hand an agent the whole list: work through it, fix them, clear them.

**An item still open refuses to be deleted, and the refusal says what to do: mark it done first.** Nothing vanishes before somebody has read it, and getting rid of anything takes two steps.

**We nearly ended up with two sets of rules for one act.** No typed command existed yet, so the browser version first got a copy of the rules to itself. That copy went in the bin the moment the command was decided.

**Then I tried to break it from each side.** `cargo test`, which runs every test written against the Rust code, passes 114: deleting while open is refused with the message that names the fix, and deleting when done really removes the file. By hand in a throwaway folder, deleting an open item failed with error code 5, and marking it done first left the folder empty. Playwright, which drives a real browser the way a person would, found no Delete on an open row, red on the first click, and an empty board on the second.

**A board that has been worked through can now be emptied.** `FB-0001`, the live board's one still-open complaint, correctly offers no Delete. `app_feedback`, the tool agents call, still only files new items: adding delete and reopen would charge every conversation for a chore that comes up now and then.

An inbox you cannot empty stops being a list of things to do.
