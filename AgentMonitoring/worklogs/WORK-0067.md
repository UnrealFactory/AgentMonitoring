## What

Close the hole round 3 shipped: `body::heading` called fewer lines a heading than every
reader downstream of it, so three spellings of the reserved `## For humans` heading walked
past the guard and one of them made the two app transports disagree about a record.

## Why

The guard is the whole feature. `##<TAB>For humans` in a `--body` was exit 0, and the app's
own renderer (`src/lib/markdown-parse.ts`, `/^(#{1,6})\s+(.*)$/`) draws a tab-separated hash
run as a heading — so the Agent view drew a level-2 heading reading "For humans" over prose
saying it was not the record's human area, which is the confusion SPEC.md's reserved section
exists to prevent, under the toggle D3 is building. A leading U+FEFF was worse than
confusing: JavaScript's `trim` strips it and Rust's does not, so browser mode served
`extraSections: [{ title: "For humans" }]` where desktop mode served none — one record, two
truths.

## How

One rule, stated once and held by three parsers. `body::heading` now closes the hash run on
any space (`is_space` = Rust's `char::is_whitespace` plus U+FEFF, which is the union of what
the two languages' `trim` functions strip), `human::is_heading_title` compares the title the
way a reader sees it drawn (whitespace collapsed, ATX closing hash run and trailing colon
off, case folded), and fences now close on their own marker the way `parseBlocks` closes
them — a ``` block held a ~~~ as a closer here and as content there, which hid a real
heading. `scripts/project-fs.mjs` got the identical change. The list of spellings lives in
`crates/agentmon-core/tests/reserved-heading-shapes.json`: the Rust integration test drives
every one through the real write path, and `scripts/markdown-smoke.mjs` holds the browser
transport and the app's renderer to the same list, plus the end-to-end property that no
agent-area payload ever renders a heading reading "For humans".

Alongside: a `--title` with a line break wrote an unreadable record *and* its event and only
then failed at exit 6 (`yaml_scalar` had no escape for a newline, so the title opened a
second frontmatter line); `app-feedback update --at` was validated and then dropped, so the
item gained an `updated:` key to hold it; and the `app_feedback` MCP tool gained an `id`
argument, which is the update verb an MCP-only agent had no way to reach.

## For humans

Every record this program keeps has two halves. One is written by the agent for other
agents, full of file names and commands. The other is the same events told plainly, for a
person who was not there. The plain half sits under a heading that reads "For humans", and
the program keeps that heading for itself: an agent that tried to write it into the
technical half was refused, so a reader could never be shown the wrong half under the right
label.

**The check was stricter on paper than on screen.** Deciding "is this line a heading?"
happens in three separate pieces of code here: the one that refuses, the one the browser
version reads records with, and the one that actually draws them. They disagreed. A heading
is normally two hash marks, a space, then the words. Put a tab where the space goes and the
drawing code still draws a heading; the refusing code saw ordinary text. So an agent could
write a convincing fake, the program would accept it, and the app would draw a heading
saying "For humans" straight above a sentence saying this is not the human half.

It is like a guest list checked only for exact spelling. One extra space and the same person
walks in.

**One record, two answers.** Worse than the fake heading: an invisible mark that some
editors put at the start of a file counts as blank space in one of the two programming
languages this app is written in and as a real character in the other. The same record file
therefore gave the browser version a "For humans" section and gave the desktop window none.
A record that says different things depending on which door you came in is worse than one
that is simply wrong.

**What fooled me.** I expected the tab to be the whole story, and it was one of three. The
no-break space — the invisible one that stops two words being split across lines — also
counts as a space to the drawing code. And the marks agents use to show computer output
could be opened with backticks here and closed with tildes, which is not how the drawing
code reads them; that gap let a real heading hide inside what one reader called a code block
and the other called plain text. Every spelling I found came from asking the same question
of all three readers rather than trusting one.

**How I know it is fixed.** All the spellings now live in one file that every reader is
tested against: eighteen that must be refused, seven that must be allowed. The command-line
tool refuses all eighteen, where it used to accept three of them without a word. A separate
check writes one record per spelling and compares, field by field, what the desktop reader
and the browser reader hand back — identical on all twenty-five, where before they gave
different answers. The browser version was then run for real and asked for nine records over
the network; every one carried its plain half. The project's own 103 record files are
byte-for-byte unchanged, and its health check reports no problems.

**Two others, both bigger than they looked.** A title with a line break in it saved the
record, wrote its entry in the activity log, and only then failed — leaving a file nothing
could read and a log entry pointing at it. One of those made the whole task list fail to
load. Titles are one line now, refused before anything is written. And a note about *when*
an item on the feedback board was retold was being checked and then thrown away; it is kept
now.
