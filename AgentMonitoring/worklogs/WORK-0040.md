## What

The record renderer's vocabulary grows, per the owner's direction ('agents should be able to make records varied and pretty'), without opening raw-markup injection: (1) image references — `![alt](assets/diagram.svg)` renders files that live inside the project's AgentMonitoring folder, over both transports; (2) task lists `- [x]`, strikethrough `~~x~~`, GitHub-style callouts `> [!note]`, and syntax highlighting in fenced code blocks. Everything stays declarative: parsed to data, drawn by the app, never dangerouslySetInnerHTML.

## Why

The app exists so humans can read agent work comfortably, and the one missing vocabulary is pictures — diagrams and screenshots are what agents produce well and humans read fastest. Raw HTML/inline-SVG passthrough stays banned (bodies are LLM-written and LLMs can be prompt-injected; a record must not be able to draw fake UI), but SVG loaded through <img> is script-inert, so file references give the drawing ability with none of the injection surface.

## How

Path safety in agentmon-core (relative, no dot-dot, canonicalized inside the folder, image extensions only, size-capped) with a Tauri command returning raw bytes (ipc::Response) -> blob URL; the dev middleware mirrors the same rules for browser mode. Parser gains image/del inlines, task-item lists, callout and figure blocks; a small hand-rolled tokenizer colors comments/strings/numbers/keywords (no new dependencies, per house style). markdown-smoke keeps the no-word-lost sweep true over the new shapes; docs/AGENT_MANUAL.md documents the vocabulary so agents actually use it.
