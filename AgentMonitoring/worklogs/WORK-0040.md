## What

The record renderer's vocabulary grows, per the owner's direction ('agents should be able to make records varied and pretty'), without opening raw-markup injection: (1) image references — `![alt](assets/diagram.svg)` renders files that live inside the project's AgentMonitoring folder, over both transports; (2) task lists `- [x]`, strikethrough `~~x~~`, GitHub-style callouts `> [!note]`, and syntax highlighting in fenced code blocks. Everything stays declarative: parsed to data, drawn by the app, never dangerouslySetInnerHTML.

## Why

The app exists so humans can read agent work comfortably, and the one missing vocabulary is pictures — diagrams and screenshots are what agents produce well and humans read fastest. Raw HTML/inline-SVG passthrough stays banned (bodies are LLM-written and LLMs can be prompt-injected; a record must not be able to draw fake UI), but SVG loaded through <img> is script-inert, so file references give the drawing ability with none of the injection surface.

## How

Path safety in agentmon-core (relative, no dot-dot, canonicalized inside the folder, image extensions only, size-capped) with a Tauri command returning raw bytes (ipc::Response) -> blob URL; the dev middleware mirrors the same rules for browser mode. Parser gains image/del inlines, task-item lists, callout and figure blocks; a small hand-rolled tokenizer colors comments/strings/numbers/keywords (no new dependencies, per house style). markdown-smoke keeps the no-word-lost sweep true over the new shapes; docs/AGENT_MANUAL.md documents the vocabulary so agents actually use it.

## For humans

The owner asked for records that could be varied and pretty. The app exists so a person can read agent work comfortably. The one thing a record could not do was show a picture — the diagrams and screenshots agents make well and people read fastest.

**A record can now point at a picture file.** The agent writes one short line, `![alt](assets/diagram.svg)`: show the file kept at that path, and call it this. Alone in a paragraph it is drawn with that text as a caption. Tick-box lists, crossed-out text, coloured notice boxes, and colour in code blocks from `lib/highlight.ts`, came with it.

**A record is never allowed to hand us markup to draw.** Record bodies are written by language models, and a model can be talked into repeating instructions it read somewhere. A record must not be able to draw a fake button. So `dangerouslySetInnerHTML`, the one call that would pass a body straight to the browser as markup, is used nowhere. The app reads the text, works out what each piece is, and draws it itself.

Pictures were safe to allow because a drawing loaded as an image cannot run anything. It is like accepting a photograph through the letterbox but never a note telling you to rearrange the room.

**The path is the dangerous part.** A path can be written to climb out of a folder and reach a private file elsewhere on the disk. `Store::asset` is the gate every picture goes through. The path must be relative and must end in one of six picture extensions. It must land inside the project's own records folder once every shortcut is resolved, and it must be under ten megabytes.

**I had the picture drawn and looked at it.** Playwright, a tool that drives an app the way a person does, opened a record in the browser. The picture really decoded, two hundred pixels wide, with its caption, notice box and tick boxes there. An attempt to climb out of the folder was refused out loud, and the real desktop app drew the same diagram.

**`markdown-smoke` checks that every word of a written record turns up in the drawn one.** It gained five new samples, and all 409 of its checks pass. Pictures out on the internet still become plain links: the app fetches nothing while it runs.

Let a page carry a picture, never an instruction.
