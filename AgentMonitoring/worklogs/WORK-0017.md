## What

Close the two failures the P6 critics left open, and ship the build.

1. **The boot dead end.** The installed app's first screen was an error card whose only
   control was **Try again** — a button that re-runs the same vault resolution and fails the
   same way on any machine that has no vault. It now goes to /projects, the screen that
   recovers, which grew a **Create a vault…** action (a folder picker plus `Vault::init`,
   through a new `create_vault_folder` command) so a human who installed the release and has
   no terminal is not stuck. The installer now ships the `agentmon` binary beside the app,
   and the onboarding prints command lines that name it at its real path.
2. **The record that said ten.** WORK-0011 claims relay is "three weeks of ten agents";
   relay has four. Filed and resolved as BUG-0017, which `refs: WORK-0011` so the correction
   shows on that work log's page, and the source comment that gave a *third* number
   (src/lib/dashboard.ts said five) no longer carries a roster at all.

Plus the flagship-screen sweep the design critic asked for: the Agents table's RESOLVED
column no longer truncates its own heading, `check:clipping` gained the check that would
have caught it, and the last three vocabulary misses are gone.

## Why

Both failures are the same kind of defect — a thing that is true everywhere except at the
one place a stranger arrives.

The dead end is the worse of the two, because it is the *first* thing an installed copy
shows and it cannot be escaped from inside the window: `discover()` walks five levels up
from the executable, so an installed app, a moved copy, an unplugged drive or a renamed
folder all land on it, and the three remedies in the message (`--vault`, `AGENTMON_VAULT`,
`agentmon init`) are two environment concepts and a binary the installer did not ship. The
rescue was already two lines below in App.tsx and was shadowed by the error branch.

The record that says ten agents is cheaper to fix and more expensive to leave. This product's
whole claim is that the record is true; a decorative number that the app's own dashboard
contradicts four rows at a time — on the very screen the record is describing — spends that
claim for nothing. The sentence's *decision* (a self-scaling time axis) is sound and its
shape half (three weeks vs one working day) is true, which is exactly why nobody checked the
number.

The RESOLVED column is the third of the same kind: a heading that the previous round widened
from 46px to 62px "believing it fixed", while the word measures 71px, and the gate passed it
because an ellipsis was present. A gate that cannot see the defect it was written for is the
defect.

## How

**The dead end.** `Home()` in src/App.tsx returns `<Navigate to="/projects" replace/>` for a
failed vault as well as an empty one; ProjectsPage's error branch already carried the
message, Try again and Open vault folder…, and now carries **Create a vault…** too. That
button calls `create_vault_folder` (src-tauri/src/lib.rs): folder picker, `Vault::init` named
after the folder the human chose, then the same `switch_vault` path the folder-opener uses —
so the window retitles, the watcher re-arms and every screen reloads exactly as it does for
any other vault switch. Picking a folder that is already a vault opens it instead of failing.

**The CLI in the installer.** `bundle.externalBin` wants the binary suffixed with the host
target triple, so `scripts/bundle-cli.mjs` builds `agentmon` and stages it as
`src-tauri/binaries/agentmon-<triple>.exe`; `npm run tauri:build` runs it and merges
`src-tauri/tauri.release.conf.json`. The entry is deliberately *not* in tauri.conf.json:
Tauri's build script fails when a declared external binary is missing, which would break
plain `cargo build` and `cargo test --workspace` on a fresh clone. A `cli_path` command finds
the binary next to the executable, and the onboarding's three command lines use it when it is
there and the bare name when it is not (dev builds, browser mode).

**The record.** The vault is append-only and `agentmon work update` refuses a finished work
log on purpose, so WORK-0011 is untouched: BUG-0017 carries the recount and points at it,
which puts the correction in the Referenced-by block of the page that carries the error.

**The column.** The three number tracks are separate grids for the header and each row, so
`max-content` would size them per grid and put a heading over a column of its own; they are
fixed at the *measured* max-content widths of the headings (39/38/71 px, rounded up with a
little air). The durable half is in `scripts/check-clipping.mjs`, which now reports a third
defect — TRUNCATED, a heading that ellipsises itself — over the app's own fixed vocabulary
(column headings, card titles, `dt`s). An honest ellipsis is right for a name out of the
vault and wrong for a word the reader needs whole to know what the numbers mean.

## For humans

Install the app on a machine that has never held a vault — the folder these records live in — and the first thing it showed was an error card. Its only button said Try again. Pressing it ran the same search and failed the same way.

It is like a door whose only key is locked behind it.

**The first screen now goes to the one that can recover.** A failed search lands on `/projects`, the screen listing every project the app can see, which offers three ways forward: try again, open a folder elsewhere, or make one. Making one opens a picker, writes a new vault named after the folder you chose, and switches to it.

**The rescue had been two lines below all along**, hidden behind the error. The three remedies it offered were useless to the person meeting them: two are settings typed in a terminal, `AGENTMON_VAULT` among them, and the third named `agentmon`, the command-line program that writes these records — which the installer did not include. That program now ships beside the app, and the printed instructions name it where it sits.

**A finished record said ten agents; there are four.** A record here is never rewritten once closed, so the recount went in as its own bug record, `BUG-0017`. It points at `WORK-0011`, the work log carrying the wrong sentence, and the correction shows on that log's own page under the records that refer to it.

**A column heading was cut short, to "RES…".** The round before widened it from 46 pixels to 62 and believed that fixed; the word needs 71. `npm run check:clipping` had passed it, because it saw three dots and took an ellipsis for honest shortening. Those columns now measure as wide as their headings, and that check knows a new fault: a heading that shortens itself.

**The summary screen read "1 of 17 work log in progress".** I found that by looking at the shipped app rather than at the code. The phrase chose between "log" and "logs" from the count of running jobs instead of from the number standing right beside it, so it was only ever wrong when exactly one thing was running — this project's usual state, and never the state an earlier photograph caught. It asks the same helper the rest of the app asks now, and I checked the other eleven places where a plural had been written out by hand: every one agrees with its own number.

Four wordings went with it. The hovered note over that count stopped reading "in progress work logs" and puts the words in the order a person says them. A work record's side card is headed *Work log*, where the same card on a bug page says *Bug*. A hovered date in the block of related records reads as a date instead of the raw machine spelling. And that block and the search box name the two real things, a work log and a bug, rather than calling both of them "a record".

**I drove the installed build, not the code.** I copied it into a bare directory, with nothing configured and no remembered choice. It came up on the recovery screen, with all three buttons and the true directory in its printed command. I ran that command with the shipped program, relaunched, and the app opened the folder it had made. Then I clicked the make-one button myself: the picker opened, the folder became a vault, the app switched.

**The wrong sentence still says ten.** A reader meets the correction only by reaching the list of records referring to it, and a corrected record carries no mark at the top. Putting one there means changing what a record may hold, not editing a line.

A check that cannot see the fault it was written for is the fault.
