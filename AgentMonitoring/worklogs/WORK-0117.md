## What

기존 폴더를 눌러 끌어 다른 폴더의 위·아래로 옮겨 순서를 저장하고, 사이드바의 같은 단계 폴더와 프로젝트 아이콘·이름·행 간격을 맞춥니다. 순서 변경·복원·취소·저장 실패, 프로젝트 이동과 HMR 회귀를 검증하면 완료합니다.

## Why

사용자가 프로젝트에 이어 폴더도 드래그로 위치를 바꾸고, 폴더와 기존 프로젝트의 어긋난 표시 위치를 같은 기준으로 맞추길 요청하셨습니다.

## How

기존 폴더 배열 순서를 변경하는 저장 동작과 폴더 전용 드래그 대상을 추가합니다. 프로젝트 드래그는 소속 이동, 폴더 드래그는 앞뒤 순서 변경으로 처리하고 놓을 위치를 선으로 표시합니다. 루트 폴더와 프로젝트는 동일한 아이콘·텍스트 열을 사용하고 폴더 내부만 들여씁니다.

## Outcome

폴더 제목을 마우스로 끌어 다른 폴더의 앞·뒤에 놓으면 순서를 변경하도록 구현했습니다. 목표 제목 위·아래 절반으로 위치를 고르고 삽입선을 표시합니다. 폴더 배열 순서를 저장해 사이드바·프로젝트 화면과 재실행 뒤 순서가 일치하며, 포함 프로젝트 소속과 기존 펼침 상태는 유지합니다. 동일 위치 놓기와 Esc는 저장 없이 취소하고 저장 실패 시 이전 순서를 유지합니다. 기존 프로젝트 소속 이동과 폴더 순서 변경을 끌기 종류로 분리했습니다.

사이드바에서 같은 단계 폴더와 프로젝트의 아이콘 중심·텍스트 시작점·글자 크기·행 높이를 맞췄습니다. 폴더의 펼침 화살표는 아이콘 왼쪽에 배치하고 내부 프로젝트만 20px 들여썼습니다.

검증: npm run check:project-folders 한국어·영어 28개 통과(위·아래 재배치, 두 화면 반영, 재로딩 복원, 포함 항목 보존, 취소·실패, 960/1600px 정렬 포함), npm run check:hmr 6회 갱신 통과, npm run build와 git diff --check 통과입니다. 한국어 정렬 및 폴더 삽입선 캡처를 직접 확인했습니다. 기존 5175 개발 서버의 폴더 핸들·순서 변경 코드 응답과 앱 프로세스 유지를 확인했습니다. README·주제 노트·필수 색인과 기존 피드백 설명을 갱신했습니다. 설치본 배포는 하지 않았습니다.

## For humans

폴더도 잡아 끌어 순서를 바꿀 수 있게 추가하겠습니다. 같은 단계의 폴더와 프로젝트 이름이 나란히 시작하도록 위치와 행 간격도 맞추겠습니다. 폴더 안에 들어간 프로젝트의 들여쓰기는 유지하며, 순서가 다시 열어도 보존되는지 확인하겠습니다.

### 2026-09-08T11:29:40Z
