## What

A new CLI verb, `agentmon reconcile --theirs <incoming AgentMonitoring copy> [--apply] [--only ids] [--at T] [--no-gitattributes]` (core in crates/agentmon-core/src/reconcile.rs, CLI thin per convention), plus a narrowly-scoped `--replayed` flag on `work update` and `bug comment`. Reconcile detects ids whose content differs between the local project and the incoming copy, re-keys the LOCAL records to the next id free on both sides, and rewrites everything that points at them: the file rename, frontmatter `id`, every `refs:` entry and bare prose mention across local work logs/bugs/notes (the exact `\b(WORK|BUG)-\d{1,8}\b` grammar src/lib/markdown-parse.ts linkifies; `[[note-names]]` never), and events.jsonl `ref` fields plus summary mentions. Dry run by default with the full plan and a from-to mapping; `--apply` executes exactly it, logs one `project_updated` event carrying the mapping, and installs `events.jsonl merge=union` in AgentMonitoring/.gitattributes. `--replayed` (requires `--at` and `--message`) writes a lost note back at its real time: ceilings waived, the started/created floor kept, the entry inserted in timeline order (new `body::insert_entry_by_time`), the event summary opening `Replayed:`.

## Why

BUG-0027: ids are a per-project zero-padded sequence allocated from local state, so two machines sharing one repo through git must collide when both write offline, and recovery was manual re-creation plus hand-editing events.jsonl. The owner's direction: do NOT change the id scheme (SPEC contract — routing, refs and chips stand on immutable per-project sequences); ship the surgical tool instead. The compounding defect — `work update` rejecting an `--at` before the record's close, making honest replay of history onto a re-created record impossible — needed a sanctioned, marked, reconstruction-only exception rather than a loosened guard.

## How

The local side moves because the incoming side is what the world already has; the incoming copy is read and never written. What counts as "the same record edited twice" versus "two records wearing one number" is decided by the triple no agentmon verb ever rewrites — title, author, start time: identical bytes = already synced (skipped; naming one in `--only` refuses outright, exit 5), same triple with different text = a content merge left to git (skipped as `diverged`), different triple = the collision, re-keyed. Re-key targets allocate above every number either side has ever used, so a chain cannot move the collision along; the id rewrite is one pass looking each token up as found, so a second-round map (0011-to-0015 while 0015-to-0019) can never double-apply. events.jsonl is rewritten textually, line by line, so unknown keys a newer build wrote survive (SPEC forward-compat). Apply writes new files before removing old ones — a crash leaves a loud duplicate doctor names, never a missing record. The events merge story is git's: `merge=union` is correct for an append-only log whose readers sort by ts, and installing it in the project's own .gitattributes makes every future pull merge clean. Human-area law: reconcile moves records without changing either area, so it takes no --human; --replayed resolves the human area exactly as a normal update (a legacy record still demands one). SPEC gained the reconcile contract and the precisely-named replay exception; docs/AGENT_MANUAL.md gained Recipe 5 (the exact BUG-0027 repro, then the fix commands), reconcile/replayed reference sections and a troubleshooting entry; docs/MCP.md states both are CLI-only git-time operations, deliberately without MCP counterparts.

## For humans

**The collision now has a one-command repair.** Two computers that handed out the same record numbers used to mean an afternoon of rebuilding by hand — six records, the last time it happened. Now one command compares the two copies, gives the unshared side the next numbers free on both machines, and fixes every mention of the old numbers in the same move: file names, cross-references, the sentences that name them, and the shared history file. It reads out its whole plan first and touches nothing until told to go ahead — like a mover who shows you the list of boxes before lifting one — and it leaves alone anything that does not actually need to move, saying why.

**A note lost in such an accident can be put back at its true time.** Rebuilding a record used to hit a wall: the tool refuses a note dated before the record's ending, which is normally the right guard, because a backdated note is usually a lie about when. A new switch, allowed only for reconstruction, lets the lost note back in at the moment it really happened, slots it into its place in the timeline, and stamps the history line with the word Replayed so the copy can never pass for an original.

**We checked it the way it will be used.** A rehearsal with two real copies of a project ran the whole accident on purpose: both sides wrote a record number 2, the sync refused exactly as reported, one command renumbered, the sync then went through, and the project's own health check found nothing wrong in the merged result. All 190 automated checks pass, ten of them new ones acting out this exact story. One unrelated red light was found along the way — a size limit the style guide outgrew some days ago — and it is written up as its own bug report (BUG-0028) rather than quietly patched.
