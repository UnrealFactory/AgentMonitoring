## What

Round 2 of the shell/portability piece, against the two critic verdicts on P5 round 1: the
browser-mode vault reader silently falling back to this repo's own live vault, and the
Projects screen + command palette losing the blind side-by-side to linear.app.

## Why

The portability failure is the serious one. `scripts/vault-fs.mjs` treated `AGENTMON_VAULT`
as the first candidate of a fall-through list, so a configured vault that stopped being
readable (renamed directory, unplugged drive, typo) was answered with `./vault` — this
project's real history — for reads *and* writes, with no banner and no error. The Rust twin
(`Vault::resolve`) makes that a hard error, and the file's own header says the two must not
drift.

The design failure is that /projects is the one screen P5 owns end to end and it reads as a
weaker product than /work one click away: a card grid with a dead track, 40% of a 1000px
window empty, a sidebar holding one nav item over 668px of void, and a palette that cannot
search records from the very screen that frames the vault.

## How

Authoritative vault resolution in the JS reader (open the configured vault or fail loudly,
naming the directory and the fix), the real resolution source reported through
/vault-api/vault, a poll that reports its failures instead of swallowing them, and a shell
banner that says the vault cannot be read rather than quietly serving a different one.
Projects rebuilt on the app's own full-bleed row form with a cross-project activity section;
sidebar nav populated everywhere; palette searching every project's records with a
recency-ranked default menu. New gate `npm run check:vault` proves the fallback is gone.

## For humans

Tell the app which folder holds your records, then rename that folder or unplug the drive it sits on. The app said nothing. It quietly opened a different folder instead — this project's own real history — for reads and for writes. No warning line, no error.

It is like a key that opens your neighbour's door once your own lock has been changed.

**A folder you named is now opened or the request fails.** You name one through `AGENTMON_VAULT`, a setting holding the path to your records folder. `scripts/vault-fs.mjs`, the file the browser version reads records with, opens that folder or refuses. The refusal names the path and gives the command that would create a folder there. It falls back to the copy inside this repository only when nobody named anything.

**When the folder stops answering, the window says so.** One amber line sits at the top of the page: not reading the folder right now, the path, the time the numbers below were last good, and a Try again button. Those numbers stay as they were and the LIVE flag comes down.

**`npm run check:vault`, the check I wrote to prove all this, wrote into the real history.** An earlier tool had left a server running on the port that check uses. The write it requires to be refused reached that server, which had the live folder open. It created a project there called `check-vault-must-not-exist`.

The check now refuses to start unless the server on its port is its own. It will not write until its reads have proved that server has no folder open.

**Twenty-nine checks cover the rules now.** A folder named but unreadable fails every request by name, refuses the write, and never serves the repository's copy. A folder renamed under an open window raises the amber line within seconds, keeps the last good numbers, and recovers by itself when the folder returns. The live folder is fingerprinted before and after and is unchanged.

**The projects page was rebuilt on the app's own row form.** It uses the full-width rows the other lists use, each with three labelled figures and a description that wraps instead of being cut off mid-word, over a feed that merges every project's newest events — so the screen has something to say rather than leaving two-fifths of the window black.

**The left column held one link above a great deal of nothing.** It names each thing once now — the app at the top, the folder at the foot — and lists that folder's projects underneath, so no screen is left with a single item in its column. The foot shows the folder's name, which is the tell that you are not where you thought you were, with the full path over on the projects page.

**`Ctrl+K`, the search box the keyboard opens, now reads records from every project.** Type nothing and it offers what happened most recently across all of them, so a bug filed a minute ago is already on the list. Find nothing and it tells you what it looked through, rather than leaving you to guess.

**An archived project used to keep flying the LIVE flag.** Its summary page says archived instead, the switcher goes on listing the project you are standing in even after you archive it, and the line at the top of the projects page — active projects, and how many archived — agrees with the count in the left column.

**One repair here was made by hand.** Deleting that stray project is the only change to the real history nothing checked in advance. Afterwards `agentmon doctor --strict`, the command that reads every record and reports anything malformed, found no problems.

An app that opens something else when it cannot open what you asked for is not being helpful.
