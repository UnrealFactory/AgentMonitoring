## What

Make the desktop app answer a failure the way the browser build does, in Korean, and give the
gates a way to see it.

## Why

A Korean user asked for this app in Korean: chart subtitles like "Started against done, running
total, with the change over the last 7 days" and all other UI chrome are English and inconvenient
— make the UI Korean.

The last round left the shipping half of that unanswered. `failureTitle()` asked
`status !== 404` first, and `invokeCommand()` throws with no status because a Tauri command
returns `Result<T, String>` — so the desktop app, the product, headlined every stale link
"볼트를 읽지 못했습니다" while browser mode said "이 프로젝트에 BUG-9999 기록이 없습니다" for
the identical condition. One condition, two sentences, one app. Underneath that headline sat two
more defects only the desktop can show: "찾은 파일 경로" (*the path that was found* — the reverse
of what happened) and, because the hint clause only exists in Rust, no boundary at all between it
and the sentence before it. A third, `invalid id 'NOTANID': expected the form …`, reached Korean
readers as raw English. `npm run check:i18n` drives the dev server, so none of the three was
reachable by it: the gate could only ever read the half that was right.

## How

`failureKind()` classifies a failure by the message, which both backends write the same way, and
uses the status only to break ties; `failureTitle()` and the new `nothingToRetry()` (which
replaces `status === 404` in five screens) read it. `invalid id` / `invalid project slug` become
their own kind, `bad_address`, with a headline of their own, and the two Rust-only shapes join
the translation list. The two hint clauses are now handed to the dictionary as a parameter, so
the sentence boundary is decided in the file that knows how the language ends a sentence.

`npm run check:errors` provokes seven failures twice each — once from the real `agentmon` binary
(`--json`, which carries core's own `kind` and the exact string the desktop receives), once from
the dev server — and requires the same kind, the same headline, the same answer about a retry, no
English outside code spans, and no two clauses joined by a space. Rust holds the other end: two
tests in `error.rs` pin the Display strings the JS matches.

## For humans

In the desktop app, a link to a record that is not there brought up a line saying it could not read the folder its records live in. The same click in the same app running in a browser said something else: this project has no `BUG-9999`. One thing had gone wrong; the two builds named it differently.

**The code sorted failures by a number only one of them carries.** It asked first whether the failure arrived with the code 404, the web's number for "no such thing". The browser side sends one; the desktop side hands failures back as plain text with no number, so the answer was always no and every dead link there was filed as a disk it could not read. It is like sorting the post by postmark when half of it was delivered by hand.

**`failureKind()` now decides from the words instead.** Both halves of the app write those messages the same way, so the words are the reliable part, and the number only breaks a tie.

**Two more faults only the desktop could show.** A line under the headline said, in Korean, *the file path that was found* — the reverse of what happened; it now says the path it went looking for. A closing clause that only the desktop's back end writes ran into the sentence before it with no full stop, because nothing joined them; the join is made in the word list now, by the file that knows how Korean ends a sentence. A third message, for a mistyped record number, reached Korean readers as raw English under a headline blaming the disk; it has a heading of its own now.

**The old check only ever drove the browser**, so none of the three was reachable by it. `npm run check:errors` provokes seven failures twice each — once through `agentmon`, the command-line tool that reads and writes these records and hands back the exact text the desktop gets, and once through the browser — then demands the same verdict, the same headline, the same answer about retrying. Put the number-first sorting back and it fails every missing-record case, saying the two disagree; drop that full stop and it names the clauses stuck together.

**Then I opened the real desktop window and clicked it.** From the dashboard into `WORK-0025` and onto its dead link: the card says this project has no `BUG-9999`, over one sentence giving the file it looked for, and offers no try-again button: trying again cannot find a record that is not there. One press of the language switch gives the English pair.

Two doors into the same room should not disagree about what just went wrong.
