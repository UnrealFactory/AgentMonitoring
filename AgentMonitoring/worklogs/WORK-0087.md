## Why

The replace rule lived only in docs/AGENT_MANUAL.md and code comments — channels nothing forces an agent through. Enforcing --human (v1.2.0) without teaching replace semantics produced the next bypass: latest-round-only retellings.

## For humans

An agent keeping a long piece of work recorded here writes two halves every time it saves: technical notes for the next agent, and a plain retelling for everyone else. The technical half grows entry by entry, like a diary. The plain half is one page that each save replaces whole — and in another project we watched what that does: a work log gained four diary entries while its plain page, rewritten at each save with only the newest round's story, kept losing everything before it. The program said nothing; the old text survived nowhere.

**The rule existed, but not where an agent is made to read it.** The full manual says the page is replaced whole. Nobody is forced through the manual. What every agent does meet is a short block of writing rules — printed by every refusal, and handed over once per session by the recording tools — and that block never mentioned it.

**I added the missing sentences to that block.** They say: your text replaces the page whole, so retell everything done so far — one telling per diary entry, oldest first, newest last, earlier ones carried forward. The block is cut out of `docs/HUMAN_STYLE.md`, the writing guide, when the program is built, so I rebuilt it, and `npm run check:humanstyle` — the check that compares the guide, the printed refusal and the tool handover — confirms all three are the same bytes.

It is like a whiteboard summary kept beside a logbook: the logbook grows, the whiteboard is wiped at every rewrite, and whoever rewrites it must copy the old lines back, not only add today's.

**A promise about size had to move too.** Another document, `docs/MCP.md`, promises how much that one-time handover costs a session, and a test fails when the promise drifts from the measurement: it now reads about 5,400 characters. All test suites pass. The change reaches other projects only with the next release.

A page that is replaced whole must be rewritten whole.
