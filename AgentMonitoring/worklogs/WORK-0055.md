## What

Replaced the visible PowerShell console update with the AgentCodeGUI-style flow: a hidden worker script (CREATE_NO_WINDOW) downloads/installs/relaunches, while a WPF splash card (app-token colors, '새 버전으로 업데이트하는 중' + indeterminate bar) covers the gap. Splash self-closes when the fresh app process appears (StartTime > t0), 180s failsafe; on failure the worker kills the splash and raises a MessageBox. Worker logs to %TEMP%\agentmonitoring-update.log. Updated i18n update.applying, AppUpdate/api doc comments, README.

## Why

User asked for the AgentCodeGUI experience — a dedicated '설치중' window — instead of a raw console scrolling behind the app.

## How

src-tauri/src/update.rs: update_script() rewritten (no Write-Host narration, log file + Stop-Process splash + WPF MessageBox on error), new splash_script() (XAML via here-string; version sanitized before entering XAML), install_app_update() spawns splash first (pid passed into worker, 0 if splash fails — splash is decoration), exit delay 600ms→1200ms so the splash overlaps the closing window. spawn_update_console→spawn_hidden_powershell (CREATE_NEW_CONSOLE→CREATE_NO_WINDOW). Raw string needed r## because XAML contains '"#'. Tests updated + new splash test; live smoke test confirmed the WPF card renders from PowerShell 5.1.

## Outcome

Shipped: update now runs behind a WPF splash (hidden worker + message-box errors). cargo test -p agentmonitoring 12/12 green incl. new splash test; tsc clean; splash XAML smoke-tested live from PowerShell 5.1 on this machine.
