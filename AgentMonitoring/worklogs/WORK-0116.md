## What

실행 중인 개발 앱의 검은 화면 문제를 재현하고 오류를 수집해 원인을 수정합니다. 변경 반영을 반복해도 앱이 유지되거나 정상 복구되는지 확인하고 현재 개발 앱을 사용할 수 있는 상태로 되돌리면 완료합니다.

## Why

사용자가 패치할 때마다 개발 앱이 검은 화면이 되어 재부팅해야 한다고 첨부 화면으로 보고하셨습니다. 기존 검사는 새로 연 브라우저에서 동작을 확인했으나 켜 둔 데스크톱 창의 코드 갱신 경로를 검증하지 못했습니다.

## How

개발 서버의 변경 반영 로그와 실제 WebView2 오류를 조사하고, 실행 중인 앱에서 코드 변경·복원과 빌드·검사 서버 간 영향을 재현합니다. 확인된 원인에 맞춰 개발 갱신 또는 복구 처리를 수정하고 반복 검증합니다.

## Updates

### 2026-09-08T11:18:24Z

실제 WebView2에서 번역 파일 동시 주석 패치만으로 useApp 컨텍스트 연결 오류와 #root 비움을 재현했습니다. 개발 교체 시 컨텍스트 객체를 보존하는 stableContext.ts를 추가하고 앱·우클릭 메뉴·프로젝트 삭제·폴더 편집·레코드 제목의 다섯 컨텍스트에 적용했습니다. 수정 후 실제 앱에서 3회 변경+3회 복원을 반복하며 화면 문구 갱신, 창 재로딩 없음, 작성 중 폴더 이름 보존, 오류 0건을 확인했습니다. 자동 check:hmr도 같은 6회 갱신을 통과했고 --without-fix 대조 실행은 첫 패치에서 기존 useApp 오류로 실패했습니다. 빌드와 폴더 회귀 22개가 통과했으며 일반 개발 실행 모드로 복귀 중입니다.

## Outcome

BUG-0030을 실제 WebView2에서 재현하고 수정했습니다. 번역 파일 동시 주석 변경으로 #root가 36,745자에서 0자가 되고 useApp must be used inside <AppProvider>가 발생했습니다. HMR 묶음 간 교체로 React 컨텍스트 객체가 달라지는 원인이었습니다. stableContext.ts를 추가해 개발 중 컨텍스트 객체를 Vite hot.data에 보존하고, 앱·우클릭 메뉴·프로젝트 삭제·폴더 편집·레코드 제목의 다섯 컨텍스트에 적용했습니다. 일반 빌드는 React createContext 동작을 유지합니다.

회귀 검사 scripts/check-hmr.mjs는 격리한 소스 사본에서 실제 화면 문구·공유 모듈을 변경/복원합니다. 수정본은 6회 갱신 중 화면 재로딩과 빈 루트·오류 없이 열린 대화상자의 미저장 내용을 유지했습니다. --without-fix 대조 실행은 첫 패치에서 기존 useApp 오류로 실패해 검출력을 확인했습니다. 실제 데스크톱 앱에서도 6회 문구 변경/복원, 오류 0건, 재로딩 없음, 미저장 입력 보존을 확인했습니다. npm run build, check:project-folders 22개, git diff --check도 통과했습니다.

진단용 소스 변경은 모두 원문 복원했습니다. 진단 프로세스를 종료하고 일반 tauri dev를 5175로 재시작했으며 앱 프로세스 38608, 서버 30644와 수정 모듈 HTTP 200 응답을 확인했습니다. README·주제 노트·필수 색인과 앱 피드백을 갱신했습니다. 설치본 배포는 하지 않았습니다.

### 2026-09-08T11:18:24Z

검은 화면의 원인이었던 공유 상태 연결을 코드 교체 사이에도 유지하도록 수정했습니다. 실제 개발 앱에서 문구를 바꿨다가 되돌리는 검사를 여섯 차례 해도 화면과 작성 중 내용이 유지됐습니다. 같은 자동 검사를 수정 전 방식으로 실행하면 기존 오류가 다시 발생하는 것도 확인했습니다.

### 2026-09-08T11:20:46Z

패치할 때 개발 앱이 검은 화면으로 남는 오류를 수정했습니다. 코드가 교체되는 동안 화면의 공유 상태 연결이 달라지지 않도록 바꿨습니다.

실제 앱에서 코드 변경과 복원을 여섯 번 반복해도 화면과 작성 중 내용이 유지됐습니다. 자동 검사도 통과했고, 수정 전 방식에서는 같은 오류가 다시 발생해 검사가 문제를 제대로 잡는 것을 확인했습니다. 지금은 진단 모드를 끝내고 일반 개발 앱과 서버를 다시 실행해 두었습니다.
