## What

Four fixes from external app feedback plus one owner wish, shipped together: (1) frontmatter list values (`files`, `tags`, `refs`, `labels`) are quoted whenever they carry a flow indicator — `[`, `]`, `{`, `}`, `,` anywhere in the value, not only at the start — so a Next.js dynamic-route path like `src/app/api/payments/[id]/route.ts` round-trips (crates/agentmon-core/src/model.rs `yaml_scalar`; FB-0003/FB-0004); (2) one unreadable record no longer locks the project: `Store::worklogs`/`bugs`/`notes` skip a file that fails to parse and doctor names it, with the quoted spelling in its fix hint (store.rs, doctor.rs); (3) `validate::work_body`'s "`## X` is empty" refusal names the heading that swallowed the section when a field began with its own `## ` line (validate.rs; FB-0004 side note); (4) MCP `log_work` pre-flights the closing step before `work start` runs — an unparseable or future `finished_at`, a finish before the start, or a `## ` heading in the outcome is refused with nothing written (mcp/lib/tools.mjs; FB-0003 side note); (5) record images open full size on click — every drawn `<img>` is wrapped in a zoom button, and `ImageLightbox` holds the modal lock and closes on Escape or any click (src/lib/markdown.tsx, src/styles/app.css, i18n en/ko).

## Why

External feedback the owner pasted on 2026-08-27. FB-0003 and FB-0004 are the same bug from two projects: `yaml_scalar` quoted only values *starting* with an indicator, so a bracketed path mid-list opened a nested sequence, the record's frontmatter stopped parsing, and every project-wide read exited 6 `invalid_project` — the "do not hand-edit records" rule collided head-on with "nothing works until you hand-edit". Both reporters asked for the same two things: quote the values, and let one broken record not take the whole project down. FB-0002 (`refs: []` read as "no change", so a dead ref could not be pruned) turned out to be already fixed in this source (commit 67035f8: `replaceListFlag` sends `--refs ""`, clap+`clean_list` read that as an empty replacement); it was verified end-to-end in a sandbox and left alone. The lightbox is the fourth item, an owner wish: attached photos were readable only at column width (560px cap), and reading one meant opening the file outside the app.

## How

The quoting fix is one arm in `yaml_scalar`'s contains-check — a quoted scalar is legal everywhere in YAML, so nothing else moves; the round-trip test pins the exact reported path. The lists skip with `let Ok(detail) … else continue`, deliberately non-silent: doctor already walks the raw files and reports the parse error per file, the by-id read still errors (which is what `update_work` against the broken record should say), and `record_ids` reads filenames, so a corrupt record still reserves its number. Deviation to note: SPEC.md's worklog example shows unquoted flow items; a quoted item is the same YAML shape, so the spec text stands unchanged.

The MCP pre-flight duplicates only the *closing* step's rules (`whenInstant` mirrors time.rs's accepted forms, `FUTURE_SKEW_MS` its 60-second skew, `sectionHeading` is fence-aware like body.rs): `work start`'s own refusals already run before any record exists, and the leading-`##` case is now answered by the core's improved message — the MCP suite asserts that message through the wire and that a refused call leaves the worklogs directory untouched. The lightbox reuses `useModalLock` so window-level key handlers stand down, sits on the modal layer's scrim, keeps the figure's inset well behind transparent SVGs, and returns focus to the button that opened it; proven in the running browser app with a Playwright probe (opens on click, closes on Escape and on scrim click) and screenshots under progress/shots/.

## For humans

![대괄호 경로가 목록 줄을 깨뜨리는 모습과, 따옴표로 감싸 살아남는 모습](assets/work-0094-1-a-bracket-breaks-the-line.svg)

이 앱을 다른 프로젝트에서 쓰던 에이전트들이 같은 사고를 두 번 제보했습니다(제보 번호 FB-0003, FB-0004). 작업을 저장하면 기록 파일 머리에, 건드린 파일 이름들이 한 줄 목록으로 적힙니다. 파일 이름에 대괄호가 든 경로가 오면 — 요즘 웹 프로젝트는 `[id]` 같은 폴더 이름을 흔히 씁니다 — 그 대괄호가 목록의 여는 괄호로 잘못 읽혔습니다. 줄 하나가 통째로 못 읽는 글이 됐습니다.

**깨진 줄 하나가 프로젝트 전체를 잠갔습니다.** 이 앱의 명령 도구 agentmon은 프로젝트를 열 때 기록을 전부 읽는데, 못 읽는 파일 하나를 만나면 읽기 전체를 포기했습니다. 그래서 기록 하나가 깨지면 목록도, 현황도, 새 저장도 전부 막혔습니다. 제보한 에이전트는 "기록 파일을 손으로 고치지 말라"는 규칙과 "손대지 않으면 아무것도 못 한다"는 상태가 정면으로 부딪힌다고 썼습니다.

**고침의 절반은 따옴표입니다.** 이제 목록에 적히는 값에 괄호나 쉼표가 들어 있으면 저장할 때 그 값을 따옴표로 감쌉니다. 명단을 쉼표로 나눠 적는 종이에 "김, 철수"라는 이름을 올리려면 따옴표로 감싸는 것과 같습니다. 감싸면 기호가 이름의 일부로 읽힙니다.

![깨진 기록 하나를 만난 목록: 전에는 전부 잠김, 이제는 그 하나만 건너뜀](assets/work-0094-2-one-file-locked-the-list.svg)

**나머지 절반은 잠금 풀기입니다.** 어떤 이유로든 못 읽는 기록이 남아 있어도, 이제 목록은 그 파일만 건너뛰고 나머지를 보여줍니다. 건너뛴 사실은 숨지 않습니다. 점검 명령 agentmon doctor — 프로젝트의 기록이 성한지 훑어 주는 명령입니다 — 가 그 파일 이름과 깨진 자리를 짚어 줍니다. 그 기록을 번호로 직접 열면 무엇이 잘못됐는지 그대로 말합니다.

![한 번에 보내는 만들기-닫기 두 걸음과, 첫걸음 앞으로 옮겨진 거절](assets/work-0094-3-refused-before-the-first-step.svg)

**반쪽 기록이 생기는 사고도 막았습니다.** 에이전트는 호출 한 번으로 "기록을 만들고 닫기"까지 보낼 수 있습니다. 앱은 기록을 만들고 나서 닫는데, 끝난 시각이 몇 초 미래라는 이유로 닫기만 거절되면 기록은 생기고 닫히지 않은 반쪽 상태가 남았습니다(FB-0003의 곁가지 제보). 이제 그 검사를 기록을 만들기 전에 먼저 합니다. 거절되면 아무것도 쓰이지 않은 채 거절만 돌아갑니다.

**거절문도 범인을 짚습니다.** 본문 칸을 `## 제목` 줄로 시작하면 그 줄이 칸의 경계로 읽혀 칸이 비는데, 돌아오는 말은 "How가 비었다"뿐이었습니다(FB-0004의 곁가지 제보). 이제 거절문이 그 제목 줄을 이름으로 짚고, 산문으로 시작하라고 알려 줍니다. 예전 제보 FB-0002 — 참조 목록을 빈 값으로 비울 수 없다 — 는 지금 소스에 이미 고쳐져 있어서, 실제로 비워지는지 명령으로 확인만 했습니다.

![본문 속 그림 카드를 누르면 화면 크기로 열리는 모습](assets/work-0094-4-click-to-full-size.svg)

**그림은 이제 눌러서 크게 봅니다.** 기록에 붙는 사진과 도면은 지금까지 본문 폭 카드 안에서만 보였습니다. 크게 보고 싶다는 제보가 있었습니다. 이제 그림을 누르면 화면 크기로 열리고, Esc 키나 빈 곳 클릭으로 닫힙니다. 실제 앱 화면에서 자동 브라우저로 눌러 보아 열리고 닫히는 것을 확인하고 화면을 찍어 두었습니다.

**어떻게 아는가.** 러스트 검사 전부와 MCP 검사 213개가 통과했습니다. 대괄호 경로를 저장해 되읽는 검사, 깨진 기록을 옆에 두고 목록을 읽는 검사가 새로 들어 있습니다. 화면 쪽은 타입 검사와 빌드가 깨끗합니다. 다만 이 수정들은 아직 새 버전으로 배포되지 않았습니다 — 설치된 앱들은 다음 버전을 받아야 달라집니다.

대괄호가 든 파일 이름 하나가 더는 프로젝트 전체를 잠그지 못합니다.
