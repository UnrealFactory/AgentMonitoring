## What

Make a correction land where the reader is, and close the four small notes the passing P6
gates left behind.

The main change is in three parts. `agentmon-core` now lets `agentmon work update` append a
note to a work log that has already closed — nothing above `## Updates` is touched, the
status and timestamps do not move, the event is still `work_updated`, and the note must be
dated at or after `finished`. The record renderer gives a note whose author opened it with
`Correction:` its own marker in the timeline and a one-line chip directly under the record's
title: "1 correction to this record — see Updates". And WORK-0011 now carries such a note,
appended through the CLI by `p6-curator`, correcting the four claims in it that are false
against this repository and citing BUG-0017 and BUG-0018.

The four small ones: inline record-id chips no longer add 4px of advance on each side, so
`BUG-0016's` reads as written; a vault the desktop app finds beside its own executable now
reports the source `exe/vault` instead of borrowing `flag`; the first-run screen points at
`agentmon --help` and names `docs/AGENT_MANUAL.md` only when it is on the machine; and the
manual's Recipe 2 shows `--refs` on `bug create` with the reason.

## Why

The P6 comprehension gate failed three times on the same record, and by round 3 its verdict
was that the reader was right and the record was wrong: WORK-0011's `## How` says "relay is
three weeks of ten agents" (relay has four) and its `## Why` cites BUG-0004 for a clipping
defect BUG-0004 is not about. Both were already filed — BUG-0017 and BUG-0018 — and both
corrections lived only in the **Referenced by** block, thousands of pixels below the
sentences they correct. A reader who stopped at the prose left with two wrong facts; a reader
who reached the bottom got a contradiction with nothing marking which side was current.

The blocker was self-imposed. Append-only means nothing already written is changed; it does
not mean a record can never be corrected. `update_work` refused a finished record outright
("a finished work log is a historical record"), which pushed every correction out into some
other record and made the honest repair — a note dated when the error was found, inside the
record that carries the error — impossible. Allowing the note costs nothing that matters: the
body above `## Updates` is still never rewritten, the state machine is untouched, and the
note cannot pretend to predate the close.

Weight on the page is the other half. A correction the reader meets after the sentence it
corrects is a correction they have already believed the wrong version of, so the marker has
to be above `## What`. It is driven only by the author's own `Correction:` prefix: the app
never reads prose for facts, never pairs a correction with the sentence it corrects, and
never decides which of two claims is true. It carries the author's flag up the page.

## How

**Core.** `update_work` drops its status guard; `require_note_time` gains a third floor —
on a record whose status is not `in_progress`, the note must be at or after `finished` —
so a correction cannot be backdated into the run it corrects. `work done` and `work abandon`
still refuse a closed record, which is the rule that was actually load-bearing. Two tests
changed from asserting the refusal to asserting the new contract: status, `finished`,
outcome and `## What` all unchanged, one note appended, the event `work_updated`, the
record's last activity now the correction, and a note dated inside the run refused.

**Renderer.** `src/lib/updates.ts` holds the whole rule: strip the `_Update by <name>._`
byline the CLI writes when the note's author is not the record's, then test the author's
first characters for `Correction:`. `CorrectionNotice` (chip under the title, links to
`#updates`) and `CorrectionMark` live in `components/ui.tsx` and are used by both detail
pages — a work log's updates and a bug's comments are the same object, so a correction on
either is drawn the same way. The correction's card takes the app's amber (attention, not
alarm), its rail dot with it, and the head reads `p6-curator · Correction` instead of
"posted update 2" — the byline the CLI used to leave as the first italic line of the prose
is now shown as a byline.

**The chips.** `a.ref-inline` was `padding: 0 4px`, which is advance width: the chip pushed
the next character 4px away, so a possessive rendered as "BUG-0016 's" and a chip ending a
sentence stood off its own full stop. Padding is now painted by a `box-shadow` spread, which
is ink and takes no space in the line.

**Vault source.** `Vault::open_beside_exe` reports `exe/vault`; the desktop app's `discover()`
uses it, and the projects screen names it "the vault folder beside the app". It used to go
through `Vault::open`, which reports `flag`, so the one place a human can check which vault
they are on said "Opened from the folder opened in this app" about a folder nobody opened.

**First run.** A new `manual_path` command answers whether `docs/AGENT_MANUAL.md` is on this
machine (an installed copy is two executables and no docs directory). The screen names
`agentmon --help` — with the real path to the shipped binary, as the command lines above it
already do — and mentions the manual only when it is there.

## Outcome

**Shipped: a correction can now live inside the record it corrects, and it reaches the
reader before the sentence it corrects does.**

`agentmon work update` appends to a work log that has already closed. The status, the
timestamps, the outcome and every byte above `## Updates` are untouched; the note lands at
the end of the timeline; the event is still `work_updated`; and the note has to be dated at
or after `finished`, so a correction cannot be backdated into the run it corrects.
`work done` and `work abandon` still refuse a closed record — that was the rule worth
keeping. The CLI says which it did: "Appended to a done record: status, timestamps and
everything above ## Updates are unchanged."

**WORK-0011 now carries its own corrections**, appended by `p6-curator` at
2026-08-19T08:00:40Z, citing BUG-0017 and BUG-0018 and correcting four claims: relay has
four agents and not ten; the clipping defect's same-class record is BUG-0009, not BUG-0004;
`charts.tsx` never shipped the promised "table-view twin"; and the fixed Agents card is a
CSS grid, not a list of flex rows. Its own sentences stand as written — that is what an
append-only vault costs, and it is the point.

**The page gives it weight.** On /p/agent-monitoring/work/WORK-0011 at 1440px the reading
order is now: title at y=73, then at **y=147** an amber chip reading "1 correction to this
record — see Updates" that links to the note, then the byline, the fact strip, and only then
`## What` at y=283, the BUG-0004 sentence at y=656 and the "ten agents" sentence at y=978.
The correction is 509px above the first sentence it corrects and 831px above the second,
where before it was 3,700px below both, in Related. In the timeline the note itself is an
amber card with an amber rail dot and a head that reads "p6-curator · Correction" instead of
"posted update 2".

The affordance is generic and blind: `src/lib/updates.ts` strips the `_Update by <name>._`
byline the CLI writes for a note by another agent, then tests whether the author's own text
opens with `Correction:`. That is the entire rule. Nothing reads prose for facts, pairs a
correction with the sentence it corrects, or decides which of two claims is true — the page
carries the author's own flag up to where it can be seen in time. The same component draws a
bug comment that opens the same way.

- **The first screen points at something the reader has.** An installed copy is two

**Not done, deliberately.** Inline `code` spans still carry `padding: 1px 4px` and so still
push punctuation 4px away; the same fix would apply, but code spans are on every screen in
the app and the design gate passed on their current weight, so that is a change to make with
a design pass rather than inside a correctness fix. And nothing was added that infers *which*
sentence a correction is about: the reader is told a correction exists and taken to it, and
the author's own words do the rest.

## For humans

A reader read one of this project's write-ups, `WORK-0011`, and came away with two untrue facts. It says `relay`, the companion project, ran with ten agents; it has four. And it points at `BUG-0004` for a display defect that bug is not about. Our check on whether a reader can follow a record failed it three times. By the third round the verdict was that the reader was right.

**Both corrections were already written down as bug reports, `BUG-0017` and `BUG-0018`, and nobody met them in time.** The page listed them at the foot of the record, thousands of pixels under the sentences they correct. Anyone who read the prose and stopped left with both wrong facts.

**The rule blocking the honest repair was our own.** Records here are append-only: what is written stays written. But the tool refused to add anything at all to a finished piece of work, so a correction had to go into some other record.

**A closed record now takes a note.** `agentmon work update`, the command that adds a dated note to a piece of work, accepts one after the work is done. Nothing already written moves. A note cannot be dated before the work closed, so nobody can slip a correction into the run it corrects.

**The page carries the author's own flag to the top.** Open a note with the word `Correction:` and a line appears under the record's title saying one exists, and linking to it. `src/lib/updates.ts` holds that entire rule. Nothing reads the prose for meaning, and nothing decides which of two claims is true.

It is like a sticker on a book's cover, put there by the author rather than a proofreader.

**I wrote the corrections in and measured the page.** The new line sits 509 pixels above the first wrong sentence and 831 above the second. Both corrections used to sit 3,700 pixels below them. `cargo test --workspace` gained a check that a correction leaves the state, the closing time and the original words untouched.

**Four smaller notes came from checks that had already passed.** An id written into a sentence used to push the next character four pixels away, so "BUG-0016's" printed as "BUG-0016 's" and an id ending a sentence stood off its own full stop. That breathing room is painted on now instead of taking up room, and across five of them on one page the gap measures zero.

A folder the app finds sitting beside its own program used to be described as "opened from the folder opened in this app" — about a folder nobody opened. It says the folder beside the app now, and that line matters because it is the one place a person can check whose records they are reading. The first screen an installed copy shows used to send the reader to a manual that an installed copy does not include; it names the program's own `--help` instead, and mentions the manual only when it is really on the machine. And the manual's recipe for filing a bug you hit mid-job now passes `--refs`: naming a record in a sentence links one way, `--refs` links both, and only `--refs` puts the new bug on that work log's own page.

**The wrong sentences still stand, word for word.** They are never edited; that is what append-only costs. A reader is told a correction exists and taken to it, and the author's words do the rest. Quoted code still shoves punctuation the same four pixels — the same repair would work, but code appears on every screen here, so that belongs to a design pass rather than to a correctness fix.

A correction nobody meets in time is not a correction.
