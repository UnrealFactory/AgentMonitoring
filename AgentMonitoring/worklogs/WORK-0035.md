## What

Replaced the central vault with per-project storage, end to end. One project is now one
`AgentMonitoring` folder inside the repo it describes (project.json v2 with an immutable
id, no slug, no status; events/worklogs/bugs unchanged). The machine's project list lives
in `~/.AgentMonitoring/registry.json` — paths only. Rewritten across every layer:
agentmon-core (Store/registry/migrate replace Vault), the CLI (git-style resolution:
--dir > AGENTMON_DIR > walk-up; -p and --vault removed; init creates the project;
`agentmon migrate` is the v1 bridge), the Tauri shell (registry-driven multi-project, one
watcher per folder, per-row availability, delete keyed by id and confirmed by typed
name, remove-from-list keyed by path), the frontend (routes by project id, Projects
screen with location picker / Open project… / unavailable rows / Remove vs Delete, i18n
en+ko reworded off the vault vocabulary), browser mode (project-fs/vite-project-api over
AGENTMON_DIRS with session add/remove), the MCP server (--dir identity), every gate
script, SPEC.md, README, CLAUDE.md, MCP.md and this manual. This repo's own history was
migrated with the new command and the vault directory deleted.

## Why

The owner reviewed where the installed exe stores data and rejected the central vault:
records should live next to the code they describe, travel with that repo's git history,
and the app should show every project at once — the git model (.git per repo, a local
bookmark list) instead of the Obsidian model. Design agreed first (docs/SPEC-v2-draft.md,
adopted into SPEC.md), with a standing performance requirement: no felt slowdown and no
memory bloat from watching N folders. Also fixed along the way: gate CLIs were
registering their temp fixtures into the real user registry (AGENTMON_REGISTRY_DIR now
isolates them), and "folder unreachable" is now distinguished from "id not registered"
so an unplugged drive dims a row instead of replacing an open screen with an error card.

## How

Core first: store.rs (open accepts the folder or its parent; resolve walks up like git;
v1 project.json is refused with the migrate hint), registry.rs (best-effort by design),
write.rs (slug-free mutations; delete only ever removes a canonicalised folder actually
named AgentMonitoring — never the code around it), migrate() copying records
byte-for-byte and keeping the v1 id so links survive. Then each wrapper thinned onto it,
tsc used as the worklist for the frontend, and every Playwright gate converted and
re-run rather than retired — check:vault became check:projects (served-set authority,
moved/CRLF copy parity modulo the reader-filled path/source fields).

## For humans

The owner looked at where an installed copy of this program keeps its data and said no. Every project's records sat together in one central folder, off to the side, while the code they described lived somewhere else.

**Now a project's records live inside the project.** One project is one folder named `AgentMonitoring`, sitting in the code it describes. It travels with that code, so the history moves whenever the code does.

It is like keeping a car's service book in the glovebox instead of on a shelf at home.

**The machine keeps a list of where those folders are.** `~/.AgentMonitoring/registry.json` sits in your home folder and holds paths and nothing else. The app reads that list and shows every project at once.

**Nothing has to be told which project you mean any more.** `agentmon`, the command-line tool that writes these records, walks up from wherever you are standing until it finds one of those folders — the way `git` finds its own. `-p`, the old option for naming a project, is gone.

**Every layer had to change in one go**: the core, that tool, the desktop app, the screens, the browser version and every automatic check.

**The Projects screen can now add and drop projects.** To add one you pick its folder on the disk, through a location picker or through `Open project…`. A row you no longer want can be taken off the list, which only forgets where that folder was. Deleting it outright is the other choice, and that one goes ahead only once you have typed the project's name.

**Two faults surfaced on the way, neither of them the job.** The checks had been registering their own throwaway folders into the real user's list; `AGENTMON_REGISTRY_DIR` now keeps them apart. And a folder on an unplugged drive used to replace whatever screen you had open with an error card; the app now tells "cannot reach it" apart from "never heard of it", and dims that row instead.

**Deleting had to learn what it is allowed to touch.** It only ever removes a folder that really is one of these, resolved to its true place on disk first, so it can never take the code sitting around it.

**This project's own history was the first thing moved.** 34 work logs, 22 bugs and 191 recorded events went across, compared byte for byte against the old store before it was deleted. `cargo test --workspace` passes 94 tests, including ones that hand the delete a renamed folder, or a shortcut pointing at one, and watch it refuse. Every screen check was converted and run again rather than retired.

**What is different: your records ride along with your code.** A folder still in the old shape is refused, with the instruction to bring it across with `agentmon migrate`, rather than half-read.

Records kept beside the thing they describe are the only ones that follow it.
