## What

WORK-0107의 제안을 바탕으로 지침 템플릿과 기존 프로젝트 갱신, MCP 기록·기억 조회, 사람 설명·시각화 규칙을 일치시킵니다. 격리한 프로젝트에서 서브에이전트가 실제 기록 작업을 수행하도록 하여 정책 준수를 확인합니다.

## Why

같은 주제의 질문마다 WORK가 생성되고 SVG가 문장 상자 위주로 나오는 문제를 사용자께서 실제 수정하고 서브에이전트로 검증해 달라고 요청하셨습니다.

## How

작업 목적·완료 조건에 따른 기록 경계를 정하고, 핵심 관계에 맞는 시각화 지침을 작성합니다. 기존 파일의 사용자 내용을 보존하며 지침을 갱신하고 노트 조회 누락을 줄입니다. 기존·수정 지침을 읽은 에이전트의 기록 선택을 비교하고 코드 검사를 수행합니다. 모든 시험 데이터는 실제 프로젝트 및 사용자 레지스트리와 분리합니다.

## Updates

### 2026-09-06T10:03:32Z

정책 v4·한/영 템플릿 v2와 안전한 기존 구간 갱신, 노트 페이지 이동 및 work-/bug- 노트의 refs·UI 경로 수정을 구현했습니다. 기존 지침을 읽은 에이전트는 설계 질문 세 번에 완료 WORK 2개와 Correction 업데이트 1개를 만들었습니다. 새 지침 에이전트는 같은 질문에 WORK 0개, 미확정 reference 1개를 남겼습니다. 구현 착수 후에는 WORK-0001 하나를 in_progress로 유지하고 사용자 채택을 decision에 반영한 뒤 handoff를 남겼습니다. 현재 별도 새 에이전트가 기록만 읽고 검증을 이어받는 시험 중입니다. 코드 검사와 diagram geometry 검사는 통과했으며 독립 리뷰에서 발견한 옛 doctor 안내 문구와 SVG viewport 비율·원점 검사 문제도 수정했습니다.

## Outcome

WORK 경계·현재 지식 관리·내용별 시각화 정책을 구현하고 실제 서브에이전트 행동으로 검증했습니다. 한/영 템플릿 v2, HUMAN_STYLE v4와 MCP 도구 설명이 목적·완료 조건을 기준으로 일치합니다. 지침 생성은 version marker 구간 및 완전 일치 legacy만 갱신하고 사용자 내용·기존 언어를 보존하며, 수정 legacy·손상/미래 marker는 안전하게 거부합니다. 이 저장소의 AGENTS.md와 CLAUDE.md에도 적용했습니다.

노트 목록에 limit/offset과 완전한 이름·설명 단위 출력을 제공하고, work-/bug- 노트의 refs·링크·메뉴 오인을 수정했습니다. doctor는 문단 구조로 그림을 요구하지 않으며 새 정책에 맞는 안내를 제공합니다. 그림 검사에는 --asset 초안 선택, 실제 글꼴·조상/루트 변환·viewBox 원점·양수 고정 크기 검증을 추가했습니다. 독립 리뷰가 발견한 실제 오류를 고치고 같은 에이전트가 재현 해소를 확인했습니다.

행동 비교: 동일한 개념 설명→대기 제안→Entity 관계 정정에서 baseline은 완료 WORK 2개+Correction 업데이트 1개, updated는 WORK 0개+미확정 reference 1개였습니다. 구현 요청 뒤 updated는 WORK-0001을 진행 중으로 유지하고 기존 노트를 decision으로 갱신, handoff를 남겼습니다. 이전 대화를 받지 않은 resume 에이전트가 기록만 읽어 자동검사 12/12·예제·구문 검사와 관계도를 마친 후 같은 WORK를 완료하고 handoff를 제거했습니다. 독립 비교 보고서는 WORK-0002로 완료했습니다. 최종 시험 프로젝트를 직접 조회해 WORK 2개 done·진행 0개·decision 1개·handoff 0개를 확인했습니다.

검증: Rust 코어·CLI 전체 테스트, 최종 doctor 집중 11개, MCP 최종 267개, 지침 생성 CLI·브라우저 33개, Markdown smoke 1,062개, geometry 회귀 7개와 프로젝트 그림 27개, 프런트엔드 build 및 Tauri cargo check가 통과했습니다. 최종 소스 대상 git diff --check도 통과했습니다. HUMAN_STYLE 전체 16,377자·compact 5,491자의 소스/내장 CLI/응답 일치를 검증했습니다.

정책 결정과 시험 절차·결과는 기존 work-boundaries-and-explanatory-visuals-proposal 노트를 갱신하고 start-here에 연결했습니다. human-area-enforcement·scene-geometry-is-measured 기억도 v4로 갱신했습니다. FB-0003·FB-0004의 설명에 수정 결과를 반영하고 검사기 문제는 FB-0005에 기록했습니다. 시험 에이전트가 만든 최종 SVG·395px PNG를 assets/에 보존했습니다.

이는 제한된 실제 시나리오 검증이며 모든 모델·대화에서의 성공률을 보장하지 않습니다. 저장소 지침과 재빌드한 개발용 CLI에 반영했지만 설치 앱 공개 배포·실제 클라이언트 재연결·다른 프로젝트 지침 갱신은 하지 않았습니다. .codex/config.toml의 설치 서버 연결도 유지했습니다.

## For humans

같은 개발 주제의 대화마다 기록이 늘어나고, 그림이 문장을 상자에 넣은 형태로 만들어지는 문제를 수정하기 시작했습니다. WORK는 하나의 개발 목적을 이어가는 기록으로, 노트는 다음 작업에도 필요한 현재 지식을 담는 곳으로 안내하겠습니다.

설명 그림은 관계와 순서가 보이도록 지침을 바꾸겠습니다. 서브에이전트가 별도의 시험 프로젝트에서 기록을 남기도록 하여 실제 선택을 확인하겠습니다. 현재는 작업 착수 단계이며 수정과 검증은 아직 완료하지 않았습니다.

### 2026-09-06T10:03:32Z

같은 설계 질문 세 번으로 기존 지침과 새 지침을 비교했습니다. 기존 방식은 작업 기록 두 개를 완료하고 정정을 추가했습니다. 새 방식은 작업 기록을 만들지 않고, 이어서 필요한 범위 정정만 미확정 참고 노트에 남겼습니다.

실제 구현을 요청하자 새 방식은 작업 하나를 열었습니다. 검증을 다음 세션에 맡기라는 요청에 맞춰 진행 중으로 유지하고 인계 내용을 저장했습니다. 지금은 이전 대화를 모르는 에이전트가 그 기억을 읽고 검증을 이어가는 중입니다. 이 결과는 이번 시험 사례에 한정되며 모든 대화에서의 성공을 보장하지는 않습니다.

### 2026-09-06T10:09:47Z

기록 기준과 그림 작성 지침을 수정하고 서브에이전트가 실제로 어떻게 기록하는지 확인했습니다. 이제 질문이나 제안마다 작업을 만들지 않고, 목적과 완료 조건을 가진 개발·조사에 WORK를 사용하도록 안내합니다. 기존 프로젝트 지침을 갱신할 때는 사용자 내용을 보존합니다.

동일한 설계 대화에서 기존 지침은 완료 작업 두 개와 정정을 만들었습니다. 새 지침은 작업 없이 미확정 참고 노트 하나만 남겼습니다. 실제 개발을 요청한 뒤 중단하자 진행 중 작업과 인계를 유지했습니다. 이전 대화를 모르는 에이전트가 저장된 기억을 읽고 자동검사 12개를 마친 후 같은 작업을 완료했습니다. 별도 비교 조사는 다른 작업으로 기록했습니다.

코드 검사와 MCP 검사, 지침 생성 화면 검사, 그림 검사를 통과했습니다. 정책과 결과는 필수 색인에서 이어 읽을 수 있습니다. 저장소와 개발용 CLI에 반영했으며, 설치 앱 공개 배포는 아직 하지 않았습니다.
