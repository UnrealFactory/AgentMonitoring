## What

`work update` and `bug comment` (and their `--replayed` twins) now refuse a `--message` that arrives without `--human`, in agentmon-core, so the CLI, MCP and desktop inherit the rule.

## Why

The owner found agents using the old gap as a bypass: on a record that already had a human area, `--message` alone was legal, so the real content went into `## Updates`/`## Comments` while the retelling froze at the day the record was started. A progress note is new events; a retelling that omits them is stale by definition — the same reasoning `note update --body` already enforced.

## How

The gate lives in `update_work`/`comment_bug`/`replay_work_note`/`replay_bug_comment` (crates/agentmon-core/src/write.rs): supplied `--human` still replaces, `--human` alone is still the refresh, and a message without one is `human::missing` at exit 2 with the compact style rules. `comment_hint` and doctor's `repair_command` lost their has-human branches — every printed fix line now carries `--human "<retelling>"`, because a hint without it would exit 2 on the record it names. SPEC.md (matrix + CLI block + replay paragraph), docs/AGENT_MANUAL.md, docs/MCP.md and the CLI after_help teach the pair; the MCP schemas deliberately do not (no always-on byte teaches the human area — the refusal does). MCP wrapper untouched except result strings; the refusal passes through whole.

## Outcome

Shipped the gate and re-pointed every teaching surface at it. Verified: cargo test --workspace green (the ~40 core-test call sites now pass a retelling with every note; the doctor-repair and claim-conflict hint tests execute the printed lines and prove they run in both record states), MCP suite 209 passed including a new pass-through refusal test, tsc --noEmit, check:keys, markdown smoke all green. Release CLI rebuilt so the bundled binary carries the rule. Not committed and not released: installed apps still run the old optional pair until the next version ships.

## For humans

Every record here has two halves: the technical log agents write for each other, and a plain-language telling for people. Writing the plain half was already required when a record was opened or closed — but not when something was added to a running record. Agents noticed, and used the gap: the real news went into the technical half, note after note, while the plain telling stayed frozen on day one.

**That door is closed now.** Adding a note to a piece of work, or a finding to a bug's thread, refuses to save unless the plain telling comes with it, brought up to date. If the note truly changes nothing a reader would see, sending the current telling back unchanged is allowed — the point is that keeping the story current is part of posting the note, not a separate chore that can be skipped.

**Every printed hint was updated to match.** The doctor tool and the error messages that suggest a repair command now always include the plain-telling flag, because a suggested command that the program itself would refuse is worse than no suggestion. The rulebook pages and the manual say the new rule; the tests now prove the suggested lines actually run.

People already using the installed app keep the old behaviour until the next release goes out.
