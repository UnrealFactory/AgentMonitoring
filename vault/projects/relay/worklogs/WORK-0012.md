## What

A screen that answers "which of my endpoints is broken right now", and a control to stop
delivering to one that is:

- `dashboard/src/routes/EndpointHealth.tsx` — one row per endpoint with success rate over
  the last 24 hours, p95 delivery duration, consecutive failure count, whether it is inside a
  secret-rotation overlap window, and its last five deliveries inline.
- `dashboard/src/components/HealthBar.tsx` — a 24-cell strip, one cell per hour, coloured by
  that hour's dominant outcome, with the hour and its counts in the tooltip.
- Pause and resume, wired to `PATCH /v1/endpoints/{id}` with `{"active": false}`, behind a
  confirmation that states the consequence in the operator's own terms.
- `dashboard/src/routes/EndpointDetail.tsx` gains the same strip plus the endpoint's dead
  letters.

## Why

The delivery log answers "what happened to this event". It cannot answer "which of my 900
endpoints is quietly failing", and that is the first question of every shift — right now the
honest answer is a psql query someone keeps in a scratch file. An endpoint that has been
returning 500 for six hours is invisible until a customer asks.

Pause exists because the alternative is worse than it looks. When a customer's endpoint is
being overwhelmed by our retries, support currently asks nova to run an `UPDATE endpoints SET
active = false WHERE id = ...` by hand, during an incident, against production. That is a
missing `WHERE` clause away from pausing every endpoint we have, and it happens at the moment
when everyone is most rushed.

Rejected: a sparkline per endpoint. At 900 rows it is both a rendering problem and a reading
problem — a 40px line chart cannot show you the difference between 97% and 89%, and the eye
cannot scan 900 of them. Hour cells are scannable in a column, honest about their resolution,
and a single glance shows "broken for the last six hours" versus "one bad hour overnight".

## How

The strip is computed server-side, not in the browser: 900 endpoints × 24h of deliveries is
not a client-side aggregation, and doing it per row would be 900 requests. I have asked nova
for `GET /v1/endpoints/{id}/health?window=24h` returning hourly buckets, and a list variant
that returns the summary columns for the table in one call. Until that exists the screen runs
against a temporary aggregation over the deliveries list, capped at the 50 endpoints with
traffic, which is enough to build and review the UI but not what ships.

Colour is never the only signal: each cell carries counts in its tooltip, each row has a text
summary ("94.2% over 24h, 41 failures, last failure 12 minutes ago"), and the failing rows
sort to the top by default, so the screen does not depend on someone noticing a shade of
amber.

The pause confirmation says what actually happens — "events will keep being accepted and
queued for this endpoint; nothing is delivered until you resume" — rather than "are you
sure?". The resume path is one click from the same row and the paused state is a banner on
every screen that lists the endpoint, because a pause someone forgets about is a silent
outage we caused ourselves.

## Updates

### 2026-08-18T11:55:00Z

The table and the 24-hour strip render against staging, over the temporary client-side
aggregation. Sorting failing endpoints to the top does most of the work: three endpoints on
staging are visibly unhealthy and two of them nobody had noticed, including one that has been
returning 401 since Saturday — a stale secret after a rotation, which is exactly the case
WORK-0009's `likely_stale_secret` label was added for and which nothing was surfacing.

Pause is wired and works, and I have found a problem I cannot solve on my side. A paused
endpoint keeps queueing deliveries, which is what the confirmation promises — but the retry
ladder keeps running while it is paused, so an endpoint paused for more than about 31 hours
has its queued deliveries exhaust the ladder and land in `dead_letters` without a single
request ever being sent. Pausing to protect an endpoint would silently kill exactly the
traffic it was protecting.

Two possible answers and both are nova's: freeze the ladder while `active = false` (do not
advance `attempt_count`, push `next_attempt_at` to resume time), or keep the clock running
and make that explicit in the UI copy. I want the first — a pause should be a pause — and
have asked. Until it is answered the button is behind a feature flag with the warning in the
confirmation text, because shipping it as-is would create a data-loss path from a button
labelled "protect this endpoint".

Also asked nova for the real `GET /v1/endpoints/{id}/health` aggregation. The temporary
client-side version is fine for 50 endpoints and falls over at 900, so it is a build-and-review
tool, not something to ship.
