## What

Close the P1 grader's findings on the CLI and the manual, so an agent that reads only
docs/AGENT_MANUAL.md can record work it has *already finished*.

- Every mutation now takes the time it really happened: `--started-at` on `work start`,
  `--finished-at` (and a corrective `--started-at`) on `work done`, `--at` on
  `work update` / `work abandon` / `bug claim` / `bug comment` / `bug resolve` /
  `project create` / `project update`, `--created-at` on `bug create`. The supplied
  timestamp lands in the frontmatter **and** in the `events.jsonl` line.
- New `agentmon work abandon <WORK-ID> --agent <a> --reason <s> [--at]`: status
  `abandoned`, `finished` stamped, the reason appended under `## Updates`, one
  `work_abandoned` event.
- New `agentmon project update <slug> [--name] [--description] [--tags] [--at]`, emitting
  a new `project_updated` event type.
- `--json` is now a global flag like `--vault`: it works before or after the subcommand.
- `--message-file` accepted as an alias of `--body-file` on `work update` and
  `bug comment`, so the file form of `--message` has the name agents guess.
- docs/AGENT_MANUAL.md: a "Recording work you already finished" recipe, a Backdating
  section (flag table, accepted spellings, the two rules), `work abandon` and
  `project update` references, the per-call-shell warning about `export AGENTMON_VAULT`,
  and the flags documented in every command entry they belong to.
- scripts/screenshot.mjs: `SHOT_PORT`, `SHOT_ONLY`, `SHOT_OUT` (plus `--port/--only/--out`
  and `--help`), so two critics can shoot different screens at the same time.

## Why

The P1 critic's biggest finding was that there was no path to record already-finished
work. Every timestamp was `now()` at the moment the CLI ran, so an agent that does two
hours of work and then writes it up produced a record claiming it took four seconds — and
an activity feed where everything happened in the same minute. That is the normal way an
agent works, so the tool was wrong, not the agent.

The rest are one-shot failures the same critic hit: a `--json` that only parsed after the
subcommand, a `--message` whose file form is called `--body-file`, no way to close work
that was superseded (so the dashboard shows agents "working" on abandoned branches
forever), no way to fix project metadata without hand-editing `project.json` (which skips
the event log), and an `export AGENTMON_VAULT` that silently evaporates in harnesses that
give every command its own shell — pointing writes at whatever `./vault` is nearest, which
in this repository is the live vault.

Rejected alternative: letting `work start` take `--finished-at` and write a complete,
already-done record in one call. It would need `--outcome` at start, which is exactly the
thing the body contract forbids (`## Outcome` is written by `work done`), and it would put
a second state machine in the create path. Two commands stay honest and stay
copy-pasteable; `work start --finished-at` is accepted by the parser only so it can fail
with the two commands that do work.

## How

`agentmon-core/src/time.rs` is the one place that understands agent-supplied time: parse
(RFC3339, seconds-optional, space-separated, bare date, or an offset — all normalized to
`%Y-%m-%dT%H:%M:%SZ`, because every "last activity" comparison in the app is a string
compare), refuse the future (with 60s of clock skew tolerated so
`--at "$(date -u ...)"` never trips), and refuse a time earlier than the state it follows.
The ordering checks run inside the project lock, against the record as it is on disk, and
before anything is written — a rejected timestamp leaves no half-record and no orphan
event.

`Vault::append_event_at` is the new primitive under `append_event`; every write path
passes its own resolved timestamp, which is what makes a backdated record and its events
agree. The request structs (`StartWork`, `FinishWork`, `NewBug`, `NewProject`) gained
optional timestamp fields and `Default`, and the mutating methods gained an `at:
Option<&str>` parameter, so no call site can forget that time is an input.

`--json` moved to a `global = true` field on the root `Cli`, which deleted fifteen
per-subcommand `json: bool` fields and the `wants_json` dispatcher along with them.

`work abandon` reuses the `## Updates` machinery rather than inventing a section, so the
reason is a normal timestamped note and the app renders it without changes. `finished` is
stamped on abandon (the work did stop), which is what stops the work-detail page saying
"running for 6h".

## Outcome

Shipped every P1 grader finding.

**Backdating.** `crates/agentmon-core/src/time.rs` parses, normalizes and orders
agent-supplied timestamps; `Vault::append_event_at` stamps the event with the same value
that goes into the frontmatter. Flags: `--started-at` (`work start`, and corrective on
`work done`), `--finished-at` (`work done`), `--at` (`work update`, `work abandon`,
`bug claim`, `bug comment`, `bug resolve`, `project create`, `project update`),
`--created-at` (`bug create`). A future time, an unparseable one, or one earlier than the
state it follows is refused with exit 2 *before* anything is written.

**New commands.** `agentmon work abandon` (status abandoned, `finished` stamped, reason
under `## Updates`, `work_abandoned` event) and `agentmon project update` (name /
description / tags, `project_updated` event).

**Ergonomics.** `--json` is global like `--vault` — before or after the subcommand, same
command; that also deleted 15 per-subcommand `json` fields and the `wants_json` dispatcher
from the CLI. `--message-file` is a visible alias of `--body-file` on `work update` and
`bug comment`.

**Manual** (docs/AGENT_MANUAL.md): "Recording work you already finished" in Recipe 1, "If
the work stops instead of finishing", a Backdating section (flag table, the five accepted
spellings, the two rejection rules with the real error text), `work abandon` and
`project update` command entries, the timestamp flags in every entry they belong to, the
prose-flag table showing `--message-file`, five new troubleshooting entries, and an
explicit warning that a harness giving each command its own shell loses
`export AGENTMON_VAULT` — with the reminder that the `./vault` fallback here is the live
vault.

**Screenshots**: scripts/screenshot.mjs takes `SHOT_PORT` / `SHOT_ONLY` / `SHOT_OUT`
(and `--port` / `--only` / `--out` / `--help`), so concurrent critics do not fight over
port 5173 or over progress/shots. It also switches the bug board to the "All" tab when
every bug is resolved — that path was failing `npm run screenshot` before this change,
because the board opens on "Open" and the live vault currently has none.

**SPEC deviation (recorded per CLAUDE.md):** SPEC.md's `events.jsonl` type list gained
`project_updated`, and the CLI surface block gained the new commands and timestamp flags.
Justification: `project update` has to be visible in the activity feed like every other
mutation, and metadata backfill is exactly the after-the-fact case this work is about.
`agentmon-core/doctor` and src/lib/types.ts know the new type, so it is not "unknown" to
either reader.
