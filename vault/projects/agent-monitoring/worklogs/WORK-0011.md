## What

Rebuild the per-project dashboard so somebody who was not watching can open it and know
the current state of the project in seconds: a NOW strip (who is working right now and for
how long, open bugs by severity, what moved in the last 24 hours), a grouped-by-day
activity timeline, and three real charts (work completed over time, bugs opened vs
resolved, per-agent activity split). Every item on the screen links to the record behind
it. Also fix BUG-0006 — the Agents table amputated by its own card — and take the
dashboard exclusion out of `npm run check:clipping` so the gate covers it from now on.

## Why

The dashboard is the screen this app is judged against play.grafana.org on, and it was the
weakest screen in the product: five flat counters, a 14-row event dump with no day
structure, an agents table that ran off the edge of its card, and not one chart. The
numbers it did show were the ones easiest to compute, not the ones a reader needs — "72
recorded events" answers nothing, while "who is holding what right now, and how long has
it been going" is the question somebody opening this app actually has.

The clipping defect is the same class BUG-0004 was on the bug board: a fixed box with
`overflow: hidden` around content that does not fit, cutting mid-glyph with no ellipsis.
It was filed rather than fixed because the dashboard was about to be rebuilt; rebuilding it
is the moment to fix it, and to put the dashboard back inside the gate so it cannot happen
again.

## How

Charts are hand-written SVG — no charting dependency — following the data-viz rules:
sequential single-hue where the job is magnitude, categorical slots (in fixed order,
validated for colour-blind separation) only where the job is identity, 2px gaps between
touching marks instead of borders, hairline solid gridlines, values on the axis rather than
on every mark, and a hover/focus tooltip on every mark with a table-view twin so no value
is only reachable by hovering. Colours come from tokens.css and keep the meaning they have
everywhere else in the app: blue = in progress, green = done, purple = resolved, and the
severity ramp on severity.

Both projects have to look right, and their histories are different shapes: relay is three
weeks of ten agents, agent-monitoring is one working day of six. So the time axis picks its
own bucket — hours when the project's span is short, days when it is long — instead of
hard-coding a daily grid that would draw agent-monitoring as a single bar.

The clipping fix follows the bug board's: the agents table becomes a list of flex rows with
`min-width: 0` down to the name, so the name (which has an ellipsis and a tooltip) is what
gives way, sized from the project's own agent names via `src/lib/columns.ts`.

The screen is now three bands. **Now** — a hero count of agents holding open work, each
with a duration that counts up and the age of its last update; open bugs with the board's

started against finished and bugs filed against fixed, with the shaded gap between the
lines carrying the number a reader actually wants (what is in flight, what is still open).
**Who and what** — one row per agent with a work/bugs split bar drawn against the busiest
agent's total and the same counts printed as text beside it, then the event log cut into
days with today open and older days collapsed to one scannable line each.

Charts are hand-written SVG, no charting dependency. The four series steps are the app's
own hues (blue = work, green = done, orange = bug, purple = fix) re-stepped for the chart
surface and validated as a palette rather than picked by eye: every step inside the dark
lightness band, chroma above the floor, contrast at least 5.6:1, and every pair a chart
actually draws together clear of the colour-blindness gates. The validator found that the
app's `--blue` and `--purple` are 0.5 ΔE apart under deuteranopia, so no chart here carries
both — which is why the burn-ups are split work-vs-done and bug-vs-fix instead of one
four-series chart.

The time axis picks its own bucket from the project's span (hours for this project's one
working day, days for relay's three weeks) rather than hard-coding a daily grid that would
draw a day-old project as a single bar.

## Outcome

**Shipped: the dashboard, rebuilt.** `src/pages/DashboardPage.tsx` is a new screen with two
new modules behind it — `src/lib/dashboard.ts` (every number on it, as pure functions) and
`src/components/charts.tsx` (the SVG). It reads as three bands:

*Now*, which ignores the time range below it because "now" is not a range: a hero count of
agents holding open work, each log with a duration that counts up and the age of its last
update; open bugs with the bug board's own severity chips, every one a link into the
filtered board, and the age of the oldest still open; and the last twenty-four hours as a
count, an hourly sparkline with the current hour marked, and a breakdown.

*Trend*: two burn-ups. Work started against finished, bugs filed against fixed, with the
shaded gap between the lines carrying what the reader came for — what is in flight, what is
still open. Cumulative rather than per-day columns because these projects are small: eight
bugs over three weeks drawn as columns is mostly empty air, while two lines read the same at
any density. The time axis picks its own bucket from the project's span (hours for this
project's one working day, days for relay's three weeks) instead of a fixed daily grid.

*Who and what*: one row per agent with a work/bugs split bar drawn against the busiest
agent's total and the same counts printed as text beside it, then the event log cut into
days — today open, older days collapsed to one line carrying the day's shape, its count and
its cast. Every row on the screen goes somewhere: a work log, a bug, a filtered board, the
record behind a feed entry.

**Colour was computed, not chosen.** The four chart steps in `tokens.css` are the app's own
hues (blue = work, green = done, orange = bug, purple = fix) re-stepped for the chart
surface and run through the data-viz validator against `#16171a`: every step inside the dark
lightness band, chroma over the floor, contrast ≥ 5.6:1, worst pair-in-a-chart ΔE 19.9
normal / 18.8 deutan for work↔done and 26.8 / 27.2 for bug↔fix. The validator also found
that `--blue` and `--purple` are **ΔE 0.5 apart under deuteranopia** and 11.6 under normal
vision, so no chart here draws both — which is why the trend is two paired burn-ups rather
than one four-series chart.

**Also fixed, from the P3 critics' list.**

- **Open-vocabulary URL filters** (`useUrlFilters` + both boards). `?assignee=nova` in a
  project that has never heard of nova now falls back to unset, the way `?tab=banana`
  always did; the vocabulary is the one the menus already compute. `check:urlstate` asserts
  it for every dimension — severity, label, assignee, reporter, status, agent, tag, and the
  dashboard's own range — *and* asserts the other half, that a value the project does
  contain still filters, so the test cannot pass on a board that ignores its URL.
- **Bug side panel**: Participants (reporter plus every comment author) and Last word
  (author and age of the newest comment, taken by timestamp so a backdated comment cannot
  fool it).
- **Severity at 960px** keeps its initial when the row is too narrow for the word, so
  severity is never four hues and nothing to read.
- **The orphaned record id**: the id is bound to the title's last word with a non-breaking
  space, so it can never end up alone on a line.
- **A record that is not there** now says so — "This project has no BUG-9999" over the
  vault's own message, with a way back — instead of "Could not read the vault".
